# STATUS 최종 10회 사람 검수 체크리스트

이 문서와 `fixtures/semantic_safety/expectations.json`은 **사람의 사후 검수 전용**이다.
Worker·추출·주체 해소·비교 모델 입력에 첨부하지 않는다. 원문을 고치거나 기대값에 맞춰 후보를 확정하지 않는다.
판정 단위는 같은 버전으로 빈 작품부터 1~5화를 순차 분석·확정한 trial 하나다. 실행 성공과 의미적 통과를 구분한다.

## 검수 순서

각 trial-01~10을 빠짐없이 열고 항목별 `PASS / FAIL / 검증 불가`와 짧은 artifact 위치를 기록한다.
key 철자 대신 **동일 인물 ID·부위·상태 의미·현재 적용 여부·근거**로 판정한다.

- [ ] **실행 일관성:** manifest의 원문 hash, Java/AI source hash, harness hash, 모델 설정이 고정됐고 매 회차 `job.json`·`worker.json`이 완료됐다. 누락·오류·재시도도 기록하며 실패 trial을 다른 성공 trial로 교체하지 않는다.
- [ ] **확정 확인:** `candidates-before-confirm.json`과 `confirmation.json`의 요청·응답을 대조한다. 대상 부상·회복이 실제 확정됐는지 확인한다. 대상 후보의 unresolved·검토 대기를 성공으로 세지 않는다. 무관한 미상 후보는 별도 기록하되 임의 연결하지 않는다.
- [ ] **1~3화 조기 오추출 없음:** 각 `after.json`에서 비요른과 다른 인물에게 아직 발생하지 않은 발 부상·마비독이 생기지 않았는지 확인한다. 이전 인간 육체의 병약함·회고를 현재 육체 상태로 옮기지 않았는지도 본다.
- [ ] **4화 부상 확립:** 비요른의 올바른 ID에 오른발/발목의 심한 물리적 손상이 활성으로 남아야 한다. 마비·감각 저하만 있고 물리적 부상이 빠졌으면 실패다. 독과 부상을 합친 값은 통합 표현으로 기록하고 실제 부상 의미·근거를 확인한다. 왼발/양발 오추출과 동일 부상의 중복도 기록한다.
- [ ] **4→5화 연결:** 5화 Worker claim의 `knownCharacters[].activeStatuses`가 4화 확정 상태와 일치하는지 확인한다. 비요른 이외 인물에게 붙었던 부상을 그대로 둔 채 비요른의 새 부상만 제거한 실행은 실패다.
- [ ] **5화 최종 종료:** `after.json`의 `snapshot.statuses`와 `facts`에서 4화부터 이어진 심한 오른발 부상이 더는 현재값에 기여하지 않아야 한다. 5화 초반의 악화·출혈·이동 제약 뒤 회복 결과가 적용됐는지 확인한다. 포션 시도만으로 종료했다고 판정하지 않고 재생·후속 달리기 근거까지 대조한다.
- [ ] **P/Q 제거 정확성:** Worker 비교 context·complete를 짝지어 `P*`를 기존 snapshot, `Q*`를 같은 묶음의 앞선 decision에 연결한다. 제거 목록·현재 ref·캐릭터 ID·FactType·factKey와 `dependencyCandidateRefs`를 추적한다. 기존 부상이 UPDATE로 Q가 됐다면 해당 Q의 P 계보까지 확인한다. 단지 REMOVE가 있거나 Q 하나가 사라졌다는 이유로 통과시키지 않는다.
- [ ] **Fact와 근거 보존:** 4화 부상 Fact 및 5화 회복/종료 Fact의 `sourceCandidateId`·`sourceEpisodeId`·`evidenceQuotes`를 저장 후보와 대조한다. quote/offset은 해당 `sourceChunkId`의 실제 본문에 맞아야 한다. 부상 이력은 남고 current 기여는 끝나야 하며, 종료된 Fact가 snapshot의 `sourceFacts`에 다시 붙으면 실패다.
- [ ] **시간 순서·회고 재유입 없음:** 치료 시작과 최종 결과를 함께 인용한 후보가 중간 악화보다 먼저 적용되지 않았는지 비교 순서를 확인한다. 5화 후반에 회고된 치료 전 부상·의식 저하·언어 장애를 PRESENT로 다시 추가하지 않는다.
- [ ] **무관한 상태 보존:** 오름의 2화 사망이 추출·확정됐다면 5화 이후에도 같은 인물의 상태/근거가 유지돼야 한다. 처음부터 미추출이면 `추출 누락 / 보존 검증 불가`로 적고 보존 PASS로 세지 않는다. 비요른의 회복으로 다른 인물·독립 상태·non-STATUS가 제거되지 않았는지 확인한다.
- [ ] **회복 상태 누적 없음:** 부상이 사라져도 `건강함·회복됨·계속 재생 중`을 근거 없이 영구 현재 STATUS로 남기면 별도 실패로 기록한다. 출혈·생명력 위험 등 치료 전 상태가 회차 말에 남았다면 각각 원문 지지 여부와 시점 오류를 판정한다. 모든 상태를 지운 실행도 통과시키지 않는다.

**독 종료는 별도 판단:** 원문은 마비독 해독 완료를 직접 선언하지 않는다. 해독 문구나 마비독 REMOVE를 필수 정답으로 강제하지 않는다.
독의 유지·제거가 어떤 근거와 불확실성에 따른 것인지 기록하고, 확실한 오른발 부상 종료와 같은 점수로 합치지 않는다.

## 실패 단계 기록

`worker/*general-draft-candidates.json → *status-reviewed-candidates.json → *status-observation-review-before.json → *status-observation-review-after.json → *extracted-candidates.json
→ *candidates-before-dedup.json → *saved-candidates.json → 비교 context/complete → confirmation.json → after.json`
순서로 **처음 달라진 단계**를 찾는다. 산출물이 없는 단계는 없다고 적는다.
추출 누락, 잘못된 주체, 통합 표현, 비교 판단, 순서·의존성, 확정 실패를 구분하며 기록된 출력만으로 모델 내부 이유를 단정하지 않는다.

## 별도 semantic_safety 검수

원문 10회와 분리된 작품·phase `safety` 산출물을 같은 절차로 검수한다.
검수자가 원문 5개와 `fixtures/semantic_safety/expectations.json`을 함께 열어 의미를 대조하며, 모델에는 txt 원문만 정상 경로로 전달한다.

| 회차 | 카엘 오른발 | 반드시 유지할 상태 |
|---|---|---|
| 1 | 심한 부상 활성 | 카엘 왼팔 부상·저주, 미라 오른발 부상 |
| 2 | 약만 시도했고 변화 없음: 종료 금지 | 동일 |
| 3 | 통증을 참고 도움받아 이동: 종료 금지 | 동일 |
| 4 | 완치·독립 기능 회복: 오른발 부상만 종료 | 동일 |
| 5 | 과거 부상 회고: 현재 부상 재유입 금지 | 동일 |

합성 기대값의 key 이름을 강제하지 않는다. 처음부터 보존 대상이 추출되지 않았다면 그 항목은 안전성 PASS가 아니다.
합성 결과는 원문 10회 성공률에 섞지 않고 별도로 보고한다.

## 최종 보고

- trial별로 `1~3화 / 4화 주체·부상 / 5화 종료 / P·Q 계보 / Fact·근거 / 회고·누적 / 오름 / 종합` 판정을 남긴다.
- 10회 전체의 실행 완료 수, 핵심 부상 종료 성공 수, 모든 검수 항목 충족 수와 검증 불가 수를 각각 보고한다. 오름 보존은 최초 확립된 건수도 함께 적는다.
- 핵심 부상 종료만 성공한 실행을 전체 의미 품질 PASS로 표시하지 않는다. 합성 safety 결과·독 해석·세계관/임베딩 제외 등 평가 범위를 함께 밝힌다. 10/10은 해당 표본 결과이며 무오류 보장이 아니다.


새 관찰 검수 실행에서는 D* 분류에 의해 제외된 초벌이 실제 단발성 처치 과정인지, 새 종료의 T* 인물·key가 원래 대상과 같고 E*가 해당 현재 청크의 후속 기능 결과를 가리키는지 대조한다. 초벌의 실제 부상 발생은 그대로 보존되어야 하며, 새 종료에 맞춰 초벌 인용·값이 바뀌면 실패다. 실제 지속 효과를 제거하거나, 과거 회상을 현재 종료로 만들어도 실패다.

관찰 검수 v4에서는 각 before/after 사이 provider-response 3표와 표 내부 유효성 재시도를 구분한다. 표가 모두 유효했는지, 입력·model·cap이 표마다 같은 초기값으로 시작했는지, 2표 이상의 실제 제외/신규 종료 제안 없이 mutation이 만들어지지 않았는지 검수한다. 대표 summary와 전체 Erefs는 해당 실제 동의 응답 하나와 같아야 한다. 합의의 의미 판단도 원문과 독립 대조한다.

v6의 분류 coverage는 수정 가능한 D 전체를 기준으로 검사한다. 읽기 전용 `preserved_end_observations`의 기존 active=false D는 분류 응답에 없어야 하고 after에 원형 그대로 남아야 한다. 원래 D 번호, T 연결, 새 종료 2표 동의와 원문 순서 검증도 확인한다. 기억 상태는 기존 정보의 실제 망각·회상 근거를 대조하고, 뒤에 새 신체의 이름을 처음 알게 되는 근거로 앞선 기억 장애를 끝내거나 발생 위치를 늦췄으면 실패다.

추출 v8의 raw states/observations에서 kind·origin·E 순서를 대조한다. 코드가 active를 파생했는지, 현재 발생 선언에 START와 이후 END가 분리됐는지 확인한다. origin을 이전/불명으로 잘못 선언해 START 누락 검사를 피한 결과도 원문상 실패다. 검수 v7에서 PAST/HYPOTHETICAL 원형은 보존되고 현재 target/onset에는 포함되지 않아야 한다. 내부 kind는 저장 JSON에 노출하지 않으며, 새 정보 학습을 독립 STATUS로 잘못 분류하지 않았는지도 별도로 판정한다.

검수 v8에서는 raw producer state index와 감사 group 배열이 후보 정렬 뒤에도 대응하는지 확인한다. 같은 producer state의 START/CONTINUE와 기존 END가 한 T에 연결되고 새 종료 중복을 만들지 않아야 한다. 다른 producer state 또는 legacy 입력을 이름만으로 합치지 않았는지 확인한다. 시작 순간이 불명확한 경우에도 현재 제약 CONTINUE와 실제 END가 각각 보존될 수 있으며, 소급 START를 정답으로 강제하지 않는다. 주인공 외 등장인물의 사망 상태 누락도 독립 대조한다.

`ONE_OFF_TREATMENT_PROCESS` 제외에는 실제 치료/처치 과정이라는 근거가 있어야 한다. 환경에서 비롯된 실제 기능 제약·일시적 증상을 독립 지속성이 없다는 이유로 지우면 실패다. 초안 보존 여부와 후속 비교의 현재 snapshot 적합성 판단을 구분한다.
