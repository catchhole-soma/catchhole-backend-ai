## A/B 결과

데이터 소유자의 명시적 승인 후 두 방식을 각각 한 번 실행했다. 총 Provider
요청 수는 110회이며, 비교 후보는 1~4화의 52개로 제한했다. 원고나 S3 객체는
읽지 않았고, 각 시점으로 복원한 기존 canonical 설정만 비교 문맥으로 사용했다. 원본 집계 JSON은
[`episodes-1-4-gpt-5.6-luna-2026-08-31.json`](../evals/world_setting_comparison/results/episodes-1-4-gpt-5.6-luna-2026-08-31.json)에
보관한다. 파일 SHA-256은
`86006283534ea965a380ec21475ea31a83d8454f11e7f27d0fb2ae35064dc8df`다.

| 지표 | 기존 단건 방식 | canonical 묶음 방식 | 차이 |
| --- | ---: | ---: | ---: |
| Provider 호출 수 | 68 | 42 | -26 (-38.2%) |
| Provider 지연 시간(ms) | 245,349 | 296,418 | +51,069 (+20.8%) |
| 입력 토큰 | 82,467 | 37,123 | -45,344 (-55.0%) |
| 캐시 입력 토큰 | 67,422 | 24,720 | -42,702 (-63.3%) |
| 비캐시 입력 토큰 | 15,045 | 12,403 | -2,642 (-17.6%) |
| 출력 토큰 | 8,373 | 10,199 | +1,826 (+21.8%) |
| 입력+출력 토큰 | 90,840 | 47,322 | -43,518 (-47.9%) |
| Batch 수 | 52 | 25 | -27 (-51.9%) |
| Decision 수 | 52 | 52 | 0 |

묶음 방식은 25개 요청 묶음에서 source 후보 52개를 누락·중복 없이 52개
decision으로 반환했다. 이번 표본에서는 여러 source를 하나의 의미 decision으로
합치지 않았고, 양쪽 모두 `SINGLE` 52건이었다. 즉 묶음 호출과 다중 decision
경로는 실제로 사용됐지만 semantic merge가 필요한 사례는 관측되지 않았다.

| operation | 기존 단건 방식 | canonical 묶음 방식 |
| --- | ---: | ---: |
| `ADD` | 52 | 50 |
| `UPDATE` | 0 | 2 |
| `MERGE` | 0 | 0 |
| `EXCLUDE` | 0 | 0 |
| `REVIEW_REQUIRED` | 0 | 0 |

묶음 방식은 2건을 새 경로 추가가 아니라 기존 경로 갱신으로 판단했다. 따라서
proposal hash와 최종 상태 hash는 서로 다르다. 양 arm의 최종 경로를 비교하면
묶음 방식에는 단건 방식의 경로 2개가 없고, 공통 경로 2개의 값이 달랐다. 원문과
사람 검수 정답을 결과 파일에 저장하지 않았으므로 어느 쪽이 더 정확한지는 이
실험만으로 판정하지 않는다. 실제 반영은 기존 검토·확정 절차를 거친다.

## 결론

- canonical 묶음 방식은 Provider 호출을 38.2%, 입력 토큰을 55.0%, 전체
  입력+출력 토큰을 47.9% 줄였다.
- 출력 토큰은 21.8%, Provider 지연 시간 합계는 20.8% 늘었다. 따라서 이번
  실행은 비용·호출 수 개선은 보여주지만 속도 개선을 보여주지는 않는다.
- 52개 source가 25개 batch에서 52개 decision으로 정확히 보존돼 다중 decision
  계약이 실제 데이터에서도 동작했다.
- 최종 상태가 2건에서 달라 결과 동등성은 입증되지 않았다. 새 방식의 2개
  `UPDATE` 판단은 정상 검토 UI에서 사람이 확인해야 한다.

최종 보고서에는 원문, 작품·회차·후보·대상 UUID, 주체명, 설정 경로·값,
근거 문장을 포함하지 않는다. 제안 결과와 최종 상태는 salted hash와 집계값으로만
비교한다.

## 해석 시 주의사항

1. 실행 순서는 기존 단건 방식 뒤 canonical 묶음 방식이다. 뒤 방식이 Provider
   prompt cache의 영향을 받을 수 있으므로 캐시 입력 토큰을 분리해 보고하고,
   지연 시간 차이를 batching만의 인과효과로 단정하지 않는다.
2. 주체 해소도 각 방식에서 독립 실행한다. 품질 차이는 주체 해소 변동까지 포함한
   end-to-end 관측 결과다.
3. `contextReconstructionExact=false`이므로 결과는 동일한 보수적 스냅샷 위의
   상대 비교이며, 당시 운영 결과의 정확한 재현을 뜻하지 않는다.

## 재실행 명령

```bash
python -m evals.world_setting_comparison.replay_cli \
  --model gpt-5.6-luna \
  --confirm-external-provider-data-transfer \
  --output /private/tmp/world-setting-comparison-ab.json
```

비공개 데이터를 외부 Provider로 보내므로 재실행할 때도 데이터 소유자의 명시적
승인을 먼저 받는다. 작품 식별자는 출력과 문서에 남기지 않으며, 결과는 privacy
validator를 통과해야 보관한다.
