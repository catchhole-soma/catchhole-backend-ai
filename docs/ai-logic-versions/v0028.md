# v0028 — Spring 분석 API 읽기 대기 분리

2026-10-29 · [상세 실행 근거](details/v0028.md) · [Java #294](https://github.com/catchhole-soma/catchhole-backend-java/issues/294)

서버가 분석 상태를 재구성하는 동안 30초를 넘긴 정상 응답도 기다릴 수 있게 한다.
분석 API의 read 한도는 `SPRING_WORKER_READ_TIMEOUT_SECONDS`, 기본 120초다.
연결·쓰기·pool과 heartbeat·token 원장의 기존 30초 한도는 유지한다.

| 검증 | 결과 |
| --- | --- |
| HTTP·설정·heartbeat·tracing 집중 회귀 | 116 passed |
| 전체 pytest | 4,628 passed / 140 skipped / 기존 경고 1, 실패 0 |
| 변경 Python ruff / diff 공백 검사 | 통과 |
| 실제 로컬 HTTP | 기존 한도 초과 응답 수신·동시 heartbeat·heartbeat 실패 시 취소 확인 |
| Compose 설정 전달 | 세 Worker에 기본 120초·별도 설정 180.5초 렌더 확인 |
| 실제 모델 품질·운영 실패율 | 미측정 |

120초는 한 번의 읽기 대기 제한이며 요청 전체나 Job 완료의 절대 deadline은 아니다.
heartbeat 실패와 lease 취소는 더 먼저 작업을 종료할 수 있다.
일반 분석 POST 자동 재전송을 추가하지 않는다.

모델·prompt·분석 판단은 유지했고 실제 provider·judge를 호출하지 않았다.
전송 경계 변경이므로 Gold 평가는 수행하지 않았다. 자동 회귀를 의미 품질 점수로 환산하지 않는다.
운영 배포와 실제 사고 원고 재분석은 수행하지 않았다.
#294 담당자가 Backend 최적화와 함께 API 지연·SQL 비용·heartbeat/timeout을 확인해야 한다.
