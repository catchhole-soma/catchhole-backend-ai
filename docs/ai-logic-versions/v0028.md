# v0028 — 챗봇 원문 근거 선택·조건 조회 복구

2026-10-29 · [상세 실행 근거](details/v0028.md) · [챗봇 #319](https://github.com/catchhole-soma/catchhole-backend-java/issues/319)

정상 원문이 있어도 서로 다른 요구의 근거와 앞뒤 장면이 답변 입력에서 빠지던 경로를 보완했다.
키워드별 대표 후보와 인접 장면을 배분하고, 추가 검색은 아직 답하지 못한 요구에 집중한다.
명시된 한 회차의 미확인 요구는 권한 범위 안에서 좁혀 다시 찾는다.
원문 전용 프롬프트·마지막 인용 복구·전체 인물 조건 조회의 필드별 재시도도 보완했다.
현재 등록값은 기존 Spring 조회로 확인하며 추출 결과를 챗봇에서 고치지 않는다.

실제 Luna/medium·같은 원문/Gold·분리한 로컬 DB에서 비교했다.
실행 성공은 정답을 뜻하지 않는다. 내부 의미 검토이며 사용자 Gold 승인·독립 judge는 아직 없다.
단일 시행이며 일부 개발 실행이 겹쳐 지연·일반 정확도 개선을 확정하지 않는다.
기본/현재값 회귀와 복합 원문 질문, 합성 경계 테스트의 분모를 구분했다.
중간 실패·부분 답변·후퇴 사례도 상세와 비공개 보고서에 보존했다.

협상 전후 권리, 정확 합계, 최초 사건과 후속 장면에는 누락/오답이 남는다.
추출 문제는 #320으로 분리하고, 챗봇 #319/#247은 열어 둔다.
이번 PR은 Draft이며 남은 실패를 재현·보완하고 회귀를 확인한 뒤 ready를 판단한다.
모델·검색/토큰/시간 상한, 원문 청킹·임베딩·DB schema는 변경하지 않았다.
운영 배포·자동 데이터 수정은 수행하지 않았다.
