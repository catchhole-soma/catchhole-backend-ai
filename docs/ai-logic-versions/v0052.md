# v0052 — JUDGE 판정 절차와 출력 규칙 정리

2026-11-09 · 적용: 운영 Worker 배포 워크플로 성공 · [AI #144](https://github.com/catchhole-soma/catchhole-backend-ai/issues/144) · [PR #145](https://github.com/catchhole-soma/catchhole-backend-ai/pull/145)

## 무엇을 바꿨나

- 확정과 의심의 경계를 판정 절차 한 단계로 정했다. 같은 시점·조건임이 확인되면 CONFLICT, 변화·예외를 확인해야 했는데 설명을 못 찾으면 SUSPECTED_CONFLICT다. 저장된 현재값과 지금 서술, 이미 확정된 과거 사실, 바뀌지 않는 속성은 같은 시점으로 본다. 의심 설명에는 바뀐 기록을 못 찾았다는 문장을 붙인다.
- Worker가 질문을 실패시키는 출력 규칙을 한 블록에 모았다. `disagreements`는 저장값과 원문이 같은 시점·조건에서 양립할 수 없어 기준을 못 정할 때로 좁혔다.
- 판정 입력과 맞지 않던 공통 머리말을 판정 전용으로 바꾸고 Worker에게 하는 말과 반복 규칙을 줄였다(8,507자 → 8,480자). schema v4, Worker 흐름, wire, 예산, PLANNER·TYPO는 그대로다.

## 평가

상태: 부분 완료. 합성 회귀, 비공개 표본 재생, 운영 Worker 배포는 끝났고 웹 전체 재검사는 미측정이다.
조건: 판정 `gpt-6-luna`/high, 질문 분리 `gpt-6.1-terra`/medium, 외부 채점 없음(합성 기대 분류 직접 비교). 추출 F1·최종 상태 F1은 해당 없음.
소요: 회귀 1회 78~82초, 표본 재생 48초

| 검증 | 결과 |
| --- | --- |
| Luna high 합성 회귀 3회 | 매회 오류 7/7·정상 12/12·질문 분리 1/1 |
| 오류 7건의 확정/의심 | 1회 7/0, 2회 6/1, 3회 7/0 |
| 웹 저장 근거 비공개 표본 재생 | 검출 1/1 유지, 의심 그대로(확정으로 바뀌지 않음) |
| 응답의 출력 규칙 점검 57건 | 위반 0 |
| 전체 자동 테스트 | 5,720 통과·186 skip·기존 경고 1 |

결과: 현재 시제 사례 두 개는 3회 모두 확정이어서 기대값을 CONFLICT로 좁혔다. 과거 회상 사례 `role_without_explicit_negation`은 수정안의 기대(의심)와 달리 확정·의심·확정으로 갈려 기대값을 둘 다 허용으로 남겼다. 과거 시점 회상의 확정/의심 경계는 안정됐다고 보지 않는다.
합성 단문은 v0051에서도 통과했으므로 실서비스 개선으로 일반화하지 않는다. 표본 재생은 1건이고 DB 행은 이전 export의 재구성본이다.
미측정: 웹 전체 검수 정확도, OPEN·FOLLOW_UP과 Worker 변화 검색까지 포함한 실제 흐름, `disagreements` 범위를 좁힌 효과(응답 0건).
