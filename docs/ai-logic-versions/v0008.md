## 무엇을 바꿨나

1. 분석용 6,000자 청크를 유지하고 검색용 최대 800토큰/약 100토큰 겹침 청크를 별도로 저장한다.
2. 현재 원문·파기 상태를 재확인하며 누락/실패 벡터만 범위·예산이 제한된 실행으로 생성한다.
3. 기존 operational 원장과 보고 outbox를 사용하고 사용자 토큰은 차감하지 않는다.

## 남은 일

- #240에서 RDB·직접 근거·원문 검색을 질문/답변에 연결하고 검색·인용 품질을 검증한다.
- 신규 분석은 검색 청크 준비까지만 한다. 임베딩 생성은 별도 운영 실행기가 맡는다.
- 운영 원고의 전체 백필과 상시 소비 스케줄은 미실시다. 실제 예산/범위를 정해 별도 적용한다.
- 800/100은 초기 정책이다. 검색 구현 담당이 실제 질문 표본으로 평가한 뒤 조정한다.
- 설정집·과거 원문은 미지원이며 준비 완료로 표시하지 않는다.
- RDB 질문 분류·전체 이력·답변 표현의 한계는 [Java #247](https://github.com/catchhole-soma/catchhole-backend-java/issues/247)에 누적 관리하며 이번 변경에는 포함하지 않는다.
