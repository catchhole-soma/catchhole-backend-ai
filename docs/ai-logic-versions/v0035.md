# v0035 — 선정 계정 관계 전용 백필

2026-10-30~31 · [상세 근거](details/v0035.md) · [Java GH332](https://github.com/catchhole-soma/catchhole-backend-java/issues/332)

고정된 선정 계정의 과거 원문에서 관계만 채우는 전용 Worker를 추가했다.
캐릭터·세계관·임베딩을 다시 만들지 않고 기존 Terra 관계 추출/비교를 사용한다.
저장된 관측·결정으로 재개하며, 실행 순서·공개 시점·비용 부담은 Java가 결정한다.

| 검증 | 결과 |
|---|---|
| 리뷰 보완 후 전체 pytest | 4,978 passed / 141 skipped / 기존 경고1 |
| 실제 Java HTTP·PostgreSQL·Python Worker | 합성1→2→3화 및 완료 후 공개 전환 통과 |
| 공개 API 경계 | Java14개 + 실제 HTTP1개 통과 |
| 사용자 차감 분리 | 과거 백필0, 도중 합류한 새 회차 정상 차감 |
| 일반 설정/후보/청크 저장 | 관계 전용 실행에서 생성0 |
| 실모델 관계 정확도 / 캐릭터·세계관 Gold | — (미측정) |

운영 배포가 성공하면 관계 Worker1개가 고정 대상 대기열을 자동 처리한다.
원문2MB/12청크 한도를 넘으면 잘라 분석하지 않고 실패한다.
취소된 원문 읽기도 전용 실행 한도를 유지하고, 종료할 때 남은 읽기를 정리한다.
기존 관계 모델·프롬프트·일반 분석은 유지했으며 추가 실제 LLM 호출은 하지 않았다.
테스트는 실제 HTTP와 DB 계약을 검증했지만 관계 판단의 의미 정확도 평가는 아니다.

원문 교체·분석 실패는 해당 작품을 멈춰 후행 결과가 잘못 공개되지 않게 한다.
실패 작업을 무한 재시도하거나 자동으로 건너뛰지 않으며 원인 확인이 필요하다.
현재는 미머지·미배포다. Java API 배포 후 AI Worker를 배포해야 실행된다.
배포 후 캠페인 완료/차단 상태, 실제 비용과 관계·근거 표본을 확인한다.
모델 점수 비교가 필요하면 같은 평가 조건으로 별도 측정해 상세에 추가한다.
