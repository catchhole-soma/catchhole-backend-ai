# v0048 — 챗봇 모델 주도 원문 탐색·사실 추출 두 단계 답변 (#319 4차, 기본 꺼짐)

2026-11-06 · 적용: 작업 브랜치 `feat/gh-319-chat-agent-retrieval` · [Java #319](https://github.com/catchhole-soma/catchhole-backend-java/issues/319)

## 무엇을 바꿨나

- 원문 질문의 틀린 답 상당수가 "정답 근거가 모델 입력에 없거나 일부만 있음"이었다. 고정 순서(키워드 1회 → 벡터 최대 2회, 조각 12개)를 대신해, 모델이 읽은 원문을 보고 다음 검색어·통째로 읽을 회차·검색 정렬을 고르는 탐색 단계를 반복하고 읽은 조각을 한 묶음에 쌓는 경로를 추가했다(`CHAT_RETRIEVAL_AGENT`, 기본 `false`).
- 답변을 두 단계로 나눴다. 읽은 묶음을 회차 순 묶음으로 나눠 병렬로 사실과 인용문을 뽑고, 서버가 인용문을 원문과 글자 그대로 대조한 뒤 검증된 사실만으로 답을 쓴다. 빈 답이면 같은 원문을 한 번의 답변 호출로 다시 읽힌다.
- 회차 통째 읽기와 검색어별 회차 분포 조회를 더했고, 검색 인용 상한을 12개에서 60개로 넓혔다. 본문 상한 초과(413)는 다시 보내지 않는 실행 한도 실패로 처리한다.

스위치가 꺼져 있으면 계획·검색 라운드·답변 요청·검증은 v0044와 같다. 기존 프롬프트(plan v14, answer v16)와 기존 설정의 기본값은 바꾸지 않았다. 실험 사본에 있던 회차 요약 색인은 효과를 확인하지 못해 옮기지 않았다.

## 평가

상태: 측정됨 — 처음 보는 42문항 1회(커밋 `49c6103` 기준). 리뷰 반영 뒤 코드로는 다시 재지 않았다(리뷰 반영 6건: 경계 조건 4건, 등록 도구 몫 1건, 검증된 부분 답 병합 1건. 부분 답 병합은 답변을 두 번 이상 시도한 질문의 답을 바꿀 수 있다).
조건: 운영 작품 복사본(100화, 검색 조각 1,010개)을 둔 로컬 환경, gpt-6-luna medium, 개선 작업에 한 번도 쓰지 않은 42문항(원문 장면 24·등록 현재값 11·작중 시점 4·대화 흐름 3), 1회 실행. 문항마다 답을 섞어 같은 채점자가 출처를 모른 채 판정했다(PASS 1점·PARTIAL 0.5점). 켠 실행은 커밋 `49c6103`에 [켤 때 함께 바꿔야 하는 값](../chat-hybrid-retrieval-v1.md#켤-때-함께-바꿔야-하는-값)의 측정값을 썼고, Spring은 호출 24·도구 60·300초·본문 1MiB에 예약 한도를 넉넉히(6,000,000) 두었다. 꺼진 실행은 운영과 같은 코드·기본 한도다.

결과: 처음 보는 문항에서 62% → 76%로 올랐다. 문항별로 켠 쪽이 높음 16·같음 23·낮음 3이다. 같은 채점에 넣은 실험 사본(회차 요약 색인 포함 32.0점·질문당 입력 약 12.6만 토큰, 색인만 뺀 것 31.5점)과 구별되지 않아, 색인을 빼고 옮긴 뒤에도 효과가 유지되고 색인은 입력 토큰만 늘렸음을 확인했다. 개발에 쓴 85문항에서는 실험 사본(색인 포함)이 65% → 83%였는데, 그 문항을 보며 고쳤으므로 42문항 쪽을 기준으로 삼는다. 켠 실행의 최댓값은 실행당 호출 17회(임베딩 포함)·도구 16회·예약 약 34만 토큰이었고, 완료 결과의 검색 인용이 12개를 넘은 답은 42개 중 2개(최대 27개)였다.
남은 문제: 42문항이라 한 문항이 2.4%p이고 1회 실행이다. 응답 시간 중앙값이 약 2배, 입력 토큰이 약 4배다. 스위치를 켜려면 Python·Spring의 호출·도구·예약·시간·본문 한도를 함께 올려야 한다. 질문당 모델 호출과 응답 시간이 늘어난다. 인용이 원문에 있다는 검증은 문장의 의미를 보장하지 않는다. 사실이 200개를 넘으면 뒤 회차의 사실이 빠진다. 탐색 모델에 알려 주는 회차 분량 어림(8,000토큰)은 고정값이다.
다음: 운영 적용은 Java 배포 → 한도 설정 → 스위치 순서다. 켜기 전에 실제 저장소 지연에서 인용 등록·검증의 Work 잠금 시간과 응답 시간(로컬 최대 133초)을 다시 잰다. 남은 오답은 등록값 질문의 되묻기·근거 부족 마감과 세부 누락이 많다(담당: 챗봇 평가 담당자).
