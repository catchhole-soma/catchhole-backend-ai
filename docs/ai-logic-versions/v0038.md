# v0038 — 검수 COVERAGE·JUDGE 입력 압축과 1글자 이름 매칭 제외 (grid v3)

2026-10-31 · 적용: 작업 브랜치 `feat/gh-349-coverage-compact-projection` · [Java #349](https://github.com/catchhole-soma/catchhole-backend-java/issues/349) 후속

## 무엇을 바꿨나

- 첫 grid v2 운영 실행(30회차)에서 PLANNER·SUBJECT_RESOLUTION은 성공했지만 COVERAGE:TSEG1이 입력 80,000토큰을 넘어 호출 전에 `REQUIRED_CONTEXT_TOO_LARGE`로 멈췄다. 호출 수가 아니라 항목 크기가 원인이었다(관련 항목 179개 795 KB, 가장 큰 인물 362 KB 중 이력 209 KB). 이제 COVERAGE·JUDGE 모델에는 식별 정보와 현재값만 남긴 압축 행(슬롯은 factKey·factType·factValue)을 보낸다. 게시 근거 묶음·조회·checkpoint는 전체 행 그대로이고, 모델이 BASELINE으로 요청한 항목은 다음 JUDGE에 전체 행으로 준다.
- 1글자 이름·별칭은 기계 매칭에서 뺀다(구간당 16~22주체가 걸렸다). 서버 grid는 같은 규칙의 v3이며(grid v3 = v2 + 1글자 제외) Worker는 v2·v3을 받는다. 1글자 이름도 주체 카탈로그에는 남아 지칭 해소가 찾을 수 있다.
- 안전장치: COVERAGE 관련 항목이 400개를 넘으면 앞 400개만 보내고 나머지는 "입력 상한으로 모델 점검에서 제외됨" NOT_APPLICABLE로 기록한다.
