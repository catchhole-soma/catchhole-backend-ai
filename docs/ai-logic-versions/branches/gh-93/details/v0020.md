Notion은 Actions가 사용하는 같은 세 data source에서 읽기 전용으로 가져왔다. API token을 새로

### 기존 팩트 차이

- 두 대조 모두 2화의 중요도 MUST 직업 3건에서 기존의 고정 직업 경로 대신 동적 역할 경로가 나왔다.
  값과 인물은 같아도 저장 위치가 달라지는 회귀 후보다. 별칭을 추가하거나 정답을 고쳐 면책하지 않았다.
- MUST 29건의 완전 일치는 기존 21/24건, 관계 추가 19/21건이었다. 같은 비교 쌍의 MUST 누락은
  각각 3/3건과 1/1건으로 같았다. 값·경로·발견을 함께 보는 완전 일치이며 별도의 일반 정확도는 아니다.
- 관계 추가 1회에서는 1화의 종족과 3화의 신장 항목이 좋아졌다. 2회에서는 3화의 일부 프로필
  누락이 줄었지만 다른 직업 항목이 빠졌고, 4화의 ITEM/STATUS 후보 2건이 Gold 기준 추가였다.
  추가 판정을 곧바로 원문상 거짓으로 해석하지 않는다. 양쪽의 이득과 손실을 모두 보존했다.
- 기존 버전에도 누락·값 오류·주체 미해소가 남았다. 관계 추가 2회에서는 2차 주체 미해소가
  2→3건으로 늘었다. 1차 인물 대응 성공과 실제 파이프라인의 주체 해소 성공은 구분한다.
- 개별 Gold ID·원본 예측·차이 이유는 비공개 report와 comparison.private.json에 보존한다.
  전수 의미 검수나 작품 전체의 누락 없음은 입증하지 않았다.

첫 선별의 첫 회차에서 위치 검증을 통과한 관찰 16개를 별도로 수동 검토했다. 명백한 새 관계 유형의 창작은 발견하지 못했지만 이를 의미 정확도 100%로 계산하지 않았다. 짧은 대명사가 다른 참여자의 이름 일부·문법적 부분 문자열·그 참여자 자신의 발화에만 있어도 문자열 검사에 합격한 사례가 있었다. 이는 이름의 단순 누락이 아니라 선택한 근거가 가리키는 참여자 역할과 모델 endpoint의 불일치다. 원문 장면이 실제 상호작용을 담고 있다는 사실과 선택한 근거가 올바른 참여자를 지지한다는 사실은 다르다.

원문의 추측을 요약에서 확정적으로 바꾼 사례와, 요약의 일부 주장이나 인물 연결이 반환한 인용 범위 밖에만 있는 사례도 확인했다. 관계 관찰은 계속 UNCONFIRMED로 취급해야 하며, 정확한 인용 위치·이름 문자열 포함·관계 방향 및 의미 지지는 각각 별도로 검토해야 한다.

별도의 개발용 작성 진단에서는 기존 캐릭터 설정으로도 남아야 할 관계 사실이 관찰 배열로만 이동하는 보존 문제가 관찰됐다. 이 진단은 사용자 승인 소설 Gold가 아니므로 위 분모나 점수에 합치지 않았다. 관찰 수가 늘어도 기존 canonical 설정이 빠지면 제품 요구를 만족하지 않는다. 지시문 순서나 배열 적용 범위만 바꾸는 것으로 보존이 해결됐다는 증거는 아직 없으며, 새 후보의 heldout 진단은 이 문제를 별도로 확인한다. 작성 사례의 이름·본문·기대 답안은 공개하지 않는다.

토큰은 예측 파이프라인 usage이며 평가용 judge와 분리한다. 캐시 입력은 전체 입력의 부분집합이다.

개발·기존 heldout 수동 대조의 의미

개발 8개에서는 v4가 여러 명시적 관계와 부정 관계를 canonical 후보에도 복원했다. 일회성 행동을 새 지속적 프로필로 만든 명백한 사례는 발견하지 못했다. 그러나 부모 후보에 있던 명시적 관계 프로필 하나가 v4에서 원시 단계부터 빠졌고, 같은 내용의 아이템 경로가 달라진 사례도 있었다. 개발 결과만으로 범용 보존 성공을 선언하지 않는다.

이전 동결 후보의 기존 heldout 대조에서도 base가 출력한 과거 관계와 이후 단절 사실이 canonical 후보에서 빠져 관찰에만 남는 사례를 확인했다. 일부 아이템 누락은 양쪽 공통이었다. 원문이 보장하지 않는 사건 순서를 요약에 넣거나 제안의 조건을 요약에서 생략하는 문제도 있었다. 이러한 수동 감사는 기대 답안을 읽기 전에 원문과 출력만 대조한 독립 진단이며, 새 사용자 승인 Gold나 공식 정확도 분모로 추가하지 않았다. 수정에 참고한 개발·기존 heldout은 이후 미노출 성능 확인 자료로 다시 취급하지 않는다.

새 reserve 결과와 미판정

v4 프롬프트를 고정한 뒤 독립적으로 작성한 새 reserve 8개에 대해 base와 v4를 각각 한 번 실행했다. 두 arm 모두 추출 8/8을 완료했고 입력 파일이 동일했다. 후보는 base 43개, v4 47개였다. v4는 원시 관찰 18개 중 17개가 위치 검증을 통과했고, 나머지 하나는 동일 이름 endpoint의 모호성 때문에 거절됐다. 후보 수가 많다는 사실 자체가 품질 개선은 아니다.

동결 judge는 8개 중 7개를 공식 판정했고, 하나는 관계 applicability 검증 오류로 PENDING이다. 해당 원시 judge 출력은 공식 점수에 사용하지 않았다. 전체 사실 41개 중 5개, critical 사실 27개 중 3개가 pending으로 남았다. Pending을 오답이나 0점으로 바꾸지 않는다.

| arm | 판정 완료 사실 FULL / 36 | PARTIAL / MISSED / WRONG | 판정 완료 critical FULL / 24 | critical PARTIAL / MISSED / WRONG |
|---|---:|---:|---:|---:|
| base | 30/36 | 2 / 4 / 0 | 18/24 | 2 / 4 / 0 |
| v4 | 32/36 | 2 / 2 / 0 | 21/24 | 2 / 1 / 0 |

이 수치는 판정 완료 분모의 strict full이며 PARTIAL에 반점을 주지 않았다. 전체 41개를 기준으로 한 가능 범위는 base 30~35개, v4 32~37개의 FULL이고, critical 전체 27개는 각각 18~21개, 21~24개다. 이 범위는 미판정의 상·하한이며 별도 점수가 아니다. 관계 OFF인 base의 관계 품질은 NOT_APPLICABLE로 취급했다.

v4 원시 관찰 의미 판정은 18개 중 SUPPORTED 16, PARTIAL 1, PENDING 1이었다. 따라서 판정 완료 항목의 SUPPORTED는 16/17이지만, 전체 완료 정확도나 accepted-only 정확도로 부르지 않는다. 사전 작성한 관계 단위 coverage는 FULL 8/11, PARTIAL 2/11, MISSED 1/11이었다. 기대 관계 단위가 없는 음성 대조 사례도 공식 PENDING이므로 성공으로 간주하지 않는다. 원시 관찰의 의미 지지, 위치 수락, 기대 단위 coverage는 서로 다른 지표다.

독립 원문 대조에서는 명시적 우정·과거 및 종료된 관계·부정 관계를 canonical 후보에도 남기는 개선을 확인했다. 익명 구조자와 뒤에 등장한 인물, 이름이 같은 서로 다른 역할도 선택 mention과 행동에서 구분했다. 최종 주체 해소·인물 ID 연결은 이 추출 전용 진단에서 검증하지 않았다.

동시에 실제 보존 실패가 있었다. Base가 출력한 현재 보유 금액과 이전 금액이 v4에서 모두 빠졌고, 다른 인물의 명시적 직업도 빠졌다. 관계 관찰에 지급 행위가 있어도 현재 잔액이 복원된 것은 아니다. 현재 금액 누락은 judge에서도 critical 미검출로 남았다. 또한 원문에 있는 단순 인사를 관찰로 출력해 현행 제외 규칙을 어긴 사례를 수동으로 확인했다. 이 사례의 공식 judge 결과는 그대로 PENDING이며 수동 진단으로 공식 점수를 덮어쓰지 않았다. 평균 및 일부 critical 합계의 개선이 이러한 구체적인 손실을 없애지 않는다.

방향과 남은 범위

이번 라운드는 v4의 운영 통합 없이 종료한다. 기존 v2 default OFF, 격리된 실험 코드, 모든 성공·실패·미판정 결과를 유지한다. 새 reserve를 보고 추가로 프롬프트를 조정하지 않는다. 관계 관찰은 UNCONFIRMED 연구 결과이며 캐릭터 사실 보존 검증은 미통과다.

다음 구현을 검토한다면 이미 확정된 캐릭터 사실을 근거와 인물 식별 정보와 함께 읽기용 관계 뷰로 투영하는 경로가 우선이다. 이 방식은 새 사실 추론을 같은 모델 출력에 더 요구하지 않으면서 기존 사실 표현을 확장할 수 있다. 다만 현재 없는 사실을 만들어 내거나 이번 누락을 복구하는 해결책은 아니며, 아직 구현·검증된 기능으로 보고하지 않는다.

행동·문맥·암시·불확실성·시점에 의존하는 관계 추출 요구는 미해결 범위로 명시적으로 남긴다. 제한된 인접 원문 문맥은 근거 위치와 지칭 확인을 돕는 별도 후처리 진단으로 검토할 수 있지만, 잘못된 화자 연결·추측의 단정·canonical 사실 누락을 해결했다고 주장할 수 없다. 제품 범위를 좁혀 완료로 처리하거나 평균 점수로 사실 보존 실패를 덮지 않는다.


## 2026-10-26 v5 후속 검증 — 요약 제거와 새로운 실제 원고 구간

### v5 원문 근거만 출력하는 실험: 기존 소설 1–4화 두 쌍과 검토한 reserve 재진단

OFF 요청은 v4와 직렬화 바이트까지 동일했고, ON 요청 차이는 summary schema 삭제, 해당 프롬프트 두 줄, 버전 키뿐이었다. 이 정적 검증은 실제 생성 품질 보존을 입증하지 않는다.

v5 소설 관찰은 원시 13개 중 11개가 위치 검증을 통과했고, 2개는 선택 근거에서 참여자 지칭을 찾지 못해 거절됐다. 8개 원문 청크의 hash와 모든 수락 구간 offset을 확인했다. 요약이 없으므로 원문에 있는 추정 표현을 확정형 요약으로 바꾸는 경로는 제거됐다. 그러나 인용 안의 1인칭 지칭이 다른 화자의 발화에 등장해도 부분 문자열 검사로 통과하는 연결 한계는 남았다. 원문 위치 검증은 화자·대명사 연결 검증이나 관계의 확정이 아니다.

이미 검토한 reserve 8개를 동결 v5로 다시 실행한 것은 새 heldout 검증이 아니라 진단이다. 8회 추출이 모두 완료됐고 15개 원시 관찰이 모두 위치 검증을 통과했다. 독립 원문 감사에서는 이전에 빠졌던 돈의 이전·현재 수량과 직업 내용이 돌아왔고, 단순 인사 관찰도 나오지 않았다. 다만 돈은 한 후보에 통합됐으며 직업의 후보별 과거 시점 연결은 baseline과 같지 않았다. 더 중요한 부정 관계 프로필이 기존 설정 후보에서 빠지고 다른 참여자 쌍의 인용문 안에만 남는 문제가 확인됐다. 역방향 관계 기록도 없어졌지만 정방향의 동일 관계는 남아 있으므로 별개의 관계 의미 손실로 중복 계산하지 않는다. 다른 소유 설정 한 건은 v4 대비 없어졌지만 baseline도 누락했던 항목이다.

reserve 관계 평가에는 출력 계약 변경에 따른 측정 한계가 추가됐다. 동결 평가기는 일부 quote-only 관찰에는 SUPPORTED를 주었지만 다른 7개에는 summary가 없다는 이유로 PENDING을 부여했고, 관계 단위에도 MISSED/PENDING을 부여했다. 따라서 v5의 관계 단위 원점수 2/7에는 출력 계약 변경과 평가기 비일관성이 섞여 v4와 직접적인 관계 품질 비교가 불가능하다. 원점수와 PENDING을 그대로 보존하고 원문 감사를 별도로 제시한다. 이 한계가 기존 설정 후보의 보존 실패를 없애지는 않으며, 설정 후보 평가는 계속 사용할 수 있다. 재채점하거나 rubric을 느슨하게 바꾸지 않았다.

독립 원문 감사에서는 fresh OFF의 직업 사실과 소유물 사실이 두 ON arm의 raw/core에서 빠지고 관찰 인용에만 남은 경우를 확인했다. 추가로 flat core에 있던 명시적 부정 관계가 v6에서는 관찰로만 남았다. 이는 다른 경로로 같은 의미를 유지한 경우나 평가기만의 불일치와 구분된다. 같은 부정 관계를 양방향 후보 두 개로 표현했다고 독립적인 의미 사실 두 개로 세지 않는다. 한편 OFF의 해당 관계 후보에는 뒤 시점의 비발언을 확정 부정으로 강화한 문제가 있어, 그 잘못된 시점까지 보존 목표로 삼지는 않는다. 초기 원문의 직접 부정과 flat의 정상 후보가 별도의 누락 근거다.

일부 차이는 전체 사실 누락과 구분했다. 이전 수량이 구조화된 값에서 빠졌지만 canonical 근거에는 남은 경우, 후보의 시점 연결이 빠졌지만 전역 time_context에는 남은 경우, profile/item 경로 또는 관계 표현 방향이 바뀌어도 의미가 유지된 경우가 있었다. 반대로 v6가 flat/OFF에서 없던 정상 관계 profile을 출력한 사례도 있었지만, 다른 사실의 누락을 상쇄하는 보존 통과 근거로 쓰지 않았다.

수용 관찰의 전체 원문 대조에서 새 관계 창작·명백한 endpoint 역전·일방적 생각의 상호 친구 승격은 발견하지 못했다. 익명 참여자는 익명으로 남았고, 가족 호칭/단순 인사만의 사례는 두 ON 모두 관찰 0개였다. 다만 발언 부재를 서술 부재로 약화한 flat 요약, 후속 부정 문맥을 모두 포괄하지 않은 v6 관찰, 선택한 인용 앞의 문맥에 일부 요약 표현이 의존한 공유 한계는 남았다. 정확한 위치 검증과 전체 원문의 의미 지지는 동일하지 않다.

동결 judge는 8회 호출 후 COMPLETED_WITH_PENDING이다. 사례 3개의 validation 실패(RELATION_APPLICABILITY_INVALID 1건, UNSUPPORTED_ACCEPTED_COVERAGE 2건)를 원래대로 보존했고 재채점하지 않았다. 아래는 각 arm의 동결 예상 사실 30개 중 FULL/MISSED/PENDING 원수치이며 PENDING을 오답 0점으로 치환하지 않는다.

판정된 예상 사실은 arm별 18개, critical은 8개이며 전체 분모는 각각 30개와 15개다. ON 관계 단위는 총 8개 중 4개 판정, 4개 미판정이다. OFF의 관계 NOT_REQUESTED/PENDING 기록은 관계 실패 점수로 해석하지 않는다. OFF에는 과도한 시점/부정 해석의 추가 오답 후보 2개도 기록됐다. judge는 두 ON의 직업 누락을 확인했으나, 일부 source-audit 보존 결함은 동결 예상 사실 분모 밖의 보충 진단이다. 이 사실을 이유로 Gold를 늘리거나 점수를 수정하지 않았다. judge token은 입력 46,038 / 출력 15,586이며 제품 호출 비용과 구분한다. 전체 유료 실행은 추출 24회와 평가 judge 8회였다.

단일 fresh 실행과 고정되지 않은 provider alias만으로 특정 누락의 원인을 namespace 자체라고 확정할 수 없다. 기존 OFF 반복 변동도 인과 해석의 한계이며, 사전등록 보존 gate를 완화하는 허용 오차가 아니다. 이번 관측은 “v6가 보존 조건을 통과했다”는 주장을 지지하지 않으므로 새 소설 반복으로 진행하지 않고 현 상태를 기록한다. contextual/익명 관계 관찰 범위의 문제를 명시적 profile 관계만으로 축소해 완료 처리하지 않는다.

v6 관련 자동 테스트 101개와 Ruff/diff 검사를 통과했다. 별도 검토자가 동결 SHA의 schema refs, 안전한 검증 재시도, 관찰별 오류 격리와 저장된 요청 캡처를 독립 확인했다. 이 계약 검증과 실제 모델 품질 검증은 구분한다. 사전등록 계획 SHA-256은 0eef3d67356046ac6ab7625fcc47a1e4d219feb1d740515f2cf38ff0a9b339cd이고 원문 감사 기록은 9138b84b2c36c3f98238cf7d13759e9ee30c6658a9b2cb2a44d3fd9d6344714a다.


### High effort 개발 반복: 점수 이득과 남은 사실 보존 손실

동결된 original OFF와 flat v4를 같은 개발 데이터에서 high effort로 각각 두 번 실행했다. 공식 예상 사실과 관계 관찰의 결과는 high v4가 양호했으나, 별도 원문 감사에서 과거 상태와 장비 관련 canonical 정보 누락이 남았다. 현재 사전등록의 넓은 캐릭터 사실 보존 조건은 미통과이며, 이 결과만으로 소설 반복 평가에 진입하거나 운영에 채택하지 않는다. 동일 호출에서 contextual/익명 관계 관찰을 만드는 접근 자체가 불가능하다는 결론은 아니다.

구현은 OFF 8121bbbdef8f20b9f5c84a7e7b75c0039b0be484, flat v4 c731d4fcd8e40ce59a67dc2423326d140f377007로 고정했다. v6는 사용하지 않았다. 진단 runner의 변경은 REASONING 상수 medium→high 한 곳뿐이며 역치환한 파일 전체 bytes가 부모 runner와 같았다. 저장된 요청 metadata에서도 각 arm의 fresh medium 참고 실행 대비 차이는 reasoning_effort 하나였고, 같은 arm의 high 두 라운드 요청 metadata는 모두 동일했다. OFF와 v4 사이에는 기존 관계 prompt·exact-first hints·schema·cache 차이가 있으므로 두 arm의 요청이 byte-identical하다는 뜻은 아니다.

모델 gpt-5.6-sol, high effort, 최초 output cap 32000/절단 retry cap 64000/최대 시도 3회를 사용했다. 입력·schema·코드·prompt는 동결했고, 평가 judge는 기존 gpt-5.6-sol·medium을 유지했다. 라운드 안의 OFF/v4는 병렬, 각 arm의 8사례는 순차 실행했다. 1라운드 완료 후 2라운드를 실행했으며 두 라운드를 모두 보존했다. 네 추출 실행은 각각 8/8 완료, 호출·HTTP 응답 각각 8회, 기록된 추출 실패·재시도·미완료 0이다. 후속 주체 해소·비교·DB 반영은 포함하지 않았다.

두 high 라운드의 공식 사실 FULL 합계는 OFF 50/54(92.59%), v4 53/54(98.15%)다. 각각 전체 60개 중 6개가 미판정이며, critical은 OFF 24/27(88.89%), v4 27/27(100%)이고 전체 30개 중 3개 미판정이 남는다. 두 라운드의 판정 분모가 달라 각 실행 비율의 단순평균은 사실 FULL 기준 OFF 92.92% / v4 98.33%로 합산 비율과 다르다. 이 수치는 같은 개발 데이터의 반복이며 독립 사례 수가 두 배가 된 검증으로 해석하지 않는다.

OFF의 판정된 비FULL은 1라운드 PARTIAL 1개, 2라운드 MISSED 1개·WRONG 2개다. v4는 2라운드 MISSED 1개다. FULL 이득 3개는 정규 값의 세부 표현 1개와 시점 주석 2개의 판정 차이에서 나왔으며, 완전히 없던 원시 사실 3개를 복구한 것과는 구분한다. 값은 같지만 OFF가 근거보다 강하게 fact_time을 한정한 경우가 포함되므로 그 시점 표현을 무조건 보존 목표로 삼지 않았다. 동일 데이터의 비교라도 medium과 high의 판정된 사례 부분집합이 달라, 과거 medium 점수와 섞어 개선폭이나 평균을 만들지 않는다.

관계 관찰은 v4 두 라운드 각각 raw 11개, 위치 검증 수용 11개, frozen judge SUPPORTED 11개였다. 합계 22/22이며 관계 단위는 15 FULL + 1 PARTIAL / 16이다. PARTIAL은 일부 행동 coverage가 빠진 경우이며, 관찰 문장이 지지된다는 것과 전체 요구 관계 단위를 모두 포괄했다는 것을 구분한다. 가족 호칭/공동 등장/단순 인사만의 negative control은 두 라운드 모두 raw 0개였지만 1라운드 해당 사례의 공식 판정은 PENDING이다. 독립 원문 감사는 잘못된 actor 연결·상호 친구로의 임의 승격·부정 반전을 발견하지 못했고, 익명 참여자 범위도 유지됐다. 단, 일부 요약은 선택 인용 앞의 원문 문맥에 의존했고 후속 비발언 문맥을 전부 담지 않은 관찰도 있어, 위치 검증을 의미·coverage 보장으로 확대하지 않았다.

독립 감사에서 발견한 보존 손실은 공식 예상 사실 분모에 추가하지 않았다. 1라운드에는 OFF에 있는 과거 수량 상태 두 개가 v4 raw/core에서 빠졌으며 현재 수량은 맞았다. 하나는 원시 값/별도 과거 후보만 빠지고 canonical 근거에는 과거 정보가 남았고, 다른 하나는 선택된 근거에도 과거 정보가 없었다. 두 과거 상태는 v4 2라운드에 다시 나타났다. 따라서 현재 수량 오류나 두 라운드 공통 누락으로 기록하지 않았다.

2라운드에는 fresh OFF의 장비 사용 후보와 장비 연관 후보가 v4 raw/core에 없고 관찰에만 남았다. 두 항목은 1라운드에는 OFF/v4 모두 별도 후보로 내지 않았고 v4는 두 번 같은 선택을 했으므로, v4가 2라운드에 새로 악화했다거나 high가 원인이라고 단정할 수 없다. 그러나 해당 fresh pair에서 canonical 선택이 보존되지 않았다는 관측은 남는다. 소유격 장비 표현은 사용·연관 근거와 법적 소유 확정을 구분하고, 직접 지지되는 사용 후보의 누락을 가장 명확한 사례로 삼았다. 이 손실을 공식 critical 오답으로 새 분류하거나 Gold에 편입하지 않았다.

이득도 함께 보존했다. v4는 일방적 믿음과 상대의 무지를 구분한 profile을 추가로 유지했고, 기존 medium의 일부 직업·소유물·명시부정 누락은 이 high 실행에서 재현되지 않았다. 일부 과거 값과 사건 뒤 시점의 상세 표현도 v4가 더 많이 보존했다. 경로 이름·관계 표현 방향·JSON 수량 키 차이는 의미가 같으면 raw omission과 구분했다. 한편 두 OFF 반복끼리도 선택되는 사용 장비 후보가 달랐다. 이 변동은 인과 확신을 낮추지만, 사전등록 보존 조건을 사후에 느슨하게 만드는 근거는 아니다.

네 실행은 모두 정규 후보 44개였지만 후보 집합이 같지는 않았다. 총 176개 후보는 원시 응답의 주체·지칭·경로·표시값·타입·근거 및 decoded value를 정규화 과정에서 보존했다. canonical 근거 184개는 원문 substring이었고, 수용 관찰 22개의 인용 구간 23개는 모두 원문 Unicode offset과 정확히 일치했다. 발견된 선택 차이를 파서 탈락으로 설명할 근거는 없었다. 후보 수·인용 성공률은 사실 보존이나 의미 정확도 점수가 아니다.

#### 캐릭터 설정의 원문 독립 감사


세 arm의 동일 R1을 비교했다. 이 소설 runner의 `rawStage1`은 추출기가 반환한 **정규화된 후보**이며 provider 원본 응답이 아니다. 원본 provider wire는 저장되지 않았으므로 이 결과로 원시 응답의 byte parity를 주장하지 않는다. 이 투영에는 후보의 `narrative_time`도 빠져 있어, 값과 근거에 남은 시간 한정은 확인할 수 있지만 저장되지 않은 typed 시간 필드를 추측하지 않았다.

- 중요한 무기 2개는 OFF와 v7 모두 정규화된 추출·주체 연결·ADD까지 유지했지만 flat에는 해당 내용 자체가 없었다. 직업 3개는 세 arm 모두 올바른 경로와 인물로 유지했다. 이 다섯 항목의 성공은 전체 설정 보존의 통과를 의미하지 않는다.
- OFF 대비 v7의 MUST FULL 감소 2개는 **종족 값이 더 넓은 profile 경로로 출력된 경우**와 **독 효과의 통증·추정 한정이 값에서 축소된 경우**다. 두 개념 전체가 사라진 것은 아니다. 한편 다른 인물의 종족은 세 arm 모두 실제로 빠졌는데, v7에서는 다른 후보와 잘못 대응되어 MISSED가 아닌 PARTIAL로 표시되었다.
- 실제 일반 설정 누락도 있었다. 언어 이해 능력은 두 ON arm 모두 빠졌고, 한 인물의 종족 속성도 두 ON arm에서 빠졌다. v7은 OFF·flat에 있던 별도 성별 속성 3개를 내지 않았다. 가족 관계 문구에 성별 단서가 남아 있다는 사실과 별도의 canonical 속성이 없다는 사실을 구분했다. 성향 설정은 OFF에 다른 경로로 남았지만 두 ON arm에는 동등한 후보가 없었다.
- 반대로 OFF에서 빠진 한 직업은 두 ON arm에 있었다. v7의 가중 identity 차이 −11은 MUST 경로 손실 −3, SHOULD 다섯 항목 손실 −10, SHOULD 직업 회복 +2로 분해된다. 개선도 포함했지만 순손실과 다른 실제 누락을 상쇄해 보존 통과로 처리하지 않았다.
- v7에서는 자기 해석이나 주변 인식에 해당하는 표현을 확정적인 종족 속성으로 분류한 추가 후보가 나왔다. 단어 자체는 원문에 있었으나 속성과 확정성의 해석이 문제였다. 이 후보와 별도로 올바르게 추출한 종족까지 충돌로 묶여 두 결정 모두 REVIEW_REQUIRED가 되어, 올바른 기존 사실의 ADD를 막았다. Stage1 FULL만으로 downstream 보존을 보장할 수 없는 사례다.
- 한 회차에서 flat은 필요한 상태·소지품 개념을 추출했지만 주체가 해결되지 않아 비교 단계로 보내지 못했다. 해당 resolver의 세 arm 입력 fingerprint는 서로 달랐다. resolver에는 관찰 배열이 직접 전달되지 않고 후보 이름·경로·값·근거 등이 전달된다. 이를 동일 입력의 순수 출력 변동이나 관계 관찰의 직접적인 인과 효과로 단정하지 않았다.
- 부상·소지품·사망 원인 등은 내용이 남아도 값의 세부 범위가 부족한 공통 사례가 있었다. 과거 직업도 근거에는 과거 시점이 남았지만 OFF·v7의 값에는 종료 한정이 약했다. 소지품과 경험치 등 공통 누락·공통 값 불일치, source-supported 추가 사실을 v7만의 새로운 손실로 바꾸지 않았다.


공식 MUST FULL/PARTIAL/MISSED는 OFF 25/3/1, flat 21/4/4, v7 23/6/0이다. v7의 MISSED 0은 모든 필수 내용이 실제로 추출되었다는 뜻이 아니다. 세 방식 모두 빠뜨린 한 인물의 종족 내용에 v7의 다른 인물 후보가 대응되어 PARTIAL로 기록된 사례가 있다. 공식 결과는 수정하지 않고 실제 내용의 존재 여부를 별도로 기록했다. 값 정확도 분모는 OFF 41/48, flat 37/42, v7 35/46이며 가중 recall 분자는 각각 131/107/120(분모 144)다. 독립 원문 감사 SHA-256 `3b1db2c0838e11bc40875b98428a5cbb3b08923885057aebf19d831f546cb517`.

판정은 **NO-GO 유지**다. 이번 v7은 flat보다 일부 설정을 회복했지만 fresh OFF보다 가중 재현율·MUST 값 일치가 낮고, 실제 프로필 누락·분류 오류에 따른 올바른 설정 반영 차단·관계 인물 결합 오류가 남았다. 한 번의 완료 비교로 인과적 손실 크기나 같은 호출에서의 보존 불가능성을 확정하지 않는다. R2 실패를 대체하거나 새 확인 세트를 열어 결과를 보정하지 않았으며 운영은 v2 OFF를 유지한다.

### 2026-10-27 유형별 출력 v8: 오프라인 시제품만 검증

v7 결과와 실패를 보존한 뒤 별도 worktree에서 다음 구조를 준비했다. v8은 캐릭터 발견·프로필·나이/레벨/능력치·상태·아이템/스킬·나머지 설정의 여섯 고정 배열을 요구한다. 모든 배열은 기존의 동일한 후보 typed union을 사용하고 시간 문맥은 기존 `time_context`에 둔다. 관계 ON일 때만 마지막에 기존 v4 관찰 wire를 둔다. 원문 복사·인물별 필수 슬롯·문장별 필수 행·새 후보 필드는 추가하지 않는다. `typed_buckets=True`는 관계 flag와 독립적이며, 기본 Worker를 활성화하는 환경변수나 DB 저장 경로는 만들지 않았다.

분류는 `value_type=NUMBER`가 아니라 기존 canonical 설정 종류를 기준으로 안내한다. TIME·사용자 schema를 위한 `other_settings`를 유지하며, 정상 후보가 다른 배열에 들어갔다는 이유로 고치거나 버리거나 재시도하지 않는다. 분류 진단은 명시적인 schema 종류가 있을 때만 남는다. 여섯 배열의 고정 순서와 각 배열 내부 순서로 펼치므로 배열 사이의 원래 모델 출력 순서를 복원하지는 않는다. 이 순서 차이가 인물 해소·비교에 영향을 줄 수 있다.

다음 비교는 원래 OFF / 유형별 OFF / 유형별 ON을 구분해야 한다. 유형별 OFF와 ON의 canonical schema hint 순서는 모두 **원래 OFF 순서**로 같게 맞췄다. 이는 기존 flat v4 ON의 exact-first 순서와 다르며, 기존 flat OFF/ON 동작 자체는 변경하지 않았다. 유형별 OFF−원래 OFF는 구조·순서 변화 전체, 유형별 ON−유형별 OFF는 공통 구조에서 관찰 추가의 차이로 해석해야 한다. 관찰을 끝에 출력하도록 지시해도 모델 내부 계산이 독립된다는 보장은 없다.

164개 계약 테스트(새 유형별 50개·기존 114개), Ruff·diff 검사를 통과했다. 작성자와 별개로 만든 합성 후보 8개·7개 subprocess의 MockTransport 포착에서도 58개 검사를 통과했다. 원래/v4 OFF와 새 기본 OFF의 전체 HTTP bytes·정규화 결과·잘못된 core에 대한 재시도 요청이 같았고 기존 flat ON도 유지됐다. typed OFF/ON의 입력 hint 순서, 모든 후보 필드·개수·시간 문맥, 잘못된 배열의 정상 후보 보존을 확인했다. core 중복/누락/잘못된 값은 기존 안전한 실패·재시도, 관찰만의 오류는 정상 설정을 보존한 거절로 구분한다. BOOK 근거 오류의 원래 배열 위치 경로도 검증했으며 내부 시간 오류 경로 검사는 경계 fault injection으로 수행해 자연 발생 provider 오류의 재현으로 주장하지 않는다.

오프라인 compact JSON/o200k 추정 빈 출력은 원래 OFF 9·flat ON 15·typed OFF 30·typed ON 36토큰, schema는 각각 2,270·2,519·2,753·3,002토큰이다. 실제 API 사용량·지연·설정 회수율은 아니다. 인물 이름과 지칭을 서로 다른 인물로 바꾼 합성 관찰도 여전히 위치 검증을 통과했다. 따라서 기존 대명사 인물 오결합이나 같은 호출의 설정 누락이 해결됐다고 보고하지 않는다.

오프라인 검토 후 격리 코드를 `80b216a6d77df4cc7ec0128c08d645b6b705692d`에 동결했다(기준 v4 `c731d4fcd8e40ce59a67dc2423326d140f377007`). 독립 검수 SHA-256 `ed8049ada728a08cdf6808cf3a71364a9e80f83c3b3102eda8ad0204f9309989`, 작성자 요청 동등성 증거 `7cc996b9ceedb473a1893ecd67f8702223f844092f6ffea9e76f2113ed473490`, 새 테스트 파일 `0be347efe4974551b0d8a76e16cdee38f3b63538bfc5d6120d0fa2d109dd6e19`다. 본 통합 브랜치에는 문서만 반영했고 격리 코드를 가져오지 않았다.

**이 오프라인 동결 시점에는 실제 v8 모델 호출·품질 평가·운영 승격을 하지 않았다.** 미열람 확인 자료는 열지 않았다. 이후 새 실행기를 검증하고 입력·모델·호출 상한·중단 조건을 별도 동결해 수행한 실제 평가는 다음 절에 기록한다. 이전 R2 실패의 대체 실행이 아니며, 작성 dev 사례에는 FINAL Gold의 가중 recall/MUST 분모를 새로 만들어 붙이지 않는다. 운영 v2 기본 OFF와 기존 NO-GO는 유지한다.

### 2026-10-27 유형별 출력 v8: 실제 소설 세 방식 비교 완료

위의 오프라인 준비 이후 새 계획을 동결하고, 동일한 사용자 FINAL 소설 1~4화를 원래 OFF(A) → 유형별 OFF(B) → 유형별 ON(C) 순서로 각각 한 번씩 끝까지 실행했다. 이전 v7 연구의 실패한 R2를 대체하지 않는다. A는 기존 평면 출력이고, B/C는 앞 절의 동일한 여섯 배열 구조다. B와 C는 기존 OFF의 canonical schema hint 순서를 공유한다. B−A는 출력 schema·지시·펼치는 순서의 변경 전체이고, C−B는 같은 유형별 구조에 관계 관찰을 추가한 차이다. 한 반복으로 모델 내부의 주의 분산이나 인과 효과를 입증하지 않는다.

추출만 `gpt-5.6-sol/high`, 주체 해소 `gpt-5.6-terra/medium`, 비교·judge는 `gpt-5.6-sol/medium`이다. `FIXED / CHARACTER / SCENARIO_LOCAL`, 회차별 한 청크, 기존 Gold·31개 schema·상태·채점기·judge 의미를 유지했다. 기본 medium 제품 실행과 구분한다. 추출 상한 32,000 및 기존 절단 재시도 64,000, 주체 2,000·비교 128,000·judge 32,000을 유지하며 `store=false`다. 모델 별칭의 provider backend snapshot은 고정하지 못했다.

실행 전에 predict와 score가 공유하는 40회 요청 상한을 동결했다. 실제 네트워크 전 영속 차감하며 실패·검증/절단 재시도·judge 재귀 분할과 토큰 계산 요청도 포함한다. 실패한 요청을 환급하거나 원문·후보를 잘라 상한을 맞추지 않는다. 이 상한은 금액·토큰 예산이 아니다. transport/provider·capture·예산 오류 뒤에는 다음 요청을 막고, 기존 후보별 검증·격리와 정상 추출의 재시도 의미는 유지한다.

원래 계획은 R1 결과가 두 control의 가중 재현율·MUST FULL과 원문 보존·관계 검증을 모두 통과할 때만 세 arm의 R2를 역순 실행하는 조건부 설계였다. B 채점 중 사용자가 현재 작업 단위 완료 후 중단을 요청했다. ##### 원시 응답과 원문에서 확인한 차이

A의 61개, B의 57개, C의 52개 원시 canonical 후보를 발견·프로필·수치·상태·아이템/스킬·기타/시간 전체 범위에서 확인했다. canonical 및 시간 인용은 각각 115/115, 99/99, 85/85개가 원문 substring으로 확인됐다. 정확한 인용은 인물·확정성·시간 의미의 정확성과 별개다.

- **구조 변경만으로도 회복과 손실이 함께 있었다.** B는 A에서 빠진 효율을 중시하는 성향, 별도 성별 속성 3개, 식량을 추출했고 종족 경로를 회복했다. 반대로 다른 회차의 성별 속성 5개·언어 이해·키·경험치 증가와 일부 전문 분야 정보가 빠졌다. 성향은 다른 경로로 출력되어 내용 회복과 identity 점수가 일치하지 않았다.
- **관계를 추가한 C는 B의 일부 회복을 다시 잃었다.** 외형, 별도 성별 3개, 식량은 B에 있었지만 C 원시 후보에는 없었다. 효율 성향도 C에서 빠졌지만 B가 이미 경로 불일치였으므로 이 실제 손실은 가중 identity 차이에 나타나지 않는다. 반대로 C는 키 정보를 기존 동결 Gold의 허용 별칭으로 회복했고, B에서 빠진 전문 분야도 다시 추출했다.
- **C−B 가중 차이 −8은 손실과 회복을 모두 포함한다.** SHOULD 다섯 항목의 identity 손실 −10과 키 회복 +2다. B−A는 −12, C−A는 −20이며 분모는 모두 144다. C−A 차이 전부를 관계 추가의 효과로 부르지 않는다. 성별·언어·경험치 누락과 주체 미해결 중 일부는 B에도 이미 있었다.
- **중요 설정의 부분적인 성공은 유지됐다.** 무기 2개, 직업 3개, 레벨·능력치 6개 MUST는 세 arm 모두 남았다. 다른 인물의 종족 누락은 세 arm의 공통 실패였다. 소지품이나 상태의 일부 값 불일치를 내용 전체의 누락으로 바꾸지 않았다.
