# v0008 — 캐릭터 비교의 전체 prompt 토큰 예산

[상세 근거](details/v0008.md) · [전체 목록](README.md)

캐릭터 비교를 고정 후보 수·문자 수 대신 실제 전달하는 전체 prompt의
입력 추정량으로 나누도록 바꾼다. 긴 기존 문맥과 후보를 Java에서 미리 자르지 않는다.

- 같은 인물·FactType 후보를 원문 순서로 하나의 논리 그룹에 전달한다.
- 입력 기본값은 256,000토큰, 출력은 reasoning을 포함해 128,000토큰이다.
- 개수 상한 없이 전체 후보의 판단·실패·의존성·제거 참조를 보존한다.
- 출력 절단만 해당 segment를 절반으로 재시도한다. 단일 절단은 실패로 남긴다.
- 대표 시점·현재값·회복/종료 이력·evidence와 앞선 성공을 다음 입력에 유지한다.
- 필수 공통 문맥이 넘으면 남은 후보에 크기 실패를 기록하며 문맥을 자르지 않는다.

| 검증 | 결과 |
| --- | --- |
| 오프라인 회귀 | AI 2,549 통과·45 제외 / Java 592 통과·1 제외·패키징 통과 |
| 출력 절단·필수 문맥 초과 | source 순서·앞선 성공·정확 실패 coverage 회귀로 검증 |
| 다단계 의미 품질 점수 | — 미측정 |
| 실제 모델/HTTP | Sol medium 1회·왼손 2건 PAST 이력 보존·현재 시점/흉터/회복 근거 보존 |

검증되지 않은 모델 tokenizer는 보수적 UTF-8 입력 추정을 사용한다.
예약 상한은 실제 청구량이 아니며 실제 input+output 사용량으로 정산한다.
기존 환경변수에 명시된 옛 값은 새 기본값을 덮으므로 배포 때 확인해야 한다.

이전 v0006/v0007 결과·원문·Gold는 그대로 보존했다.
운영 배포·live 환경변수 변경은 수행하지 않았다.
최종 복원 SHA·구현 PR은 병합 전에 보완한다. 실제 비교는 좁은 사례 1회이며 전체 의미 평가는 미측정이다.
