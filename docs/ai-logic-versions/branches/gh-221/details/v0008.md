## 변경 경계

Java의 캐릭터 10개/30,000자 claim 상한과 기존 단건 문자 guard를 제거한다. 같은 인물·FactType의 전체 논리 그룹, 원문 순서, frozen context/version/hash/lease 검증은 유지한다. AI/Java 묶음 schema의 후보·decision·dependency 20개 및 제거 참조 30개 방어 상한도 제거해 전체 그룹의 결과를 전달한다. 기존 단건/CONFIRMED_ONLY snapshot 30개 정책과 세계관/1차 추출 정책은 이번 범위가 아니다.

AI는 `LLM_CHARACTER_FACT_BATCH_COMPARISON_MAX_INPUT_TOKENS=256000`과 `LLM_CHARACTER_FACT_BATCH_COMPARISON_MAX_OUTPUT_TOKENS=128000`을 기본으로 사용한다. 개수 설정 `CHARACTER_FACT_COMPARISON_BATCH_MAX_CANDIDATES`는 제거한다. 전체 system/user/schema/여유분을 포함한 입력을 추정하며 확인되지 않은 tokenizer mapping을 만들지 않는다. `gpt-6.1-sol`의 정확 tokenizer는 확인되지 않아 보수적 UTF-8 추정을 사용한다. 외부 token-count API를 prefix마다 호출하지 않는다.

출력 128,000에는 reasoning과 visible output을 함께 포함한다. 예약 최소 상한 128,256과 가격 가중치는 실제 사용량과 구분한다. 실제 정산은 공급자가 반환한 input+output token 사용량으로 수행하며 캐시 정책과 요금 가중치를 바꾸지 않는다. 명시적 기존 환경변수는 새 기본값을 덮으므로 운영 적용은 설정 검토·배포 뒤에 따로 검증해야 한다.

입력 분할과 출력 절단 재분할은 앞선 성공의 projected snapshot, C/P/Q 참조, dependency, 대표 시점, current source 시점, 회복·종료 이력과 읽기 전용 evidence를 보존한다. 출력 절단에만 해당 segment를 원문 순서로 절반 분할하며 단일 절단은 `LLM_OUTPUT_TRUNCATED`다. 후보 자체 입력 초과는 `COMPARISON_VALIDATION_FAILED`/`character_batch_input_limit_exceeded`, 필수 공통 문맥 초과는 같은 failure code/`character_batch_required_context_input_limit_exceeded`로 남은 후보를 정확히 덮고 논리 묶음을 중단한다. 입력을 자르지 않으며 이전 정상 decision을 잃지 않는다. quota와 frozen/stale/lease 오류는 fatal 경계를 유지한다.

정적 비교 지침과 prompt cache namespace는 변경하지 않는다. 출력 상한·응답 schema·실행 분할 변경이므로 새 로직 버전으로 기록한다.
