## 남은 검증과 계약 한계

작업 4에서 새로 고정할 긴 문서와 세 문서 순서의 추출·비교·현재값·검토 연결 검증이 필요하다. 짧은 합성 단건/후보 1개 묶음의 결과를 다중 후보 의미 판단이나 전체 파이프라인 품질로 일반화하지 않는다. 서로 다른 비교 조각·이미 완료한 단계에 흩어진 내부 충돌의 소급 철회 기능을 추가하지 않았다.

인물 기존 REVIEW_REQUIRED는 target ref·proposal·removal을 허용하지 않아 일반 확인 필요와 비교한 확정값의 내용 충돌을 같은 source 연결로 구별할 수 없다. 이 한계는 작업 2의 최소 기존 필드 재사용 계약 검증 대상으로 전달했고, 이번 고정 대조 실행 중 schema를 변경하지 않았다. 세계관 GENERAL_UNCERTAINTY의 단일 source 제한은 유지하며 다중 source CONFLICT는 operation과 무관하게 서버 자동 반영 보류가 필요하다.

미완료 C02 때문에 현재 Java ORDERED claim이 요구하는 `supportsFrozenComparisonEvidence=true`를 AI가 아직 소비·전송하지 못한다. 실제 worker 전체 연결을 완료했다고 주장하지 않는다. 설치 없이 실제 provider 결과를 현재 Java 소스의 격리 publish/context/complete 검사에 넘기는 경로는 별도 작업이다. PR·배포·복원 SHA 보완과 긴 문서 재검증은 담당 root의 다음 승인 범위에서 수행한다.


## 작업 2 — 검토 연결·선택적 기준시점·PG 호환 계약, 2026-10-09

동일 PR1의 후속 구현이므로 AGENTS의 PR당 전체 로직 버전 하나 규칙에 따라 v0007에 추가한다. 위 작업 1의 실행·수치·조건은 당시 상태의 기록이다. 작업 공간의 `checkpoints/task-1-ai/files`와 `manifest.json`, 작업 1 report 및 모든 medium/max 원시 관찰을 보존했다. 현재 v0007 요약과 아래 작업 2 변경은 별도 재검토 대상이며 작업 1 PASS를 현재 코드 전체의 PASS로 사용하지 않는다.

- 인물 batch PRESENT REVIEW_REQUIRED만 기존 활성 P/Q ref를 같은 canonical Fact 유형·key의 비양립 항목에 읽기 전용으로 연결한다. proposal·removal·mutation target type/key는 비운다. projection은 계속 비투영이고 기존 projector가 실제 현재 묶음 기여자만 dependency로 산출한다. 배치 검증 실패 후 한 후보씩 재비교하는 경로도 기존 compare_batch를 사용하므로 계약이 유지된다. 구 compare 단건 API의 mutation target 의미는 변경하지 않았다.
- 일반 불확실성·결과 없는 치료 시도·PAST/HYPOTHETICAL/UNKNOWN 검토는 target=null이다. PRESENT 검토 참조도 BOOK 본문 시작과 기준 anchor가 상충하면 거부한다. 같은 현재값의 의미 충돌인지 결정하는 일은 모델에 남으며 텍스트 분류기나 새 field/enum을 만들지 않았다.
- 자동 호출은 기존 validate_current_change에 검증한 operation만 내부로 전달한다. 목적지 MERGE는 기존 의미/출처를 보존하며 알려진 같은/이전 시점도 허용한다. 명시적 UPDATE/STATUS 종료는 모든 알려진 현재 출처의 선후 검사를 유지하고 PRESENT BOOK/UNSPECIFIED의 선택적 공백만 허용한다. 출처 불명·비PRESENT·보호·본문/anchor 상충, 이동/출처 경로의 엄격한 기본 검사와 수동 기본 경계는 유지한다. 출처 시점은 삭제하거나 만들지 않았다.
- 세계관 source 하나의 확정 현재 충돌은 최종 `CONFLICT + REVIEW_REQUIRED + GENERAL_UNCERTAINTY`다. 실제 target/matched/proposed canonical 경로, 같은 원본 scope, 한 incoming, 비어 있지 않은 모두 PRESENT인 현재 source times, 확정 PRESENT 원문과 이동 없음만 허용한다. 원본 설정명이 canonical 경로의 동의 표현이면 source 이름을 보존한다. BOOK은 기존 ASSERTED 표식을 요구하며 EPISODE에 없는 표식을 요구하지 않는다. normalization은 실제 현재값과 새 원문값을 모두 보존하고 원본 source·인용은 바꾸지 않는다. 일반 SINGLE/GENERAL_UNCERTAINTY와 구분하며 없는 현재 경로를 만들어 검토 연결을 성립시키지 않는다.

초기 null reviewReason 설계는 Python 2,483 검사에서 통과했지만 실제 Java PostgreSQL 검사에서 기존 V54 CHECK가 거부했다. DB/migration을 바꾸지 않고 기존 사유를 유지하는 위 조합으로 정정했다. 기존 null 설계와 고정 응답 입력은 `ai-verification/task2-pre-pg-correction/files` 및 manifest, 전체 검사 원본은 `task2-full-with-fixtures.*`로 바이트 보존했다. 이 자료를 최종 PG 호환 증거로 사용하지 않는다. 교정 후 새로운 `task2-world-pg-reason-correction-red.*`와 `task2-full-after-pg.*`에 별도 기록했다.
