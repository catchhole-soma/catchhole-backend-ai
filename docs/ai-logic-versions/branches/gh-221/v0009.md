# v0009 — Sol 6.1 캐릭터 비교의 정확 입력 토큰 수

[상세 근거](details/v0009.md) · [전체 목록](README.md)

Sol 6.1 캐릭터 비교의 입력 분할을 OpenAI가 센 정확 token 수로 판정한다.
전체 문맥을 포함해 256,000 이하는 허용하고 초과하면 원문 순서로 나눈다.

- 생성과 같은 model·역할·본문·reasoning·응답 schema를 count endpoint에 보낸다.
- 동일 입력은 fit·생성 전 확인·예약에서 재사용해 보통 count 1회+생성 1회다.
- 전체 그룹이 넘을 때만 prefix를 이진 탐색한다. feedback·투영 문맥 변경은 다시 센다.
- 현재값·대표 시점·회복/종료 이력·근거와 앞선 성공 판단을 보존한다.
- count 실패나 잘못된 응답은 생성 전에 Job 오류로 중단한다.
- 출력 128,000과 기존 quota·lease·출력 절단 복구 경계는 유지한다.

| 검증 | 결과 |
| --- | --- |
| 오프라인 회귀 | 전체 AI 2,570 통과·45 제외 / 후속 exact 22개 통과 |
| 실제 count/generation | 일반 실행 1 count+1 생성·8,943=usage 8,943 / 이번 검증 총 4 count+1 생성 |
| 다단계 의미 품질 점수 | — 미측정 |

예약량은 정확 입력+출력 상한이며 실제 공급자 사용량으로 정산한다.
count API 호출은 생성 호출과 별도로 기록한다.
다른 목적에 count 호출을 추가하지 않는다.

이전 v0006/v0007/v0008의 입력·Gold·결과를 보존했다.
운영 배포·live 환경변수 변경은 수행하지 않았다.
최종 복원 SHA·구현 PR은 병합 전에 보완한다.
실제 합성 경계는 257,096 초과·255,510 허용을 확인했다. 큰 입력 생성은 실행하지 않았다.
실제 의미 검증은 STATUS batch 1회이며 전체 의미 평가가 필요하면 고정 조건으로 별도 실행해야 한다.
