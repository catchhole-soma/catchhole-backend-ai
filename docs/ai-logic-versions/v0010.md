# v0010 — 일회성 대화의 후속 질문과 최신 근거 재조회

2026-10-13 · 적용: `feat/gh-241-chat-context` 작업 브랜치, 기본 OFF

## 무엇을 바꿨나

- Spring이 선별한 최근 대화로 “그 마법”, “그 능력”의 지칭을 해석한다.
- 과거 답변을 사실 근거로 재사용하지 않고 현재 RDB·직접 근거·원문을 다시 읽는다.
- 문맥은 최대 6턴/답변 1,000/전체 8,000 UTF-16 단위다. 분류·행 선택·근거 생성 모두 최신 조회 결과를 보존하며, 입력 예산을 넘으면 오래된 문맥부터 빼고 생략을 안내한다.
- QA 행 선택은 v3, 나머지 분류/생성은 v2다. 회차 범위의 과거 대화 계승을 조회 전에 차단하고 선택 단계에도 문맥 생략을 알린다. 문맥 요약을 위한 추가 모델 호출은 없다.

## 평가

상태: 구현·계약/회귀 검증 완료. 실제 모델 품질은 미측정.
조건: 합성 대화, 고정 모델 출력, 실제 격리 PostgreSQL·Spring·Python·브라우저 연결. provider/embedding/judge API key 미사용.

| 검증 | 결과 |
| --- | --- |
| 새 문맥 계약/재조회 회귀 | 최신 근거 우선 보완 후 34 통과 |
| Python 전체(외부 DB env 미주입) | 최신 근거 우선 보완 후 2,460 통과 / 50 skip |
| Java 전체+bootJar | 1,758 통과 / 24 skip |
| Front 전체 / 별도 실제 로컬 연결 | 524 통과·12 skip / 1 통과 |
| 실제 모델의 지칭 해석·사실 정확도·비용 | — 미측정 |

연결 예: 현재값 35 → 수동으로 42로 수정 → “그 마법의 소모 마력은?” → 새 조회값 42.
원문 장면 질문은 실제 청크 검색과 Spring 인용 검증을 거쳐 근거 창/현재 원문 링크로 연결했다.
대화 종료 후 본문 삭제와 이미 발생한 호출의 정산 보존을 별도 검증했다.
리뷰 보완 검증: Front 챗봇 12개·실제 연결 1개, Java 세션·실행 H2/PG 69개 통과(세션 각 20개 포함). 로컬 Java 전체는 VM 시계 차이로 기존 이메일 TTL 테스트 1개 실패했으며 상세에 보존했다.
한계: 고정 출력 대역은 배포 모델의 의미 정확도를 증명하지 않는다. 긴 대화의 앞부분과 답변 뒷부분은 생략될 수 있다.

운영: 배포·기능 활성화·백필 미실시. 기존 분석 Worker 로직·모델 설정은 변경하지 않았다.
