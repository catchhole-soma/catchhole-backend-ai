# v0004 — 회차별 자동 확정과 연속 분석 안정성

2026-09-13 · 적용: [AI #70](https://github.com/catchhole-soma/catchhole-backend-ai/pull/70) · 이전 기준: [main v0003](v0003.md)

## 무엇을 바꿨나

- 한 회차의 정상 설정을 저장한 뒤 다음 회차가 최신 확정 설정과 미해결 참고를 구분해 읽는다.
- 개별 연결·비교 오류는 원인과 원문을 보존해 검토로 남기고 다른 후보와 다음 회차를 계속 처리한다.
- 잘못된 응답의 제한된 재시도·부분 복구와 일반 불확실성 검토를 유지한다. 계정·사용량·입력·저장 오류는 계속 중단한다.
- #65의 세계관 추출·분류 변경을 제외하고 최신 main 위에 분리했다. main의 새 인물 평가·provider 진단·300초 읽기 제한은 유지한다.
- main v0003(#69)의 그룹 비교 handoff를 반영한다. 기존 모드는 입력 종료 후 그룹 비교를 수행하고, 누적 모드는 원래 회차 Job에서 비교·자동 저장을 끝낸 뒤 다음 회차로 진행한다. #65 선행 머지는 필요하지 않다.

## 검증과 한계

**최신 main 통합 코드의 정답지 기반 정확도·재현율은 미측정이다.**

| 확인 | 결과 |
| --- | --- |
| 오프라인 전체 pytest | 1,883 통과 · integration 14개 제외 |
| Ruff | 통과 |
| 사전 캐시 없는 테스트 환경 | context 전달 테스트 12개 통과 |
| main과 세계관 1차 추출 요청 대조 | 완전히 동일 |
| 기존 모드 요청 6종 | 모델·추론·사용자 입력·응답 형식·출력 상한 유지 |
| PostgreSQL 저장 경계 | 별도 테스트 DB에서 12개 통과 |
| Spring HTTP ↔ Python Worker | 합성 연속 분석·부분 복구 등 9개 통과 |
| 저장 예측 평가 3종 | 독립된 main에서 생성한 ORACLE/FIXED/ROLLING 전체 보고서와 동일 |

최신 main 통합 코드의 복원 SHA는 이 코드 커밋 직후 문서 커밋에 기록한다. 이전 #65 분리 코드: `6b881363d1624cfea1d8552aff8cb6aec18b32dd`.
이 검증은 합성 입력·고정 응답이며 외부 LLM을 호출하지 않았다. 이번 main 통합에서 별도 PostgreSQL/Spring 통합을 새로 실행했다. 실제 원고를 통한 외부 LLM 연속 분석은 실행하지 않았다.
이전 로컬 코드의 실제 21~40화와 41~50화는 각각 20·10회차 연속 완료했지만, 이번 분리 코드의 실행 결과로 취급하지 않는다.
주체 과병합과 과도한 검토 보류 가능성은 남아 있으며, 이번 작업을 정확도 개선으로 주장하지 않는다.
GH180 담당은 분리 코드의 다음 실제 연속 실행을 확인하고, 정확도 담당은 별도 이슈에서 동일 Gold·모델·judge의 FIXED 평가를 수행한다.
과거 실행의 Terra/Luna/Luna·none 조건은 운영 기본 조합과 구분한다.
