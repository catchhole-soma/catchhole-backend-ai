# v0033 — 챗봇 계획 계약 정규화·집중 조회 되돌림·다인물 비교 예산 (#319 2차)

2026-10-31 · 적용: 작업 브랜치 `feat/gh-319-chat-quality-v3` · [Java #319](https://github.com/catchhole-soma/catchhole-backend-java/issues/319)

## 무엇을 바꿨나

- 발표용 질문셋에서 뽑은 결함 18문항이 **모델 품질이 아니라 결정적 경로**에서 실패했다. 계획 응답의 흔한 계약 위반 3종(등록값 필수 + 원문 보완, 등록 전용인데 요구 항목이 남음, 보완인데 요구 항목이 없음)은 재호출 대신 정규화한다. 재호출이 모델 호출 상한(6)을 소진해 뒤 단계가 `EXECUTION_LIMIT_EXCEEDED`로 끝났기 때문이다. 두 번째 계획 응답까지 질문에 없는 항목 이름(focus.attribute)만 틀리면 되묻기·실행 실패 대신 그 이름을 비우고 유형으로 진행한다(`FOCUS_ATTRIBUTE_DROPPED`). 두 속성 × 두 인물 질문이 5회 중 3회 계획 단계에서 끝났다.
- 집중 조회가 0행으로 포기하던 세 경로를 되돌림으로 바꿨다. 질문한 항목 이름과 등록 이름이 달라 선택이 비면 그 유형의 현재값 전체에서 고르고(`FOCUS_FALLBACK`), 질문한 유형에 항목이 없으면 유형을 비운 항목 목록에서 다시 고르고(`FOCUS_TYPE_WIDENED`), 인물 항목 선택이 모호해도 질문한 속성 자체가 겹치지 않으면 되묻지 않고 현재값을 읽어 고른다. 항목 목록은 값 없는 메타데이터라 50개씩 읽는다(`fields_page_size`).
- 여러 인물의 현재 속성 비교는 이력을 건너뛰고 현재값으로 답한다(`HISTORY_SKIPPED_FOR_COMPARISON`). 항목 158개인 인물 둘의 이력까지 읽으면 도구 상한 20을 넘겨 "항목을 모두 확인하지 못함"으로 끝났다. 첫 답변이 출력 상한에서 잘리고 복구 시간이 없으면 실행 실패 대신 `ANSWER_LIMIT` 안내로 마감한다. 원문 질문에 등록값을 함께 묻는 혼합 계획에서 원문 라운드 예약 때문에 등록 항목 목록을 다 읽지 못하면 되묻지 않고 등록 현재값은 미확인으로 둔 채 원문 답변을 계속한다(`REGISTERED_LOOKUP_INCOMPLETE`).
- hybrid plan v13 / QA plan v10: 동명이인·전수 질문은 `NONE + SCENE + EARLIEST + LIST/COUNT`로 회차를 분산해 수집하고, 부재 확인("레벨 4가 된 적 있어?")은 `HISTORY + SUMMARY`로 예/아니오를 먼저 말한다. 이름이 명시된 인물의 현재 속성·비교는 CURRENT만 조회하되 능력·효과·출처 설명은 원문을 유지하고, 이름 없는 규칙·수치 질문은 되묻지 않는다. answer v16·검색·근거 예산·모델은 바꾸지 않았다.
