# v0033 — 충돌 의심 판정 전 변화·예외 검색 보완

2026-10-31 · 적용: 작업 브랜치 `fix/gh-341-change-search-insert` · [Java #341](https://github.com/catchhole-soma/catchhole-backend-java/issues/341)

## 무엇을 바꿨나

- 실제 Terra가 변화·예외 조회 없이 충돌 의심(SUSPECTED_CONFLICT)을 내면 `INVALID_DECISION_CHANGE_SEARCH_MISSING`으로 설정 분기 전체가 PARTIAL로 끝났다. 다시 시도해도 입력이 같아 같은 질문에서 멈췄다. 이제 Worker가 그 질문에 KEYWORD 변화·예외 검색 하나를 넣고 결과를 붙여 다시 묻는다.
- 검색은 질문당 한 번이다(대상 언급+설정 항목으로 query 생성, FOLLOW_UP과 같은 revision `NEW_CLUE`). 재개·재시도·검색 실패에도 다시 넣지 않는다.
- 다시 받은 판정이 그 검색을 인용하지 않으면 실제 receipt만 덧붙인다. 판정·사유·등급·prompt·schema·예산·Backend 계약은 바꾸지 않았다.

## 평가

상태: 미측정(실제 모델) · 자동 테스트 완료
조건: 스크립트로 응답을 고정한 가짜 모델 · 실제 provider/DB/네트워크 호출 없음
소요: —

| 항목 | 결과 |
| --- | --- |
| 조회 없는 충돌 의심 → 검색 1회·재질문·완료 | 통과(revise 1회, Backend 판정 조건 충족) |
| 재질문이 검색을 인용하지 않음 → receipt 보완 | 통과(`CHANGE_SEARCH_RECEIPT_FILLED`=1) |
| 모델이 이미 검색함 / 검색 실패·재개 / revise 직후 crash | 재삽입 0 |
| query를 만들 수 없음 | 기존 `CHANGE_SEARCH_MISSING` 유지 |
| 자동 테스트 | 전체 4,914 통과 / 141 skip / 기존 경고 1, 검수 집중 93 통과 |

실제 모델 재실행: 리뷰어 확인 예정

결과: 질문 하나의 계약 위반으로 분기 전체가 멈추던 경로를 결정적으로 보완했다. 실제 모델에서의 완료율과 판정 품질은 아직 확인하지 않았다.
남은 문제: 검색이 변화를 찾지 못해도 충돌 의심은 그대로 남는다(의미 판단 불변). 같은 원인 질문 미병합과 범위 판정 FN/FP(#331 평가)는 별도다. 열린 AI #108도 v0033을 써서 나중에 머지하는 쪽이 번호를 다시 매긴다.
