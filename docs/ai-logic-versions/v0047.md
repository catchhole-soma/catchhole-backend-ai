# v0047 — 챗봇 답변 아래 안내를 네 문구로 축소·발생 코드 기록 (#319)

2026-11-06 · 적용: 작업 브랜치 `feat/gh-319-chat-answer-notes`, 미배포 · [Java #319](https://github.com/catchhole-soma/catchhole-backend-java/issues/319)

## 무엇을 바꿨나

- 챗봇 결과의 `limitations`(화면의 "답변에서 확인할 점")에 부분 답변, 등록 설정·원고 충돌, 검색 준비가 덜 된 회차, 원고·검색 저장소 오류 네 문구만 싣는다. 평가 85문항 집계(제품 담당자 제공, 이 작업에서 다시 세지 않음)에서 절반가량의 답에 조회 과정 설명이 붙었지만 작가가 할 수 있는 일이 없었고, 붙은 답(45개 중 정답 21)과 안 붙은 답(40개 중 정답 20)의 정답률이 비슷했다.
- 내부 안내 코드·문장과 발생 조건, 답변 본문, 프롬프트와 답변 모델 입력은 그대로다. 결과가 Python 프로세스를 떠나는 실행 경계 한 곳에서 화면 문구로 바꾼다.
- 숨긴 코드는 결과마다 `chat_answer_notices attempt=… outcome=… codes=[…] shown=[…]` 한 줄로 남긴다. 코드 이름만 기록한다.

## 평가

상태: 미측정 — 실제 모델 호출 없음. 모델 호출 없는 합성 재현으로 공개·기록 경로만 확인했다.
조건: 프롬프트·모델·검색·답변 본문이 같으므로 정답률 재측정은 하지 않았다. 답변 모델 입력이 같다는 점은 합성 회귀로 확인했고 실제 모델 실행으로 확인한 것은 아니다.

| 검증 | 결과 |
| --- | --- |
| 전체 자동 테스트 | 5,553 passed / 170 skipped / 기존 경고 1개 (변경 전 5,385 / 170) |
| 공개 문구 | 네 문구만 공개, 묶인 코드는 한 번, 숨긴 코드 47개는 결과 종류 3가지 모두에서 결과에 없고 기록에 있음 |
| 기존 검증 | 문구로 코드 발생을 보던 26개 테스트 파일의 단언을 기록 검사로 옮김. hybrid의 부분 답변 판단을 일부러 바꾸면 10개가 실패함 |

결과: 화면 문구만 바뀌고 답변은 같다. 다만 `PARTIAL_ANSWER` 문구("질문의 일부에만 답했어요.")는 현재 실제로 붙는 경로가 없다. 원문 결합 답변은 부분 답변을 본문에서 설명하고 이 코드를 결과에 붙이지 않으며, 답을 보류한 결과에 남은 코드는 문구로 내보내지 않기 때문이다.
남은 문제: 허용 범위에 회차가 하나도 없는 경우(`NO_SUPPORTED_SOURCES`)의 문구가 없다. 임베딩 백필이 늦거나 꺼진 작품은 원문 검색을 쓴 모든 답에 검색 준비 문구가 붙는다. 화면 확인과 운영 로그량 확인을 하지 않았다.
다음: 부분 답변 문구를 실제 부분 답변에 붙일지(hybrid 판단 변경 필요)는 제품 결정이다. 다음 챗봇 평가 실행에서 문구가 붙은 답의 수와 종류를 `chat_answer_notices` 기록으로 센다(담당: 챗봇 평가 담당자).
