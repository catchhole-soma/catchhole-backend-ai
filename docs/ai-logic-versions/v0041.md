# v0041 — 관계 비교 입력 분할과 실패 복구 진단

2026-11-02 · [상세 근거](details/v0041.md) · [Java GH332](https://github.com/catchhole-soma/catchhole-backend-java/issues/332)

관계 백필이 비교 검증7건·입력 제한2건으로 멈춘 상태를 복구하기 위한 변경이다.
64k를 넘는 입력만 관련 인물 쌍으로 나눠 비교하고 원문·근거·참조를 보존한다.
일반 크기 입력과 캐릭터·세계관 추출은 기존 경로를 유지한다.

| 검증 | 결과 |
| --- | --- |
| 전체 pytest | 5,094 passed / 143 skipped / 기존 경고1 |
| 후속 변경 범위 / 변경 Ruff | 59 passed / 통과 |
| 운영 입력 제한2건의 가장 큰 투영 성분 | 10,446 / 9,661 UTF-8 bytes |
| 사전 확인의 DB 쓰기 / 모델 호출 | 0 / 0 |
| 실제 관계 의미 정확도·Gold 점수 | — (미측정) |

모든 입력 묶음을 먼저 검사하고 최대16회 순서대로 비교한다.
합친 결과를 전체 문맥으로 다시 검증하며 일부 결과만 반영하지 않는다.
이전처럼 상세 원인을 버리지 않고 고정 코드로 남기며 원문과 오류 문자열은 숨긴다.

Java가 적격 서비스 부담 실패 회차를 한 번만 복구하고 새 Worker만 가져간다.
저장된 검증 관측을 재사용하므로 복구를 위해 관계 추출을 다시 호출하지 않는다.
Java API가 먼저, AI Worker가 나중에 배포돼야 이 경로가 시작된다.

입력 크기 사전 확인은 실모델 판정이나 정확도 개선의 증거가 아니다.
검증 실패7건의 정확한 원인은 기존 기록에 없으며 재실행 진단으로 확인해야 한다.
별도2작품의 일반 분석 순서 막힘은 이번 관계 복구에서 임의로 취소·재시도하지 않는다.
현재는 미머지·미배포이며 운영 완료와 실제 비용은 아직 검증 전이다.
배포 후 실패·공개 세대·서비스 부담 사용자 차감0을 확인하고 남은 원인을 기록한다.
