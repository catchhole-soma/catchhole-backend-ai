- 기존 운영 설정으로 비밀값·읽기 전용 DB 계정·사설 연결을 자동 준비한다.
- 동일 이미지로 챗봇을 배포하고 정기 실행기가 기존·신규·수정 회차를 인덱싱한다.
- 준비된 원문·미전송 보고·실행 상태를 확인한 뒤 최초 공개하고 이후 수동 OFF는 보존한다.

최종 전체 실행에는 실제 Compose 해석 5개가 포함된다.
skip 중 PostgreSQL 82개는 별도 격리 환경에서 실행했다.
사용자 원고·운영 DB·실제 provider/judge는 사용하지 않았다.
새 기본 정책은 활성 작품의 현재 원문, 서비스 부담 누적 입력 상한 5천만이다.
이는 보수적 실행 상한이며 400회차의 실측 토큰·비용이 아니다.
기존 범위·모델·예산·DSN과 분석 설정·프롬프트·청크 크기는 유지한다.
공통 설정 충돌·넓은 접근 허용·부족한 DB 권한을 거절하고 호출 전 일시 오류의 제한된 재시도를 보완했다.
진행 상태와 예산은 재배포로 초기화하지 않으며 불확실 호출은 명시적 재개가 필요하다.
외부 API와 DB의 exactly-once, 설정집/과거 버전 인덱싱은 지원하지 않는다.
IAM·DB 권한·자원 부족은 자동 확대하지 않고 원인을 보고한다.
첫 백필이 30분을 넘으면 timer를 유지하고 최신 배포 재실행으로 공개를 이어간다.
