# v0032 — 검수 모델 출력의 대상 참조·위치·조건부 판정 정규화

2026-10-30 · 적용: 작업 브랜치 `fix/gh-331-validation-target-ref` · [Java #331](https://github.com/catchhole-soma/catchhole-backend-java/issues/331)

## 무엇을 바꿨나

- 실제 Terra가 대상 원고를 `TSEG1`로 부르고 위치를 1~4자 틀려 설정 검사가 한 번도 끝나지 않았다. 입력에 `T1`을 명시하고, Worker가 span 참조와 위치를 모델 자신의 quote 기준으로 다시 맞춘다(없는 quote·모호한 반복은 거절).
- 모델이 되풀이할 필요 없는 값(FOLLOW_UP의 판정 필드, NO_CONFLICT의 영향, `required_reads`, 판정의 `target_spans`)은 서버가 확정한다. 참조 종류는 schema로 제한하고, 읽을 수 없는 조회 의무(frozen RAG 없는 VECTOR 포함)는 저장 전에 거절한다.
- `INVALID_INSPECTION_CONTRACT`로 묻히던 원인 코드·단계를 로그와 Backend `failure_code`에 남긴다. 판정 내용·사유·등급·모델·예산은 바꾸지 않았다.

## 평가

상태: 완료(실제 재실행에서 사례 3종 모두 COMPLETED 도달) · 의미 품질 점수 미측정
조건: 합성 사례 B2·A3 원본·A3 교체본 · 검수 `gpt-6.1-terra`(역할별 medium/high/low) · 추출 로컬 fallback `gpt-5.6-terra` · judge 없음
소요: report당 약 4~12분(재시도 포함)

| 항목 | 수정 전 | 수정 후 |
| --- | --- | --- |
| main 그대로 설정 분기 완료 | 0/4 | 3/3 report COMPLETED(재시도 포함) |
| `TSEGn` 참조 / 위치 재계산 | 63건 거절 / 25건 shim | 0건 / 설정 21·오탈자 5건 자동 |
| S3~S6·required_reads 위반 | 실패 다수 | 0건 |
| B2 0건 → 자동 완료 | shim으로만 | AUTOMATIC → APPLIED |
| 자동 테스트 | — | 전체 4,868 통과 / 140 skip, 실제 Java HTTP 27 통과 |
| 사례 대조(최종) | 오탈자 3/3, 파괴된 검 TP | 오탈자 3/3, 파괴된 검 TP(4건 미병합), 앞마당·망토 FN, 교체본 FP 1 |

결과: 계약 위반으로는 더 이상 멈추지 않는다. 재실행 중 VECTOR·prompt cache·`target_spans` 되풀이 문제가 새로 드러나 같은 브랜치에서 고쳤고, 그 원인도 Backend `failure_code`에 그대로 보였다.
남은 문제: 범위가 애매한 규칙을 NO_CONFLICT로 판정(FN), 같은 원인 질문이 여러 finding으로 남음, 교체본의 계획 외 NEEDS_CONTEXT 1건. 모두 판정·병합 단계의 의미 문제다.
다음: 질문 병합 기준과 범위 판정 개선은 별도 작업. JUDGE `target_spans`를 wire에서 빼는 정리는 Backend와 함께 판단. 운영 추출 모델·frozen RAG를 연결한 상태에서 운영 활성화 전 재평가(CatchHole 개발팀).
