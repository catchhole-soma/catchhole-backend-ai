# v0037 — 검수 의미 검색은 색인이 준비된 Job에만 제안

2026-10-31 · 적용: 작업 브랜치 `feat/gh-344-validation-vector-search` · [Java #344](https://github.com/catchhole-soma/catchhole-backend-java/issues/344)

## 무엇을 바꿨나

- 이전에는 검수 Worker에 원문 색인(frozen RAG)이 연결되면 모델에 의미(VECTOR) 검색을 항상 제안했다. 운영 색인은 일부 회차가 빠져 있어, 모델이 VECTOR를 고르면 `VECTOR_NOT_READY`·`VECTOR_INDEX_PARTIAL`로 설정 검사 전체가 끝났다. 이제 Job 시작 때 그 보고서 범위의 색인 상태를 최대 5초 동안 한 번 읽어, 모든 과거 회차가 임베딩되어 있고 query embedding이 설정됐을 때만 VECTOR를 제안한다. 읽기 실패·초과면 그 Job은 색인 없이 키워드로 계속한다.
- API가 선택 역할 QUERY_EMBEDDING을 설정하지 않은 claim은 실패 대신 키워드 검색만으로 실행한다(설정했는데 색인과 다르면 계속 거절). 이전 시도가 VECTOR를 저장한 Job은 재개 때 VECTOR를 유지해 이미 성공한 조회를 다시 막지 않는다.
- 운영 Compose는 의미 검색 플래그를 고정하고 읽기 전용 URL을 env로 opt-in한다(기본 빈 값 = 키워드만). 배포 검사는 URL이 있을 때만 챗봇 reader·색인 버전 일치와 DB 연결 예산을 확인한다. 챗봇 reader는 검수 범위 테이블 3개 SELECT를 더 받고, 배포 때 bootstrap이 grant를 갱신한다.

## 평가

상태: 미측정(실제 모델·운영 DB) · 자동 테스트 완료
조건: 스크립트로 응답을 고정한 가짜 모델 · 가짜 readiness/검색/embedding · 실제 provider/DB/네트워크 호출 없음
소요: —

| 항목 | 결과 |
| --- | --- |
| 색인 준비 + embedding 설정 | VECTOR 제안, `VECTOR_OFFERED`=1, `vector search offered=True` |
| 부분 색인 / vector 0 / embedding 없음 / 범위 불일치 | KEYWORD만 제안, 모델 VECTOR 의무는 저장 전 거절 |
| readiness 읽기 실패 / 5초 초과 | KEYWORD만, 그 Job은 색인 없이 원문 직접 읽기, Job 완료, 경고에 예외 종류만 |
| reader 허용 테이블 | 두 검색 repository SQL에서 도출한 10개와 정확히 일치 |
| 이전 시도가 VECTOR 저장 + 재구축 중 재개 | VECTOR 유지, 모델 호출 0으로 완료 |
| QUERY_EMBEDDING 미설정 claim | embedding 없이 진행(이전: `EMBEDDING_CONFIGURATION_INVALID`) |
| 자동 테스트 | 전체 4,998 통과 / 142 skip / 기존 경고 1, 검수·배포·bootstrap 집중 442 통과 |

결과: 모델이 실행할 수 없는 의미 검색을 고르는 경로를 결정적으로 막았고, 의미 검색을 env 하나로 안전하게 켜고 끌 수 있게 했다. 판정·prompt·schema 생성·Backend 계약은 바꾸지 않았다.
남은 문제: 실제 모델·운영 색인에서의 재실행(`offered=True`인 작품의 VECTOR 성공, 부분 색인 작품의 키워드 완료)과 의미 검색이 판정 품질·사용량·지연에 주는 영향은 미측정이다. 색인이 빠진 회차가 있는 작품은 계속 키워드만 쓴다. reader grant 변경의 일회용 PostgreSQL 통합 테스트는 실행하지 않았다.
다음: 리뷰어가 운영 활성화 전 실제 모델로 재실행한다. 활성화 순서는 `deploy/WORKER_EC2_DEPLOYMENT.md` 의미 검색 켜기 절을 따른다.
