# v0022 — 긴 생성 응답의 읽기 제한 900초

2026-10-24 · PR #91 최신 main 통합 · 실측일 2026-10-22 · 배포 결과는 연결 Actions에서 확인

## 무엇을 바꿨나

- Responses 기본 client의 읽기 제한만 300→900초로 늘렸다.
- 정상 설정집 추출 응답이 실제로 773.379초 걸렸다. 기존 300초 제한은 이런 정상 요청을 완료 전에 끊었다.
- 연결·전송·풀 제한 120초, 주입한 HTTP client, 재시도·모델·프롬프트·토큰 상한은 유지한다.

## 평가

상태: 타임아웃 수정 검증·설정집 성능 실측 완료 / 정식 Gold 품질 미측정
조건: 실제 제품 HTTP·DB·Worker·OpenAI 경로, 빈 작품별 인물/세계관 설정집
모델: 추출·비교 gpt-6.1-sol / 대상 연결 gpt-6-luna / medium / judge 미사용

최신 main 통합본 전체 pytest **4,266 통과·134 skip·경고 1**. 10/22 실측 당시 전체 검증은 4,227 통과였다. 수정 전에는 5분 초과 응답 회귀가 ReadTimeout으로 실패했다.
인물·세계관 설정집 각각 전 3회와 후 3회, **총 12회 모두 비교·자동 반영·공개 GET 조회까지 완료**했다. 로컬 잔액·정산 대조 12회 통과, 미해제 예약 0이다.

전후 모두 read=900이며 **기존 호출 구조와 현재 코드의 비교**다. read 연장만의 속도 개선 효과를 분리한 실험은 아니다. 기존 300초 실험의 성공·실패도 별도로 보존했다.
인물 baseline 3회 중 2회는 900초 타임아웃 후 재시도해 완료했고 현재 6회는 전송 재시도 0이다. 타임아웃 2회의 제공자 사용량은 미확인이며 0으로 계산하지 않는다. 첫 baseline에는 별도 짧은 진단 호출이 겹쳤고, 후보·프롬프트·캐시·원격 지연 차이와 작은 표본의 한계가 있다.
정식 Gold 품질은 미측정이다. 임준우/Codex가 #139 FINAL Gold와 현재값·시점·이력·부분 실패·재개·중복 반영 보호를 별도로 평가하고, 저장만의 독립 시간도 추가 측정한다. #251은 열린 상태로 유지하며 2026-10-22 실측 당시 main 병합·운영 배포는 수행하지 않았다.
