# v0036 — 검수 누락 보완을 주체 매칭·SUBJECT_RESOLUTION으로 전환 (grid v2)

2026-10-31 · 적용: 작업 브랜치 `feat/gh-349-subject-resolution-coverage` · [Java #349](https://github.com/catchhole-soma/catchhole-backend-java/issues/349)

## 무엇을 바꿨나

- 누락 보완(COVERAGE) 전에 구간마다 전체 카탈로그를 페이지로 나눠 RELATED_SELECTION을 불러, 1,200항목 작품은 구간당 24회가 들고 COVERAGE 입력이 호출 상한을 넘었다. 이제 구간 문맥에 이름·별칭이 그대로 나온 주체(서버 grid `segmentSubjects`)와 구간당 한 번의 SUBJECT_RESOLUTION(대명사·호칭·별명 지칭 해소, 호출 역할은 기존 RELATED_SELECTION)이 찾은 주체의 항목만 COVERAGE에 준다.
- 세 단계의 `subject_catalogue`를 주체당 한 행으로 줄였다. 해소할 주체가 남지 않으면 호출하지 않는다. 잘못된 mentions는 `SUBJECT_RESOLUTION_INVALID`다.
- grid v1이거나 `segmentSubjects`가 없으면 `GRID_VERSION_UNSUPPORTED`로 멈춘다. Backend와 같은 release로 배포하며, 배포 전 claim된 Job은 retry해야 한다.

## 평가

상태: 미측정(실제 모델) · 자동 테스트 완료
조건: 스크립트로 응답을 고정한 가짜 모델 · 실제 provider/DB/네트워크 호출 없음
소요: —

| 항목 | 결과 |
| --- | --- |
| 이름 매칭만 / 지칭 해소 추가 / null 지칭 | COVERAGE rules = 관련 주체 항목(카탈로그 순서), null은 추가 없음 |
| 없는 주체·중복·공백 mention | `SUBJECT_RESOLUTION_INVALID`, COVERAGE 호출 0 |
| 120항목·3주체·페이지 50 | RELATED_SELECTION 역할 호출 구간당 3 → 1 |
| SUBJECT_RESOLUTION 저장 뒤 crash 재개 | 재호출 0 |
| grid 없음·v1·형식 오류 | `GRID_VERSION_UNSUPPORTED`/`INVALID_GRID_CONTRACT`, PLANNER 뒤 정지 |
| 자동 테스트 | 전체 4,978 통과 / 141 skip / 기존 경고 1(이전 4,950), 신규 28 case |

실제 모델 재실행: 리뷰어 확인 예정(대규모 작품 실제 Terra 재실행과 Java↔Python HTTP 계약 테스트 모두).

결과: 모델 호출 수가 카탈로그 크기와 무관해지고 COVERAGE 입력이 관련 주체의 항목으로 줄었다. 지칭 해소 품질은 측정하지 않았다.
남은 문제: 정규화 없는 매칭이라 다른 단어 안의 이름·동명 주체도 포함된다(과포함). 한 주체의 항목이 매우 많으면 COVERAGE 입력이 여전히 클 수 있다. PLANNER는 더 이상 항목 참조(B)를 보지 않는다.
다음: 리뷰어가 실제 Terra 재실행·Java HTTP 계약 테스트·두 저장소 공통 fixture diff를 확인한다.
