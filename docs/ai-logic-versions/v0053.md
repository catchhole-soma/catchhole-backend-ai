# v0053 — 설정집 인물 입력의 중복 제거와 관련 대상 선택

2026-11-09 · [이슈 #147](https://github.com/catchhole-soma/catchhole-backend-ai/issues/147) · 미배포

## 무엇을 바꿨나

- 설정집에 반복되던 인물 이름·별칭·식별 근거·동일 STATUS를 한 번씩 전달한다.
- 전체 인물 목록은 유지하고 모든 행이 `이름: 내용`으로 주체를 명시한 문서만 상세를 선택한다.
- 일반 서술·이름 없는 행·전역/집단 규칙이 섞이면 전체 상세를 남긴다.
- 원문·schema·기준시점·보호값·동결 입력 검증과 64,000 한도는 유지한다.

## 평가

| 지표 | 이전 | 변경 |
| --- | ---: | ---: |
| 실패 7건의 입력 guard 통과 | 0/7 | 7/7 |
| 재구성 입력량 범위 | 64,293~65,810 | 54,063~55,347 |
| 7건 중 가장 작은 한도 여유 | 한도 초과 | 8,653 |
| 실제 모델 인물/설정 F1 | — | — |

중복 제거만으로 7/7이 한도 안에 들어왔다. 실제 7건은 일반/혼합 문맥이라
전체 인물을 유지했다. 절감률은 15.61~15.96%다.

토큰은 동일 tokenizer·schema·10%+256 보호 여유로 재구성했다. provider 청구 실측이 아니다.
모델을 호출하지 않았고 고객 데이터/분석 상태를 바꾸지 않았다.
합성 400명 입력은 이름 1명/동명이인 2명을 보존하면서 한도를 통과했다.
자동 회귀 5,748 통과/186 skip·기존 경고 1. 원입력 지문·코드 해시·사례별 표는 상세에 기록한다.

남은 일은 간접 지칭·이름 없는 규칙의 실제 모델 품질 평가와 배포다.
입력 한도 통과를 전체 분석 성공이나 품질 개선으로 해석하지 않는다.
