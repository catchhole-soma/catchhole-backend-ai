### 바뀐 동작과 경계

1. **현재 등록값의 확인 의무**: `HybridPlan.registeredCurrentRequired`를 누락·잘못된 타입이 허용되지 않는 boolean으로 추가했다. 인물의 지금/현재 속성·보유·상태와 등록 화면/수동 수정값 확인은 현재 자료를 요구한다. 원문·작중·특정 출처 회차의 서술 요청은 원문 경로로 분리한다. 단어 하나로 모든 질문을 현재 조회로 바꾸지 않는다. 서버가 해소한 대상·CURRENT 행·조회 완전성으로 의무 충족을 확인하고, 현재 대상/값을 못 찾으면 원문만으로 현재값을 확정하지 않는다. 원문도 요청한 혼합 답변은 확인한 현재값을 보존하고 미확인 부분을 남긴다. 일반 작품 개념의 기존 typed-gap 원문 보완과 명확화는 유지한다. 비슷한 이름·사실을 동일 인물로 자동 병합하지 않는다.
2. **후속 정정과 계획 복구**: 값만 말하는 정정의 실제 표현을 focus.attribute로 보존하고 관측된 FIELD 참조로 항목을 선택한다. LLM이 SQL·저장 key·ID를 만들거나 정정 내용을 사실로 채택하지 않는다. 미관측 focus/name/searchTerms의 오류는 고정 코드와 정확한 경로로 복구한다. 같은 대상의 여러 항목은 대상 하나와 실제 연속 구절을 유지해 FIELD에서 여러 경로를 선택하며, 원래 현재/이력/원문·설명 요구를 전체 값 나열로 넓히지 않는다. 과거 등록 snapshot 복원과 특정 회차 원문 사건의 완료·진행 확인을 구분한다. 검증 안내만 입력 한도를 넘으면 안내를 단계적으로 줄여 실제 적합성을 확인하고 원래 입력·schema·실패 의미·예약/정산을 보존한다.
3. **원문 후보와 출처 설명**: 벡터 추가 탐색은 현재 선택·보존된 근거 중 실제 답변 모델에 노출한 청크 ID만 제외한다. 모든 과거 노출 ID를 누적해 제외하는 정책은 아니다. 검색에서 찾았지만 선택 상한으로 버린 청크를 이미 읽은 것으로 취급하지 않는다. 단일 명시 회차는 공유 근거 상한 안에서 읽을 수 있게 했다. 원문 검색의 총 근거·토큰·라운드·임베딩 호출 상한은 늘리지 않았다. Java는 출처별 원자료·내용 수정·확정 방식·기록 생성 시각을 분리한 optional provenance를 반환한다. 일반 값/이력마다 처리정보를 반복 표시하지 않고 명시적 출처 질문에서 관련 차이만 설명한다.

구현은 `app/chatbot/`의 `hybrid.py`, `qa.py`, `qa_lookup.py`, `qa_render.py`, `qa_synthesis.py`, `qa_validation.py`, `qa_prompts.py`, `hybrid_prompts.py`와 `app/schemas/chat_hybrid.py`, `app/schemas/setting_tools.py`에 있다. 정확한 파일 목록과 diff는 제품 복원 SHA를 기준으로 확인한다. 동작 계약은 [챗봇 품질 문서](../../chat-query-quality-v1.md), Java/Python 공통 DTO·fixture는 [설정 조회 계약](../../setting-tools-v1.md)에 기록했다.

### 추가 보완의 기술 정책 — 2026-10-23

같은 미완료 PR의 구현 보완이므로 v0020을 유지한다. 변경 파일은 `app/chatbot/hybrid.py`, `hybrid_grounding.py`, `app/retrieval/evidence.py`, `app/schemas/chat_hybrid.py`이며 분석 Worker·Java DTO·공개 인용 wire 계약은 바꾸지 않는다. 이 절은 구현 정책만 기록한다. 새 제품 복원 SHA·회귀 집계·실제 재평가와 후속 판정은 하단의 같은 질문 재검증 절에 기록한다. 아래 후보 1~4와 추가 평가의 수치·SHA는 이전 실행 그대로 보존하며 이 보완의 실측 결과로 옮기지 않는다.

- **지원된 원본 문맥 보호**: 검증된 부분 답변이 실제 사용한 검색 근거는 `ChunkEvidence.fingerprint`, 직접 근거는 typed source·원문·출처 회차의 identity로 저장한다. 라운드의 E 번호를 영구 키로 사용하지 않는다. 추가 검색에서 보호 근거를 우선 배치하고 입력 한도 조정에서도 비보호 후보를 먼저 제외한다. 보호된 원본 중 하나라도 빠졌거나 보호 문맥 자체가 입력에 들어가지 않으면 새 모델 답변으로 기존 부분 답변을 대체하지 않는다. 기존 답변과 참조 snapshot을 복구한 뒤 원문·현재값·권한을 최종 재검증한다.
- **후보 우선순위와 예산**: 공통 `compose_evidence(priority_chunk_ids=...)`는 명시한 순서, 기존 retained, 나머지 순위/회차 분산의 순서로 선택한다. 같은 위치·버전·원문인 다른 ID 중복은 먼저 지정한 priority ID를 보존하고 검색 방식만 병합한다. 같은 ID의 다른 fingerprint·충돌 overlap은 계속 거절한다. priority는 개수·회차·토큰 상한을 우회하지 않는다. 직접 근거를 일부 남긴 뒤 검색 근거를 추가할 때 E 번호를 연속으로 다시 매겨 인용 충돌을 막는다.
- **검증 실패와 정상 NONE의 구분**: 정상적으로 검증한 NONE은 기존처럼 새 벡터 후보에 문맥을 양보한다. 검증 실패는 이전 자료가 무관하다는 판정이 아니다. 타입이 유효한 거절 응답에서 지원 구절의 위치를 확인할 수 있으면 실제 원본 청크를 source hint로만 보존하고, 없으면 이전 문맥 일부를 제한적으로 남긴다. 복구 우선 후보 수는 가용 검색 슬롯의 절반(최소 1개)으로 제한하고 새 후보에도 우선순위를 배분한다. 전체 후보의 실제 포함 여부는 같은 예산으로 결정한다. 미검증 문장·coverage를 검증된 사실이나 부분 답변으로 승격하지 않는다. 공급자·전송·출력 절단 복구·권한·출처 실패는 기존 오류 경계를 유지한다.
- **지원 구절의 원문 복구**: 동일하게 제공된 merged passage 안에서 정확한 quote 일치를 먼저 검사한다. 없을 때만 개행과 그 주변 공백을 한 칸으로 표시한 형태가 유일한 원래 구간에 대응하는지 확인하고, `ResolvedSupport.quote`에는 원문의 문자열을 저장한다. 일반 띄어쓰기·단어·구두점의 변경이나 의역은 복구하지 않고 다른 passage로 이동하지 않는다. 잘못된 앞 청크 anchor는 그 passage의 실제 원본 참조로 교정하며 경계를 넘는 인용은 필요한 참조 전체를 보존한다. 알려지지 않은 anchor·복수 위치·참조로 덮이지 않는 구간은 거절한다. 공개 인용은 원래 청크의 hash/offset/receipt 계약을 유지한다.
- **coverage만 구조에서 파생**: schema는 지원된 내용 없음·미확인·충돌 등 요청 없이 확인 가능한 coverage 모순을 보수적으로 정리한다. 일반 명시 요청 답변은 인용 위치·실제 행 참조·요구 전체의 answered/missing 분할을 검증한 뒤 coverage를 계산한다. coverage enum만 잘못됐다는 이유로 올바른 주장·충돌·인용을 다시 생성하지 않는다. 요청 누락·잘못된 참조·인용은 계속 실패이며 relatedFacets는 실제 답한 요구로 세지 않는다. 구형의 명시 요청 없는 PARTIAL을 무조건 COMPLETE로 바꾸지 않는다.
- **명시 요구를 모두 답한 차이 설명의 종료**: 사건·조건 검사를 거친 비항목별 requestedParts 답변이 모든 요구를 답하고 미확인 행이 없으며 필수 현재 조회도 충족하면, 등록값/원문 차이의 PARTIAL 상태를 보존한 채 추가 검색 없이 종료한다. 충돌을 삭제하거나 COMPLETE로 승격하지 않고 현재값·원문을 각각 표시한다. perItem 또는 실제 미확인 요구에는 이 종료 조건을 적용하지 않는다.

계획/답변 cache key는 `chat-hybrid-plan-v11`/`chat-hybrid-answer-v13`을 유지하며 프롬프트·제품 모델·추론 강도는 이 보완에서 변경하지 않는다. 공유 근거 8개/6,000토큰, 원문 라운드 2, 모델 호출 6, 질문 임베딩 1 및 실행의 전체 토큰·시간·도구/호출 상한은 그대로다. 정확한 인용 위치는 의미적 지지·동일 인물/속성/시점·인과·최초 발생을 인증하지 않으며 별도 semantic judge는 추가하지 않는다. 이 변경의 품질·회귀 판단은 같은 Gold와 별도 실제 실행의 의미 검토가 필요하다.

### Java 출처 계약의 제한

`sourceKind=EPISODE|SETTING_BOOK|USER_INPUT|UNKNOWN`, `contentEdited=true|false|null`, `applicationAction=AUTOMATIC_CONFIRM|USER_CONFIRM|UNKNOWN`은 독립 축이다. 자동 확정은 `reviewedAutomatically=true`, 사용자 확정은 자동 확정이 아니면서 `reviewedApplicationMode`가 있을 때만 판별한다. applicationAction은 현재 보존된 후보 확정 metadata이며 마지막 현재 슬롯 반영 행위나 불변 감사기록이 아니다. `recordedAt`은 Fact 생성 시각이고 편집/반영/작중 사건 시각이 아니다. MERGE의 복수 출처와 같은 순서·20개 상한·truncation을 유지하며 내부 source ID는 모델 입력에서 제거한다. 구 서버가 provenance를 생략하는 계약도 지원한다.

candidate/job의 명시 sourceKind로 원고·설정집을 보존하고 내용 수정 여부는 `candidate.userContentModified`의 true/false/null만 사용한다. **candidate 없는 직접 수동 Fact에는 영구 origin marker가 없어 기존 출처 미상 Fact와 확실히 구분할 수 없으므로 UNKNOWN이다.** 빈 출처만 보고 USER_INPUT을 합성하지 않는다. `rawComparisonJson.origin=USER_EDIT`는 대상/확정 선택 변경도 포함하고 purge 시 지워지므로 출처·내용 수정의 근거로 사용하지 않는다. 과거 편집/반영 시각 복원과 영구 감사로그 추가는 미구현이다.

### 초기 현재값 대조 6건과 후보 4의 보완

초기 대조는 격리한 복제 DB에서 공개 수정 API와 실제 질문 API를 사용했다. 현재값 조회, 같은 대화에서 수정 후 재조회, 사용자 정정의 재확인, 원문 전용 조회, 현재값·원문 비교, 이름 변경 후 현재 대상 부재를 각각 검사했다. 내부 판정은 **PASS 5 / PARTIAL 1**, 출처 우선순위 경계는 **6/6 유지**다. 출처 경계 유지율을 답변 완전성 6/6으로 표현하지 않는다. 원문 인용 1건의 hash와 offset 일치도 확인했다.

부분 충족 1건은 현재값을 지켰지만 원문과의 비교를 전달하지 못했다. 검색과 답변 입력에 비교할 자료가 있었으며, 답변 생성 4회가 요청 부분 누락 또는 `conflicts`와 `coverage=COMPLETE`의 모순으로 탈락했다. 최종 응답에는 검증된 현재값만 남았다. 이 실패를 원문 부재·검색 미발견 또는 인용 줄바꿈 문제로 분류하지 않는다.

후보 4는 `chat-hybrid-answer-v13`에서 확인된 CURRENT 행의 R*와 원문의 E*를 구분한 비교 주장을 허용하고 각 값의 근거를 함께 지정하게 한다. 현재값 미확인 시에는 원문만으로 그 요구를 충족했다고 표시하지 않는다. 요청 부분 누락(`REQUESTED_PARTS_INCOMPLETE`)과 coverage 모순(`ANSWER_COVERAGE_MISMATCH`)의 피드백을 나눠 실제 답한 부분·충돌을 지우지 않고 coverage를 복구한다. 충돌이 남으면 모든 요구를 답했더라도 coverage는 PARTIAL이다. 현재 행을 함께 사용한 응답의 머리말도 등록 정보와 원문을 구분하도록 변경했다.
