## 바뀐 동작

1. **검색 삽입.** `inspect()` JUDGE 루프에서 `_prepare_judgment`와 FOLLOW_UP 분기 다음, `_validate_decision` 전에 확인한다. DECIDED SUSPECTED_CONFLICT인데 질문의 own receipt에 성공한 `CHANGES_EXCEPTIONS` KEYWORD/VECTOR가 없고, 고정 purpose(`WORKER_CHANGE_SEARCH_PURPOSE`)의 검색이 own receipt나 pending에 없으면 `LookupIntent(ref=Qn-CHANGES_EXCEPTIONS, kind=CHANGES_EXCEPTIONS, operation=KEYWORD)`를 만든다. ref는 서버 발급 의무의 기존 형식(`Qn-BASELINE`, `Qn-BOOK`)을 따른다. 모델 FOLLOW_UP ref는 모델이 정한 문자열이고 Worker가 번호를 붙이지 않으며, receipt ref `L*`와 섞이지 않게 했다.
2. **query.** 중복 없는 비어 있지 않은(trim) `subject_mentions` 뒤에 `property_or_rule`을 공백으로 잇고 1000자에서 자른 뒤 다시 trim한다. 결과가 비면 넣지 않고 기존 `INVALID_DECISION_CHANGE_SEARCH_MISSING`이 남는다. 항상 KEYWORD다(frozen RAG가 없으면 VECTOR는 제안하지 않는다).
3. **revision.** `validate_intents`를 거친 뒤 FOLLOW_UP과 같은 공용 경로로 처리한다. checkpoint가 있으면 `revise({Qn}, ..., "NEW_CLUE")`, 이어서 decision/bundle 제거, revision+1, pending 추가, 재대기, runtime 저장. reason은 FOLLOW_UP과 같은 `NEW_CLUE`다. 근거: Backend `ValidationResultServiceImpl.reviseValidationChecks`는 `reason`을 200자 이하 비어 있지 않은 문자열로만 받아 check history `change_reason`에 저장하고, 새 의무 수가 늘고 이전 의무를 모두 포함하는지만 검사한다. Front `validation-report-labels.ts`는 `NEW_CLUE`만 "새 단서를 찾아 다시 확인했어요."로 표시한다.
4. **한 번만.** 표식 검색이 pending(같은 실행·runtime 재개·revise 직후 crash 복원)이거나 own receipt에 있으면 다시 넣지 않는다. 검색 실패는 기존처럼 실패 receipt를 남기고 그 조회 코드(예: `SOURCE_UNREADABLE`)로 미완료가 되며 pending에 남은 의무만 다음 시도에서 다시 실행한다. 실패한 조회는 실행 전체를 멈추므로 "검색 실패 뒤 JUDGE가 또 충돌 의심"으로 이어지는 경로는 없다.
5. **인용 보완.** `_validate_decision`에서 `required_reads` 보완 다음, 일반 completion 검사 전에 한다. SUSPECTED_CONFLICT의 `changes_exceptions.receipt_refs`에 성공 검색 receipt가 없는데 own receipt에 있으면 그 receipt ref 전체를 덧붙이고, `evidence_refs`에는 그 receipt들의 근거 중 알려진 참조를 덧붙인다(둘 다 비면 `T1`). 모델의 기존 인용은 지우지 않고 그대로 검사하므로 없는 receipt를 인용하면 `INVALID_DECISION_CHANGES_EXCEPTIONS`로 계속 거절된다. 다른 판정 결과는 바꾸지 않는다.
6. **진단.** `normalizations`에 `CHANGE_SEARCH_INSERTED`·`CHANGE_SEARCH_RECEIPT_FILLED`를 센다.

Backend `ValidationDecisionValidator`(변경 없음)의 조건(bundle receipt 전부 SUCCEEDED·모든 의무에 같은 intent의 receipt, completion 참조 실재, required_reads=전체 receipt, SUSPECTED_CONFLICT의 changes_exceptions에 CHANGES_EXCEPTIONS KEYWORD/VECTOR receipt, 판정 근거에 fact 또는 T1 밖의 근거)을 게시된 판정·bundle로 테스트에서 확인했다. 판정·사유·영향 등급·질문 병합·예산·모델·추론 강도는 바꾸지 않았다. 검색 한 번과 JUDGE 호출 한 번이 기존 예산 안에서 늘 수 있다.
