## 구현과 호환 경계

- 캐릭터 EPISODE 1차는 원문·metadata·schema·기존 이름과 활성 STATUS·검증된 시간 문맥, 별도의 미확정 이름/STATUS 힌트만 전달한다. 보류의 일반 설정·원문 인용·사유·identity evidence·전체 semantic CURRENT를 제거한다. 정적 STATUS 전망 분리 규칙은 유지한다. false는 종료 주장, null은 활성 불명으로 보존하며 현재값으로 승격하지 않는다.
- 세계관 EPISODE 1차는 원문·metadata·정적 규칙만 사용한다. SETTING_BOOK의 layout/current/pending/시점 입력과 기존 비교 보호는 유지한다. 참고 항목 출처가 BOOK이어도 이번 요청이 EPISODE이면 회차 투영을 적용한다.
- `pending_reference_projection`은 원래 frozen reference 객체의 순서 있는 부분집합만 반환한다. 현재 요청의 도메인과 관련 실제/임시 주체·이름·별칭을 사용하며, 비교의 알려진 ID 불일치는 동명보다 우선한다. 같은 인물의 다른 Fact 유형·키, 같은 세계관 주체의 다른 scope/root 경로를 남겨 부상/회복·계층 충돌을 비교할 수 있게 한다.
- Java는 원래 freeze 시점에 `selection`을 보존한다. 원래 schema로 held/failed STATUS를 분류하고, 내용 비교 성공 여부와 독립적인 검증된 주체 연결을 보존한다. 실패한 operation 대상·모호/실패한 주체 연결은 링크로 복원하지 않는다. 기존 frozen 입력을 backfill하거나 retry에서 현재 후보로 재조회하지 않는다.
- 새 AI는 모든 내부 요청에 `X-Analysis-Reference-Selection: true`를 전송한다. Java는 true에만 reference `selection`과 advisory `selectionNames`를 내보내며 누락/false에는 필드 자체를 생략한다. metadata capture와 advisory hash/contextToken은 기능 광고와 독립적이다. 새 AI/구 Java 또는 구 frozen 입력은 주어진 이름·별칭·schema에 따른 보수적 fallback을 사용한다.
- 실제 batch 후보 DTO에는 원문 인물 이름이 없으므로 기존 frozen advisory에 owner 별칭과 원 후보 표기만 `selectionNames`로 운반한다. 기존 `characterId`·`provisionalSubjectKey`를 재사용하며 새 대상 ID DTO는 없다. 선택 metadata는 모델 입력에서 제거한다. 명시적인 scope를 같은 fit/mandatory/재시도/분할/복구 경로에 전달한다.
- 전체 analysisContext/hash/equality/source/lease/journal·현재값 변경 권한은 유지한다. 보류는 advisory이며 선택 가능한 K/D/P/Q/T나 snapshot·dependency·과거 후보 자동 승인으로 바뀌지 않는다. 모델·입출력 cap·업로드 제한·실제 provider 호출 수 정책을 변경하지 않는다.

캐시 변경은 캐릭터 `setting-extraction:v12:<schemahash>:episode-lean-pending-v1`, 세계관 `world-setting-extraction:v6:episode-lean-v1`이다. BOOK 및 identity/comparison의 기존 지시문/cache suffix는 유지한다. `selectionNames`는 새 AI에서 제거하고 구 Worker에는 보내지 않아 BOOK provider 입력도 유지한다.

## 같은 실패 입력의 토큰 재구성

2026-10-24에 기존 원문·고정 입력과 이전 프롬프트 해시가 동일함을 확인하고 실제 이전·수정 추출기의 프롬프트를 provider 호출 전에 캡처했다. 캐릭터 1차 입력(응답 JSON 스키마 포함)은 **59,446 → 20,979**, 안전 여유분을 포함한 검사값은 **65,647 → 23,333**이다. `o200k_base`, `ceil(raw * 1.10) + 256` 기준으로 64,000 제한을 통과했다. 기존 인물 이름·활성 상태와 미확정 이름·STATUS 힌트는 유지된다.

[이슈의 전체 전후 표와 조건](https://github.com/catchhole-soma/catchhole-backend-java/issues/287#issuecomment-6379880239)에 기록했다. 실제 LLM 호출·운영 코드/데이터 변경은 없었고 공급자 청구 토큰이나 2차·회차 전체 합계, 의미 정확도 측정은 아니다. 당시 metadata-free 고정 입력을 그대로 사용했고 새 선택 metadata를 소급 생성하지 않았다.
