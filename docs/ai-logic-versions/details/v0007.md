## 변경과 보존 경계

- 인물·세계관 단건/묶음 비교의 네 프롬프트에서 같은 대상·항목·조건의 명백한 비양립만 충돌로 안내한다. 값 차이와 새 문서의 오류 정정 선언은 검토하며, 정상 UPDATE는 명시적 변화 과정과 전후 상태를 요구한다. 표현 차이·양립 가능한 보완·범위가 분명한 명시적 예외는 기존 의미를 보존한다.
- 인물 묶음은 순서대로 임시 적용하기 전에 내부 충돌 후보를 모두 검토하도록 안내한다. 세계관 CONFLICT의 모든 source·값을 보존한다. DTO·operation·호출 수·실패 경로와 이미 작동하는 projection 보호 분기는 바꾸지 않았다.
- 실제 추론 강도 검증에서 `OpenAIResponsesClient._supports_reasoning`이 `gpt-6.1-sol`을 제외하는 결함을 발견했다. 기존 모델 계열에 `gpt-6`만 추가해 설정한 `max`가 HTTP 요청 본문에 전달되도록 수정했다. 운영 모델·기본 추론 강도·출력 상한은 변경하지 않았다.

설정집·ordered suffix와 공급자 길이 제한용 기존 해시 규칙은 유지했다. 과거 요청 golden과 GH180 override는 보존하고 별도 PR1 fixture에 승인된 prompt SHA·전체 body SHA·cache key 차이만 기록했다. 모델·추론·입력·schema·store·상한의 parity는 계속 검사한다.

## 과거 medium 관찰의 정정

원본 `short-policy-before.json`(5/10)과 `short-policy-after.json`(10/10)의 metadata는 설정 의도인 max였지만, 실제 raw response 20회 모두 `reasoning.effort=medium`이다. 위 client 결함 때문에 outbound reasoning이 누락됐다. 원본은 바이트 그대로 보존하며 `short-policy-reasoning-correction.json`에 두 파일의 SHA-256·관찰한 effort·정정 사유를 남겼다. 이 결과를 요구한 max 검증이나 max 개선 근거로 사용하지 않는다. 최초 sandbox network 실패도 별도 원본으로 보존한다.

## 남은 검증과 계약 한계

작업 4에서 새로 고정할 긴 문서와 세 문서 순서의 추출·비교·현재값·검토 연결 검증이 필요하다. 짧은 합성 단건/후보 1개 묶음의 결과를 다중 후보 의미 판단이나 전체 파이프라인 품질로 일반화하지 않는다. 서로 다른 비교 조각·이미 완료한 단계에 흩어진 내부 충돌의 소급 철회 기능을 추가하지 않았다.

인물 기존 REVIEW_REQUIRED는 target ref·proposal·removal을 허용하지 않아 일반 확인 필요와 비교한 확정값의 내용 충돌을 같은 source 연결로 구별할 수 없다. 이 한계는 작업 2의 최소 기존 필드 재사용 계약 검증 대상으로 전달했고, 이번 고정 대조 실행 중 schema를 변경하지 않았다. 세계관 GENERAL_UNCERTAINTY의 단일 source 제한은 유지하며 다중 source CONFLICT는 operation과 무관하게 서버 자동 반영 보류가 필요하다.

미완료 C02 때문에 현재 Java ORDERED claim이 요구하는 `supportsFrozenComparisonEvidence=true`를 AI가 아직 소비·전송하지 못한다. 실제 worker 전체 연결을 완료했다고 주장하지 않는다. 설치 없이 실제 provider 결과를 현재 Java 소스의 격리 publish/context/complete 검사에 넘기는 경로는 별도 작업이다. PR·배포·복원 SHA 보완과 긴 문서 재검증은 담당 root의 다음 승인 범위에서 수행한다.
