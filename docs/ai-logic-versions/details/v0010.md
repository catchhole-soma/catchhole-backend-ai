## 계약과 실행 조건

Spring의 선택된 conversation만 입력한다. 6턴/답변 1,000/전체 8,000 UTF-16 단위와 7개 질문 스캔은 초기 운영 제한이다. Python은 추가로 전체 입력 토큰 상한을 검사한다. 과거 문자열은 지칭 해석용으로만 사용하고 현재 질문을 우선하며, 이전 sourceRange를 묵시적으로 계승하지 않는다. R*/E*는 이번 조회 결과만 허용한다. 이름/검색어는 현재 질문 또는 남아 있는 문맥에 관측된 문자열인지 검사한다.

프롬프트/cache 키: `chat-qa-plan-v2`, `chat-qa-select-v2`, `chat-hybrid-plan-v2`, `chat-hybrid-answer-v2`. QA 두 단계와 기존 hybrid 예산을 유지하며 문맥 요약 호출을 추가하지 않는다. vector query에는 검증된 대상 이름/검색어와 현재 질문을 함께 넣는다. 없는 대화 필드는 이전 schemaVersion 1 wire와 호환된다.

공통 계약과 재현 순서는 [대화 문서](../../chat-sessions-v1.md)를 따른다. 문맥/원문/개인 대화를 로그나 공개 fixture에 복사하지 않는다. 이번 fixture는 합성 화염술/아리아 예제다.
