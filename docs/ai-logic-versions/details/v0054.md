## 변경과 선택 범위

BOOK 캐릭터 1차 추출을 두 호출로 나눈다. 1단계 `book_character_selection`은 청크 원문과 가벼운 catalog(ref·이름·별칭·확정 여부, 직책/소속/가족관계/호칭 계열 PROFILE 힌트 최대 5개·값 30자)와 미해결 참고 이름을 받아 이번 청크가 관련된 인물 ref를 고른다. 응답은 strict JSON이며 `selected`(ref·원문 표현·근거 종류), `ambiguous`(표현과 후보 ref 전부), `unmatched_mentions`(catalog에 없는 표현)로 구성되고, ref 필드는 입력 ref의 enum이라 없는 ref를 낼 수 없다. 오류리포트 planner가 `subject_catalogue`에서 `subject_refs`를 고르고 그 ref의 저장값만 읽는 구조와 같다.

결정적 보강 두 가지를 둔다. 모든 비어 있지 않은 행이 `이름: level=12` 같은 수치 셀이면 v0053의 결정적 선택을 그대로 쓰고 모델을 호출하지 않는다. 그 외에는 모델 선택 결과에 원문에 이름·별칭이 통째로(2자 이상) 들어 있는 인물을 합집합으로 더한다. 한 글자 부분 일치는 쓰지 않는다.

2단계 추출의 `book_character_context.characters`에는 선택된 ref와 모호 후보 전부의 CURRENT 상세만 들어간다. catalog는 전원 유지하고 `unmatched_mentions`를 함께 전달해 신규 인물 발견이나 모호 지칭의 단서로만 쓰게 한다. 일반 서술이거나 선택에 실패했다는 이유로 전체 상세를 다시 넣는 경로는 없다. 선택이 3회 재시도 후에도 실패하면 `LlmExtractionError`로 그 청크가 실패하며 기존 `LLM_RESPONSE_PARSE_ERROR`로 분류된다. 새 failure code나 Java 변경은 없다.

선택 호출은 추출과 같은 `MeteredTextGenerationClient`(purpose `SETTING_EXTRACTION`)를 거쳐 같은 job 장부에 정산되고, 두 호출 모두 `BoundedOrderedClient` guard를 적용한다. guard 한도는 고정 64,000(2026-09-13 도입, provider 한도가 아닌 앱 안전장치)에서 설정값 `LLM_SETTING_EXTRACTION_MAX_INPUT_TOKENS`로 바꾸고 기본을 128,000으로 올렸다. 인물 사실 비교가 이미 256,000을 쓰므로 provider는 그 이상을 받는다. 토큰 예약은 실제 프롬프트 크기 + 출력 상한으로 계산되므로 한도 인상 자체는 예약량을 바꾸지 않고, 더 큰 작품이 실패 대신 더 큰 요청으로 진행된다. 회차 ordered 경로도 같은 extractor의 guard를 쓰지만 현재 약 21,000토큰이라 영향이 없다. Worker Compose·env 예제에 같은 값을 넣었다. 선택 모델은 `LLM_BOOK_CHARACTER_SELECTION_MODEL`(기본은 인물 추출 모델), 출력 상한은 `LLM_BOOK_CHARACTER_SELECTION_MAX_OUTPUT_TOKENS` 4,000/절단 재시도 8,000이다. 선택 cache key `book-character-selection:v1`, 추출 suffix `:book-character-context-v4`. v0053의 중복 제거, 현재 사실·전망 분리, 수식어 보존 지시, frozen carrier/hash/lease, 후속 해소/비교, EPISODE/world 경로는 유지한다.

## 왜 설정집만 많이 썼나

같은 작품 133명 기준 인물 관련 입력은 회차 추출이 약 2,100토큰(이름 목록 785 + 활성 STATUS 33개 1,305)인 반면 설정집 추출은 v0053 기준 약 32,700토큰(catalog 3,100 + 상세 29,600, 1인당 평균 223)이다. v0020(AI #94)이 회차 입력만 줄이고 BOOK은 유지했기 때문이며, 설정집은 기존 값과 바로 대조하도록 전 인물의 CURRENT를 통째로 넣고 있었다. 원문이 50토큰짜리 세계 규칙 한 줄이어도 전 인물의 직책·가족·외모 현재값이 따라갔다. 이번 변경은 그 대조 방식은 유지하면서 대상을 관련 인물로 좁힌다.

## 관련 인물 선택의 정확도

실제 명단 4건에서 gold 주체 중 catalog에 있던 인물은 R3 12명, R4 12명, R5 12명, R6 61명이며 **선택 누락 0명**이다. gold 밖 선택은 R3 2명, R4 1명, R5 1명, R6 4명으로 그중 일부는 원문에 이름이 글자 그대로 없고(직속·소속 표현으로 연결된 것으로 보이나 단회라 원인을 단정하지 않음) 상세 1인분(평균 223토큰)씩 비용이 들 뿐 출력에 잘못된 사실을 만들지는 않았다. gold 주체 중 catalog에 없던 신규 인물은 R3 21명, R4 20명, R5 20명, R6 60명이고 선택 응답의 `unmatched_mentions`가 각각 19·19·19·56명을 그대로 적었다. 추출의 발견 후보(CHARACTER_DISCOVERY)는 기준과 같거나(R3 21/21) 1건 적은데(R4·R5·R6 21→20, 61→60), 줄어든 1건은 기준이 이미 등록된 인물을 다시 발견 후보로 낸 중복이라 수정본이 맞다.

세계 규칙만 있는 R1·R2·R7은 선택 0명, 추출 SETTING 0·발견 0으로 기준과 같고 인물 사실을 만들어내지 않았다.

합성 간접 지칭 8종(S13~S20, 각 2회)은 기대 선택 누락 0·과잉 0이다. 직책만 있는 S13(재판장)·S19(새벽 기사단 단장, 두 줄 제목), 가족관계+대명사 S14(아린 벨의 어머니·그녀), 배우자 S20(보라 남의 남편), 별칭 서술 S15(청람이라 불리는 소녀), 동명 S16(아린 → 두 후보 모두 ambiguous), 신규 인물 S17(하린 → unmatched 2/2), 전원 규칙+이름 S18(보라 남만)이 모두 기대대로였다. 수치 행 S10~S12는 선택 호출 없이 1~2명을 결정적으로 골랐다.

## R5 기관명 변동 확인(#149 관련, 각 3회)

R5를 기준·수정본 각 3회 실행했다(1회차는 위 표의 실행). 선택은 3회 모두 13/133으로 같았고 추출 입력 21,705·선택 입력 9,033으로 결정적이다.
