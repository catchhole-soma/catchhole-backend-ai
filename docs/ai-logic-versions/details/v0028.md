## 변경과 복원 경계

GH306/309의 inspect/check_typos callable을 유지하며 전용 EpisodeValidationWorker/client/checkpoint/execution과 명시 CLI를 추가했다.
Java 실제 ValidationJob/lease와 CommonResponse.data를 사용하고 결과/질문/입력/원장은 Java가 소유한다. Python validation DB 쓰기는 없다.
PLANNER/선정 전체 page/COVERAGE/책 읽기/책별 coverage를 검증 직후 저장하고 병합 계획은 첫 JUDGE 전에 저장한다.
정상 NO_CONFLICT와 분류/정확 span이 있는 typo segment도 즉시 저장하며 성공 단위를 추가 호출 없이 복원한다.
FOLLOW_UP은 모든 영향 revision을 원자 변경하고 그 직후 crash에도 현재 서버 의무로 복원한다. 다른 정상 완료는 유지한다.
한 책 검토를 저장한 뒤 다음 책을 읽으며 성공 BOOK_SOURCE와 서버 segments로 미완료 rule만 범위 읽기한다.
checkpoint는 필요한 질문 근거/queue/전역 receipts와 질문별 refs만 보존하고 전체 책이나 stage/decision blob을 중복 저장하지 않는다.

실행은 기본 OFF다. 모든 역할/분기 예산은 trusted claim의 명시 설정을 요구하며 운영 기본 상한을 만들지 않는다.
두 task는 독립이고 역할 cap/token/CAS 실패와 공유 lease/input/source 손실을 구분한다. 공유 무효화는 새 예약/게시를 막되 실제 사용량 정산을 보존한다.
count/generate는 같은 frozen options/schema이며 검수용 raw one-shot과 단층 metered(max_retries=0) 경계를 유지한다.
모델 역할은 trusted call_role로 고르고 일반 추출/챗봇 모델·retry·분석 runner는 바꾸지 않는다.

실제 frozen RAG는 명시 SELECT 전용 factory에 연결한다. current report/contentRevision/manifest/source/retained purge/lease를 ranking/LIMIT 이전에 검증한다.
optional QUERY_EMBEDDING은 기존 text-embedding-3-small/index version/1536 차원과 별도 cap을 검증한다. 새 index/백필은 없다.
V95 validation_call_input이 실제 query UTF-8 SHA-256(정규화/trim 없음), input/manifest/index identity를 원 호출에 고정한다.
현재 VECTOR 의무·SUCCEEDED/완전 READY receipt·원래 SETTLED SUCCESS usage의 고정 index identity를 대조한 경우에만 JUDGE-only 재개에서 embedding을 재사용한다.
현재 source/input은 다시 검증하되 live index 재구축/미준비 자체는 이미 성공한 JUDGE-only 재개를 막지 않는다.
그 외 새 embedding이 필요하고 cap이 소진됐으면 retry를 queue 전에 거절한다. UNKNOWN/실패 비용을 0으로 초기화하지 않는다.

서버 modelSettings/modelSourceCatalogue/modelClues와 projection/clue version을 소비하며 Job 없는 callable만 로컬 fallback을 유지한다.
authorCorrectionProofs는 실제 편집 transport이며 canonical author_correction=null이다. 자유 문자열 시점/조건의 권위로 승격하지 않고 DB_RAW_DISAGREEMENT는 NEEDS_CONTEXT다.
원문 교체/파기는 이전 사본과 완료를 복구하지 않는다. 추출 Job/후보/자동 확정/철회는 모든 경로에서 0이다.
작가 판단/검토 종료/추출 release #312, UI/다음 회차 등록 제한 #314는 별도다.
