## 변경과 경계

1. `RetrievalSearchRepository.keyword(cover_terms=True)`는 권한/현재 원문 필터 뒤 키워드별 최상위 대표 후보를 우선하고 같은 회차의 사건 점수를 동점 해소에 사용한다. 기본 false 소비자는 기존 순위를 유지한다. materialized scored 결과를 공유하며 별도 임베딩·백필·추출 변경은 없다. 키워드 일치 개수 기반 한계와 전체 허용 코퍼스 검사 비용은 남으며 전문 인덱스 최적화로 부르지 않는다.
2. `source_search.py`는 두 독립 후보·작은 인접 장면과 기존 확인 근거의 이어지는 대목을 우선한다. 미확인 요구 중심 벡터 쿼리로 이미 답한 질문 전체를 반복하는 편향을 줄인다. 후보가 반환된 것, 실제 모델 입력에 포함된 것, 의미적으로 답한 것은 별개다.
3. 내부 계획의 optional `requestedParts.sourceEpisodeNo`는 이번 질문에 직접 명시된 회차만 허용한다. 미확인 요구가 모두 같은 회차를 가리킬 때만 서버 범위 안으로 좁힌다. 과거 대화·추정 시점은 범위를 바꿀 수 없다. 해당 단일 회차는 남은 공통 근거 예산을 사용하고 넓은 범위의 기본 회차별3개는 유지한다.
4. 순수 원문 답변은 등록 행/항목 설명을 뺀 전용 프롬프트를 사용한다. 현재값 질문은 기존 RDB 경로다. eventMatch/eventStatus 조건을 provider schema에도 반영한다. 인용·사건 구분·수치·계획/미실행 검증 지침과 현재값/출처 최종 재검증은 유지한다.
5. 마지막 검색에서 COMPLETE 초안의 일부 인용이 실패하면 남은 기존 시도/시간 예산 안에서 복구한다. 실패하면 검증된 부분만 보존한다. provider/권한 오류를 정상 성공으로 바꾸지 않는다. 같은 미확인 요구를 가진 부분 답변의 병합·새 핵심 정보 보존은 여전히 개선 여지가 있다.
6. 실제 조건 조회 실패에서 collection 조건을 바꿔 쓴 뒤 재시도에 subject를 추가하는 문제를 확인했다. 조건/속성·collection 충돌별 고정 피드백과 계획 지침을 보완했다. 거절된 값/ID를 재시도 지침에 복사하지 않는다. HELP는 구체적 예시 질문을 포함한다.
