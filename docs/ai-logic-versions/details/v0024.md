AI `app/services/episode_chunk_service.py`의 새 분석 청크 저장만 바꾼다. 기존에는 동일 원문도
청크를 삭제하고 새 UUID로 저장해 확정값·이력·대표 시점이 예전 청크를 참조할 수 있었다.
기존 청크 전체와 새 분할 결과의 회차 ID·순서·본문·시작/끝 offset·문단 시작/끝이 같으면
기존 ID와 임베딩을 보존하고 실행 metadata만 갱신한다. 하나라도 다르면 기존 교체를 수행한다.
분할 알고리즘·청크 크기·프롬프트·모델·추론 강도·출력 상한·재시도·과금 정책은 바꾸지 않는다.
ordered 직접 저장의 lease·실행·원문 검증과 rollback은 유지한다.

Java 동반 변경은 이미 사라진 회차 청크 참조를 원 Job에 고정한 원문 manifest·hash·인용·offset으로
재검증해 읽고, 원문 파기 후 유효한 새 관측이 대표 시점을 갱신할 수 있게 한다.
성공한 원 Job 또는 이미 검토한 후보에만 없는 UUID 복구를 적용하며, 다른 회차에 실제 존재하는
UUID·미완료 신규 추출·설정집 청크에는 적용하지 않는다. Java는 배포 전후 모두 기존 schema를 읽는다.
기존 운영 데이터 일괄 복구나 유료 재분석을 자동 실행하지 않는다. 코드를 되돌리면 이후 새 분석이
다시 청크 ID를 교체할 수 있으며, 코드 복원만으로 이미 저장된 관측이나 파기된 인용이 복원되지는 않는다.
