요청받은 표와 다르게 둔 것과 근거(코드 확인):

- `INDEX_PARTIAL`·`NO_SUPPORTED_SOURCES`는 숨긴다. `search_repository.readiness()`는 범위의 비보관 회차가 0개일 때만 `NO_SUPPORTED_SOURCES`를 내고, hybrid는 준비 상태에 코드가 하나라도 있으면 `INDEX_PARTIAL`을 덧붙인다. 그대로 연결하면 회차가 없는 범위에 "준비가 끝나지 않은 회차가 있다"가 붙는다. `INDEX_PARTIAL`은 항상 세부 코드와 함께 뜨므로 세부 코드 연결만으로 나머지 경우의 화면은 같다.
- `PARTIAL_ANSWER`·`SETTING_SOURCE_CONFLICT`는 ANSWER에만 붙인다. hybrid는 성공 답변에서 `PARTIAL_ANSWER`를 결과 코드에서 빼고 본문으로 설명한다. 이 코드가 결과에 남는 것은 부분 답변을 내보내려다 원문 변경·길이 한도·근거 검증 실패로 보류한 경우뿐이다.

합성 테스트 전체에서 최종 결과에 붙은 코드를 집계하면(`tests/test_chat_answer_notices.py` 제외, 테스트 1,150개의 결과 573건) `PARTIAL_ANSWER`는 INSUFFICIENT_EVIDENCE에서만 5회, `SETTING_SOURCE_CONFLICT`는 ANSWER에서만 8회, `SETTING_BOOK_UNSUPPORTED`는 0회였고, 문구가 하나라도 붙은 결과는 18건이었다. 합성 사례의 분포이며 실제 사용 분포가 아니다.
