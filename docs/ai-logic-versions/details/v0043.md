## 배경과 확인 범위

운영에서 관계 비교의 `RELATIONSHIP_ENDPOINTS_UNGROUNDED`가 반복됐다.
저장된 고정 입력과 배포 코드의 planner를 읽기 전용으로 검사한 결과, 64k 이내에는
관계 없는 슬롯·미해소 과거 관측도 한 요청에 섞이고, 큰 입력도 투영한 여러 쌍을
하나의 평평한 결정 배열로 생성했다. 실제 전송 분할에서 새/과거 관측의 인물 후보가
모두 singleton인 사례도 있어 단순히 미해소 이름만 제거해서 해결할 수는 없다.
실패한 모델 응답은 저장되지 않아 특정 관계 선택이나 장면 혼동을 실제 원인으로
단정하지 않는다. 이름·원문·사용자 식별값·개별 입력은 이 기록에 복사하지 않았다.

## 변경한 생성과 검증 경계

- `relationship_grouped_comparator.py`는 모든 opt-in 비교를 유일한 unordered 쌍으로
  나눈다. 같은 쌍의 전체 새 O, 유일하게 해소된 H, 모든 기존 R 슬롯만 투영하고
  필요한 두 인물 정보·원래 ref·근거·순서를 유지한다. 같은 장면의 다른 쌍을
  하나의 decision으로 합칠 수 없으며 unresolved H는 저장 상태를 유지한다.
- endpoint를 유일하게 고를 수 없는 새 O는 provider 없이 내부 HOLD한다.
  성공으로 꾸민 모델 실패와 구분하며 사용자 검토를 필수로 요구하지 않는다.
- 각 provider 요청은 여러 독립 `groups`를 담는다. 출력은 groupRef와 결정 배열이며
  endpoint 출력 필드를 제거했다. ADD는 LEFT_TO_RIGHT/RIGHT_TO_LEFT/MUTUAL/UNDIRECTED를
  선택하고 Worker가 두 endpoint를 복원한다. MERGE/UPDATE/END는 소유 R를 고르며
  기존 endpoint/axis/kind/direction을 복원하고 MERGE는 기존 label/summary도 보존한다.
  모델이 다른 R·O/H를 고르거나 불변 필드를 다시 생성하면 기존 검증으로 거절한다.
- 이름·별칭 추측, 다른 group의 장면 합치기, 단순 호의를 친분으로 확대하기를 prompt에
  금지한다. 행동 근거는 INTERACTION의 적합한 kind로 구분하고 일방적 태도를 보존한다.
  semantic correctness를 코드가 보장하지는 않는다.
- 각 그룹을 기존 canonical validator로 독립 검증한다. 알려진 group의 누락·중복·schema
  오류는 그 그룹만, 파싱할 수 없는 envelope/미상 group은 그 요청의 그룹을 거절한다.
  정상 그룹은 메모리에 보존하고 나쁜 그룹만 고정 reasonCode를 붙여 한 번 다시 생성한다.
  오류 응답 본문·예외 문자열·원문을 피드백/진단에 복사하지 않는다.
- 재시도 후 실패한 그룹은 해당 쌍의 전체 새 O와 허용 reasonCode로 반환한다.
  성공 결정과 실패 O는 서로 겹치지 않고 전체 입력을 덮으며 Spring이 한 트랜잭션으로
  적용한다. 성공 O의 여러 슬롯에 END+ADD가 필요한 경우는 기존처럼 허용한다.
  결합 후512결정 상한을 넘는 그룹은 부분 절단하지 않고 전체 그룹 실패로 보존한다.

추출 실패, 잘못된 고정 context, 미측정 의미 오류도 남아 있어 모든 분석 실패를
없애는 변경이 아니다. 이전 partial capability가 없는 계약은 v0041 비교 경로를 유지한다.
