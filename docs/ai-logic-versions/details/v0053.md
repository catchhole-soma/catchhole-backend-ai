## 변경과 안전한 선택 범위

BOOK ordered+semantic 입력을 `book_character_context` 하나로 묶는다. 전체 이름·별칭·확정 여부 catalog는 유지하고 상세를 K ref로 연결한다. 같은 식별 인용을 한 번 보내며 동일 STATUS key/표시값만 출처·보호·시점과 결합한다. 다른 값·명시 종료는 보존한다.

상세 선택은 모든 비어 있지 않은 행이 `이름: level=12, age=25`처럼 명시적인 수치 셀일 때만 한다. 지원 key는 age/level/나이/레벨/stats.*다. 이름·별칭·짧은 이름이 여러 인물에 대응하면 모두 남긴다. 일반 서술, 이름 뒤 문장, 자유 속성값, 알 수 없는 헤더, 집단 규칙은 전체 상세를 유지한다. 관계 단어 목록만으로 문장 주체를 추측하지 않는다.

실모델 평가에서 발견한 회귀를 보완했다. 입력의 중복 제거가 원문에 다시 명시된 현재 사실의 생략으로 이어지지 않게 하고, 현재 사실과 미래 전망을 분리한다. 표의 상위 제목이 명시하는 소속·직속 관계·수식어를 인용뿐 아니라 값에도 보존하도록 지시한다. 원문 밖 관계를 만들지는 않는다. 캐시 suffix는 `:book-character-context-v3`다.

원래 frozen carrier/hash/lease, 원문·schema·기준시점·보호값, 후속 인물 해소/비교, EPISODE/world, 모델과 출력/입력 상한은 유지한다. 이번 품질 변화는 문맥 재구성과 BOOK 보존 지시의 합친 결과이며, 중복 제거 하나의 인과 효과로 설명하지 않는다.

선행 v0020 / [AI #94](https://github.com/catchhole-soma/catchhole-backend-ai/pull/94) / [Java #287](https://github.com/catchhole-soma/catchhole-backend-java/issues/287)은 EPISODE만 줄이고 BOOK을 제외했다. v0045 / [AI #127](https://github.com/catchhole-soma/catchhole-backend-ai/pull/127) / [Java #349](https://github.com/catchhole-soma/catchhole-backend-java/issues/349)은 오류리포트 질문의 subject_refs로 CURRENT를 선택한다. 이번 수치 행 선택과 같은 알고리즘은 아니다.

## 실제 모델 비교 조건

2026-11-09, 요청 및 provider 반환 모델 `gpt-6.1-terra`, reasoning medium, 초기 출력 상한 32,000/절단 재시도 64,000, 형식 검증 시도 3회. 절단 재시도로 provider 호출이 추가될 수 있으므로 최대 호출 3회라고 하지 않는다. 실행 프로세스별 동시성 2, seed 미고정, store=false. 최종 비교는 실제 7건 전후 각 1회와 합성 12개 전후 각 3회, 총 86개 추출이다.

운영 실패에는 응답이 없으므로 평가 전용 subclass에서 **기존 버전의 애플리케이션 guard만 우회**해 대조군을 생성했다. 기존 요청 텍스트/모델/파서·근거 검증은 그대로며 수정본은 실제 guard를 통과했다. 운영 DB, 분석 상태, 사용자 토큰 장부는 변경하지 않았다. 이는 기존 운영 분석 성공률 7/7을 뜻하지 않는다.

독립 검토자가 모델 출력 열람 전에 원문에서 gold를 고정했다. 이후 전후 라벨을 섞은 결과를 같은 gold로 감사하고 각 gold ID와 원래 candidate index의 연결을 비공개로 남겼다. 별도 Sol API judge/정규 FIXED 다단계 평가가 아니며 아래 지표를 그 평가의 precision/recall/F1로 바꾸지 않는다. 두 값 필드(attribute_value와 value_json)를 모두 동일하게 읽되, 인용문에만 있는 사실은 출력값 보존으로 세지 않는다.
