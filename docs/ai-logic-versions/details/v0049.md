## 변경

- `JudgeOpenAnswer`/`JudgeFinalAnswer`에 strict boolean `db_evidence_sufficient`를 추가한다. Worker는 true와 검증된 B 인용 둘 다 있어야 충분하다고 본다. 충분성 자체의 의미 판단은 모델 책임이며 B 인용의 존재만으로 의미가 정확하다고 보장하지 않는다.
- 부족하고 성공 VECTOR receipt가 없으면 질문 의도+대상 문장 검색 후 FINAL로 재판정한다. 문맥만 읽은 FOLLOW_UP과 인용 없는 충돌 해제도 이 검사를 거친다. 실패/준비 부족은 INCOMPLETE, 빈 범위는 기존 NOT_APPLICABLE, 호출 상한 3회와 변화 검색 정책은 유지한다.
- PLANNER는 신분·관계·수치 등 사실 전제와 희망/추측 내용을 나눈다. JUDGE는 근거 없는 착각·거짓말·겸직·변화를 만들지 않으며, 다른 축의 역할·명시된 겸직·변화와 단순 희망은 정상으로 둔다. '대부분'을 절대 규칙으로 강화하지 않는다.
- schema/cache 이름: `validation_planner_v4`, `validation_judge_open_v4`, `validation_judge_final_v4`. 운영 모델/예산/재시도 기본값은 바꾸지 않는다.
