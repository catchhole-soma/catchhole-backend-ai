## 처리 경계
- raw provider는 계속 한 번만 호출한다. `ObservedProvider`가 provider HTTP 오류만 상태 코드·허용된 오류 코드·검증된 요청 ID로 변환한다. 본문·키·URL·원문을 기록하지 않는다.
- `invoke_with_retry`는 metering 바깥에서 최초 포함 최대 3번 시도한다. 생성 시도마다 새 예약/요청 ID를 쓰며 실패한 사용량은 UNKNOWN으로 보존한다. 단순 HTTP 실패를 0토큰으로 정산하지 않는다.
- 429(일반 속도 제한), 500/502/503/504, 네트워크·읽기 시간 초과만 대상이다. 인증/입력/컨텍스트/결제·quota 오류, 출력 schema 오류, Spring 원장 오류는 재시도하지 않는다.
- Retry-After를 최소 대기시간으로 존중하고 jitter를 더한다. 대기 상한 60초를 넘는 서버 지시는 앞당겨 재시도하지 않고 미완료로 남긴다. 첫 실패 이후 복구 상한 180초와 기존 질문/분기 deadline 중 먼저 도달한 것을 적용한다.
- 대기 중에는 공유 provider 슬롯을 잡지 않는다. 기존 모델 호출 예산을 매 시도 차감하고 재시도 직전 gate를 확인한다. lease/source 무효화, 취소, 예약 거절을 우회하지 않는다.
- TYPO의 닫힌 client 경계는 알려진 단일 observer + raw provider 조합만 추가로 허용한다. 임의 중첩 wrapper나 숨겨진 transport 재시도는 허용하지 않는다.
- 참조 정책: https://developers.openai.com/api/docs/guides/rate-limits (2026-11-11 확인).
