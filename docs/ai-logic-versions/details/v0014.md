## 최초 설정 자동화 보완

수동으로 요구하던 env·비밀값·읽기 전용 계정·사설 연결·첫 공개를 동일 PR에서 배포 코드로 옮겼다.
`bootstrap-chat-aws.py`는 최신 publish SHA와 Java 배포 잠금 지원을 확인하고, 기존 워커 설정으로 API를 찾는다.
실제 VPC/SG 연결을 대조한 뒤 API SG에서 Worker TCP 8082로만 접근을 허용한다.
`bootstrap-chat-runtime.py`는 Compose로 기존 값을 해석하고, 비밀값 intent를 먼저 영속화한 뒤 env를 보완한다.
Compose 출력의 dollar escaping을 환경 값에만 복원해 실제 HTTP 헤더와 Docker env-file에 전달한다.
`.api-deploy.lock`은 Java 배포와 API 설정·첫 공개를 직렬화한다. API의 현재 이미지 값은 그대로 사용한다.

`app.retrieval.bootstrap`은 기존 관리자 연결로 필요한 SELECT만 가진 별도 검색 계정을 준비한다.
기존 검색 DSN은 검사·재사용하고, 동명 계정 충돌·상속 권한·쓰기·객체 소유권·위험한 실행 권한을 거절한다.
역할 생성 전 비밀번호 intent를 0600으로 저장하고, 인증 및 실제 검색 SQL 준비 검사 후 결과를 저장한다.
기존 공유 ACL, IAM 정책, RDS/EC2 용량을 자동 확대하지 않는다. 실제 연결 한도·예약분·관리 여유와 메모리를 검사한다.

값이 없는 최초 설정은 활성 작품의 현재 회차, `retrieval-v1-rollout`, 서비스 부담 누적 보수적 입력 상한 50,000,000이다.
5천만은 400회차 비용 측정값이나 실제 토큰 소비량이 아니며 이후 신규·수정 원문도 같은 예산을 사용한다.
기존 custom 모델·범위·allowlist·예산·DSN은 유지하고 초기화 이후 수동 OFF도 보존한다.
챗봇의 기존 기본 `gpt-6-luna`·medium과 800/100 검색 청크, 임베딩 모델/차원은 유지한다.
서로 명시한 embedding version이 다르면 preflight가 차단하며 기존 검색 공간을 임의로 바꾸지 않는다.

첫 공개는 완료 순회의 READY 또는 정상 EMPTY, 미전송 보고 0, 불확실 호출 없음,
실제 실행 중인 챗봇 검색/운영 readiness와 API 인증을 확인한 뒤 진행한다.
30분 내 완료되지 않으면 timer·진행 상태를 보존하고 공개를 보류하며 최신 배포 재실행으로 이어간다.
공개 ON을 파일에 저장한 뒤 API 재시작이 실패한 경우 자동 OFF 롤백은 하지 않는다.
이미 준비를 통과한 설정이 다음 API 재시작에 반영될 수 있으며 실제 env/실행 상태를 대조한다.
