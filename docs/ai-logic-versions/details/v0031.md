## 변경 이유와 실행 경계

baseline(동일 main 코드) 실행 기록을 단계별로 읽어 확인한 결정적 결함 2개와 가장 큰 비통과 묶음 1개를 고쳤다.

1. **입력 토큰 추정**: tiktoken 0.13.0이 모르는 `gpt-6-luna` 별칭이 UTF-8 byte 상한(한글 3바이트/자)으로 떨어져 실제의 3~4배로 추정됐다. 60발화 중 44발화에서 `INPUT_LIMIT`가 발생해 선택한 근거 8개 중 1~2개가 모델 입력에서 빠졌다. `gpt-6`·`gpt-5.6` 계열은 `o200k_base`로 센다. 수정 후 60발화에서 `INPUT_LIMIT` 0회.
2. **도구 예약**: 원문 검색이 필요한 계획의 비집중 인물별 등록 이력 조회가 도구 예산 16 중 13을 써서 원문 검색(4 필요)이 시작되지 않던 경로(baseline T2-11). `3*max_rounds+2`(+정렬 1)를 남기고 남은 여유를 인물 수로 나눈다.
3. **장면 확장**: 회차는 맞췄지만 세부가 빠진 PARTIAL(baseline 비통과 24건 중 14건)에서 2라운드가 전역 벡터만 반복했다. PARTIAL이면 검증된 초안이 인용한 청크의 반경 `focus_radius=2` 이웃을 먼저 읽고 그 라운드 회차 몫을 +2 한다.
4. **회차 순서 검색**(E축 최초/최후): 계획 `ordering`으로 `keyword_ordered`를 1라운드에 한 번 더 호출한다. 실제 실행에서 anchor 4단어 AND가 0건(4/5)·일반 단어 1개가 초반 언급 12개(X12)를 돌려줘 두 번 고쳤다 — 인물명 필수·대상 단어 절반 일치(`8d1ca57`), 우선 배치 상한 `ordered_top_k=4`(`54077cc`), 2라운드 의미 검색 3배 확장 후 가장 이른 후보 우선(`35e9dab`). 답변 입력 `searchOrdering`과 안내 `ORDERED_SEARCH_*`를 추가했다.
5. **도움말**: HELP 고정 답변에 일반 예시 두 개를 넣었다(B2-10).

모델(gpt-6-luna/medium)·검색 라운드 2·근거 8개/6,000토큰·도구 16·모델 호출 6·입력 32,000 상한·Spring wire 계약은 바꾸지 않았다.
