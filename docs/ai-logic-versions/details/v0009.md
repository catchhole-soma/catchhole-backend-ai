## 변경 경계

`gpt-6.1-sol` 캐릭터 비교는 검증되지 않은 로컬 tokenizer mapping이나 UTF-8 byte 상한으로 입력을 판정하지 않는다. OpenAI `/v1/responses/input_tokens`에 생성과 동일한 model, system/user 역할·전체 문자열, reasoning, structured output schema를 전송한다. 256,000은 포함하고 256,001부터 분할한다. 출력 상한 128,000과 정적 prompt/cache namespace는 유지한다.

전체 남은 그룹을 먼저 세고, 초과하면 원문 순서 prefix를 이진 탐색한다. 입력 identity의 SHA 기반 최대 128개 cache를 사용해 변하지 않은 fit→비교 preflight→Metered 예약에서 count를 재사용한다. model·system/user 전체 입력·reasoning·schema identity가 다르면 재계산한다. schema feedback 재시도와 앞선 decision이 만든 projected current/time/history 변경도 다시 세며 입력을 자르지 않는다. source/book 지침은 mandatory empty-candidate probe에도 보존한다.

캐릭터 비교 예약은 정확 입력 token 수+요청 출력 상한이다. count endpoint는 생성 요청 수·사용량으로 위장하지 않으며 다른 목적에는 count 요청을 추가하지 않는다. count 실패·누락·잘못된 응답은 `LlmInputTokenCountError`를 발생시키고 후보 의미 실패로 격리하지 않는다. provider 생성과 quota 예약 전에 Job 오류로 중단한다. 기존 quota·lease·stale/frozen·출력 절단 복구와 source coverage 규칙은 유지한다.

## 실제 검증의 범위와 한계

합성 boundary는 원본 전체 공통 문맥에 후보 padding을 붙인 count-only 검증이며 큰 입력의 의미 생성은 실행하지 않았다. 정확 256,000/256,001 경계는 결정론적 회귀, 실제 boundary는 위 255,510/257,096 두 값으로 구분한다. fresh 의미 검증은 STATUS batch 1회뿐이다. PROFILE/E 및 Dain 완료는 명시적으로 기록한 재생 자료이며 새 모델 판단으로 계산하지 않는다. 사전검증 전 sandbox 연결 실패 1회는 HTTP 도달 전 실패라 성공 count 4회에 포함하지 않는다.
