## 동작·실행 조건

- 기존 분석 Worker의 추출/해소/비교 모델과 프롬프트는 변경하지 않는다. 기존 RDB 행 선택과 추출형 응답도 재사용한다.
- 새 계획은 `HybridPlan.rdbMode`와 `sourceNeed`를 독립적으로 분류한다. 프롬프트 cache 버전은 `chat-hybrid-plan-v1`, `chat-hybrid-answer-v1`; RDB 선택은 `chat-qa-select-v1`이다.
- 제품 텍스트 모델 기본 `gpt-5.6-terra`·reasoning `medium`; 실제 모델은 실행하지 않았다. `ScriptedTextClient`의 고정 JSON과 FakeSearch/FakeEmbedding은 경로 검증 대역이다.
- 검색 임베딩 계약은 `text-embedding-3-small`, 1536차원, version `v1`, policy `cl100k-800-100-boundary-v1`. 실제 embedding API 호출 없음.
- 검색 라운드 2, query embedding 1, 모델 시도 6(스키마 재시도 포함), 키워드/벡터 Top-K 각각 12, 인접 반경 1/최대 6, 최종 근거 8/회차별 3, 검색 문맥 3,000토큰. 전체 입력 8,000토큰·출력 1,500토큰 및 서버 실행 예산을 추가로 적용한다.
- 직접 근거로 충분한 답변을 만들면 검색을 생략한다. 부족하면 키워드+인접, 이어 벡터+인접으로 확대한다. 연결 회차는 정렬 힌트이며 서버 허용 회차 범위를 대신하지 않는다.
- 현재 회차만 지원한다. 설정집/과거 원문 버전·과거 상태 전체 복원·전체 Fact 이력 최적화는 이 단계에서 구현하지 않았다.
- runtime의 검색 플래그는 기본 OFF다. 조회 전용 PostgreSQL 연결 pool 2/overflow 0, 연결·SQL·pool 대기 5초, 명시적 DSN만 사용한다.
- 원문 인용은 Python의 fingerprint와 Spring의 receipt/현재 원문 SHA/Unicode offset으로 재검증한다. 검증 실패 시 무효 인용만 지운 설명을 그대로 게시하지 않는다.
- API key·실제 provider·유료 judge·운영 DB·실제 사용자 원고를 사용하지 않았다.

## 의미 검토와 남은 작업

- 합성 10개 시나리오의 고정 출력을 내부에서 검토했다. 정상 경로/보류/의도적 무관 주장 대조군을 분리하며 10/10 모델 정확도로 보고하지 않는다.
- 유효한 E*와 원문 인용에 무관한 주장을 고의로 결합하면 구조상 ANSWER로 통과할 수 있다. 이것은 런타임에 의미 검증기가 없음을 확인한 인위적 대조군이며 실제 모델의 오류 관측이 아니다. `semanticExpected=UNSUPPORTED_CLAIM`, `qualityMeasurement=false`로 기록하고 #247 OPT-10 및 #242에서 추적한다.
- FakeSearch는 fixture가 지정한 청크를 반환한다. 그 반환을 실제 SQL 키워드 실패나 벡터 검색 품질 측정으로 해석하지 않는다. 실제 필터·정렬·범위는 별도 PG 테스트가 검증한다.
- 실제 S3 응답 VersionId·다운로드 중 크기 제한은 제공하지 않는 기존 getText 경계를 유지했다. 반복 전체 원문 검증과 잠금/메모리/I/O 부하는 #247 OPT-11로 추적하며 운영 실측은 하지 않았다.
- 기본 OFF, 운영 약 400회차 백필·상시 소비 스케줄·EC2 챗봇 기동은 미실시. #247 OPT-09 미전송 보고 후 백필 중단은 사용자 결정에 따른 보류 상태로 유지한다.
- #241 대화/화면과 파기 계약 연결, #242 실제 모델 질문 평가·비용/지연 검증, #247 전체 이력/상한/표현 최적화를 이어간다.
