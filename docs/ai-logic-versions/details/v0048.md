## 바뀐 동작

1. **탐색(`hybrid_agent.AgentRetrieval`).** 범위 확인 → 씨앗(계획 검색어 키워드 + 질문 벡터, 또는 좁은 범위의 회차 통째 읽기) → 탐색 단계 반복 → 답변 → 빠진 요구를 겨냥한 재탐색. 탐색 단계 출력은 서버가 설정 상한·허용 범위·중복으로 정리한다.
2. **조회(`app/retrieval`).** `episodes`(회차 통째 읽기), `keyword_episodes`(검색어별 회차 분포), `episode_span`, 서비스 `keyword_explore`. 기존 `CURRENT_FROM` 조건을 그대로 적용한다.
3. **두 단계 답변.** 병렬 추출 → 기존 인용 검증기로 대조 → 검증된 사실(F*)만으로 답 작성 → 기존 답변 검증. 빈 답은 한 번의 답변 호출로 재시도한다.
4. **옵션.** 계획이 좁힌 회차 범위를 서버 허용 범위 안에서 넓혀 읽기, 등록 이력 답을 원문으로 보완(실패 시 등록 답 유지), 항목별 질문의 탐색 처리.
5. **상한.** 검색 인용 60개(60개씩 나눠 등록, 초과 인용은 게시하지 않음), 탐색 답변 전용 넓은 응답 모델, 기존 설정의 허용 상한 확대(기본값 유지), `CHAT_QA_PROVIDER_TIMEOUT_SECONDS`.
6. **413.** 종료 상태·`EXECUTION_LIMIT_EXCEEDED`로 분류하고 완료 보고는 작은 실패 보고로 바꿔 보낸다. `httpx>=0.28.0`.

## PR #137 리뷰 반영

자동 리뷰 지적 6건을 코드로 확인해 모두 고쳤다. 스위치가 꺼진 실행의 동작은 바뀌지 않는다. 42문항 측정은 리뷰 반영 전 코드(`49c6103`)로 했고 반영 뒤에는 다시 재지 않았다. 아래 5·6번째 행은 답변을 여러 번 시도한 질문과 도구 호출이 빠듯한 실행의 결과를 바꿀 수 있다.

| 지적 | 고친 내용 |
| --- | --- |
| 탐색 한 단계 답변이 schema상 유효한 7~12개 인용 문장을 거절 | 문장당 인용 조각 수 상한을 문장이 속한 응답 모델에서 고른다(`AgentGroundedClaim` 12, 기존 문장·항목별 답 6, 충돌 3). 이전에는 두 단계 답변일 때만 12였다 |
| 추출 호출에 주지 않은 다른 묶음의 조각 참조가 통과 | 인용문의 첫 조회와 참조 바로잡기를 그 호출에 준 묶음 안에서만 한다 |
| 범위에 검색 조각이 없으면 연결 인용으로 답할 기회를 건너뜀 | 탐색 전에 조각 유무를 확인하고(`agent_source_span`, 탐색 상태 미변경) 없으면 기존 고정 라운드 경로와 기존 답변 계약으로 넘긴다 |
| 모르는 사실 참조를 조용히 빼고 문장을 남김 | 입력에 없는 `F*`가 하나라도 있으면 답 전체를 거절해 기존 재시도에 맡긴다. 충돌 표시도 같다 |
| 답변 시도마다 초안을 통째로 골라, 서로 다른 요구를 답한 부분 답 중 앞의 것이 버려짐 | 고정 라운드의 `merge_partial_snapshot`을 재사용해 양립하는 문장과 근거 스냅샷을 합치고 남은 요구를 다시 계산한다(`agent_merge_partial`). 병합 함수는 근거·문장 수 한도를 인자로 받고(기본값은 기존 12개·8문장, 탐색은 60개·12문장) 합친 답을 뒤 초안의 응답 모델로 만든다. 새로 답한 요구가 없는 시도는 앞 답의 요구를 모두 답하고 문장이 줄지 않았을 때만 앞 답을 대신한다(이전의 '나중 초안 우선'을 답한 요구를 잃지 않는 경우로 한정) |
| 회차 통째 읽기가 100개를 돌려주면 등록 2회를 써서 마지막 재검증·영수증 몫이 모자람 | 조각을 묶음에 넣는 한 곳(`agent_pool_add`)에서 등록 뒤 마무리 2회가 남는 수(`agent_register_room`)까지만 넣는다. 검색 쪽도 같은 한도를 지난다(기본 설정의 한 단계는 최대 48개라 기존 예약 안이었고, 결과 수를 올린 설정에서만 넘을 수 있었다). 수정 전 코드에서 남은 도구 4회·읽기 100개가 `EXECUTION_LIMIT_EXCEEDED`가 됨을 재현했다 |

새 회귀는 수정 전 코드(앞 4건은 `2a43f17`, 뒤 2건은 `46fecef`)에서 실패하고 수정 뒤 통과함을 확인했다. 고정 라운드의 6개 상한 회귀는 수정 전후 모두 통과한다(꺼진 실행 불변).
