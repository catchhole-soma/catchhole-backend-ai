# v0044 — 챗봇 막다른 경로 제거·키워드 희귀도 가중·계획 v14 (#319 3차)

2026-11-02 · 적용: 작업 브랜치 `feat/gh-319-chat-quality-v4` · [Java #319](https://github.com/catchhole-soma/catchhole-backend-java/issues/319)

## 무엇을 바꿨나

- 발표셋 미실행 문항에서 원문으로 답해야 할 질문이 등록 조회의 막다른 경로에서 되묻기로 끝났다. 원문 계획(등록 현재값 필수 제외)은 이제 등록 행이 답변 입력을 넘치면 현재값·계획 정렬 순으로 행을 줄이고(`REGISTERED_ROWS_TRIMMED`), 같은 이름의 세계관이 두 분류에 있거나 등록 항목 선택이 모호하면 등록 정보 없이 원문으로 답한다(`REGISTERED_LOOKUP_AMBIGUOUS`). 인물 이름의 모호성은 원문 답변도 사람을 구분해야 하므로 계속 되묻는다.
- 세계관 대상은 이름이 정확히 같은 등록 대상이 하나뿐이면 부분 일치 후보('미궁법')가 있어도 그 대상을 쓴다. 인물은 계약대로 정확히 같아도 되묻는다. 구형 행 선택은 판단과 행 목록이 어긋난 응답만 재호출 없이 맞춘다.
- 키워드 1라운드 순위를 일치 단어 비율에서 단어 희귀도 가중 비율(BM25 IDF에 `ln(1+x)`)로 바꿨다. X09(첫 살인 장면) 후퇴의 실제 원인이 계획 프롬프트가 아니라, 1인칭 주인공 이름·'어떻게' 같은 흔한 단어가 결정 단어 '죽인'과 같은 무게를 받는 순위였기 때문이다. 한 글자 단어는 다른 단어 안에서도 일치하므로 여러 글자 단어보다 무겁지 않게 했다. 검수 실행의 검색 순위는 그대로다.
- hybrid plan v14: 따옴표 인용 대사의 화자·앞뒤 장면 질문과 '주인공' 질문은 되묻지 않고 원문을 찾는다. 대화에 없는 '그 사람' 지칭은 계속 되묻는다. answer v16·QA plan v10·모델은 그대로다.
