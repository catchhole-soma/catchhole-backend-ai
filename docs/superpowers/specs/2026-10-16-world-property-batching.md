# 세계관 설정 내용 비교를 토큰 한도에 맞춰 묶기

상태: 구현·전체 회귀·운영 모델 고정 입력30회 측정 및 공통 품질 채점 완료(2026-10-16). 실제 결과는 v0017 상세에 기록한다.

## 출발점

- 작업 이슈: [#267](https://github.com/catchhole-soma/catchhole-backend-java/issues/267).
- 선행·상위 성능 이슈: https://github.com/catchhole-soma/catchhole-backend-java/issues/251
- 선행 Java #266 병합: `339ef410162b450764cea968bc18c51555dbc8c4`.
- 선행 AI #86 병합: `ed015dd948d580059020a506a96fb1b0b107b011`.
- 두 저장소의 새 브랜치: `feat/gh-267-world-property-batching`.
- 인물별 설정 비교와 원고 전체 세계관 대상 연결은 이미 기준 코드에 포함된다.

## 목표

포션의 회복 효과, 검의 공격력, 방패의 방어력처럼 여러 세계관 대상의 기존 설정과 새 내용을 입력·예상 출력 토큰 한도 안에서 함께 처리할 수 있는 만큼 묶어 보낸다. 각 응답에는 그 요청에 담긴 대상과 후보의 판단이 구분돼 들어간다. 대상 연결·추출·캐릭터 비교는 이번 변경 대상이 아니다.

같은 작품·같은 고정 원고 안에서 묶으며, 실제 요청 크기는 입력·예상 출력 예산과 순서 의존성으로 결정한다. 한 원고를 여러 요청으로 나누는 것도 정상 처리다. 회차당 1회나 특정 요청 수를 목표·완료 조건으로 두지 않는다. 한도 안에서 함께 처리할 수 있는 비교를 불필요하게 별도 호출하지 않는 것이 목표다.

## 보존할 의미

- 기존 내부 묶음의 category·canonical subject·raw scope·source membership과 검수/출처 단위를 보존한다. AI 요청 단위만 넓힌다.
- `CONFIRMED_ONLY`는 확정 상태 기준을 유지한다. `ORDERED_PROVISIONAL`은 서버가 고정한 순서대로 앞선 정상 판단을 다음 판단의 근거에 반영한다.
- 다른 대상의 후보·속성을 잘못 참조한 판단, 누락·중복, 미래 결과 참조를 거절한다. 참조 허용 목록은 각 내부 묶음별로 검사한다.
- 같은 대상의 앞선 ADD/UPDATE/MERGE를 뒤 묶음에서 참고할 수 있도록 순차 검증을 유지한다. 같은 요청 안에 담으면 검증 가능한 결과 참조를 지원하고, 앞선 결과의 검증·반영이 필요한 경우 다음 요청의 문맥으로 전달한다. 기존 단건 schema에 지시문만 추가하지 않는다.
- Python과 Java가 같은 순서로 상태를 재현하며 서버가 beforeValue·version·출처·보호 경로를 검증한다. stale token을 새 token으로 바꿔 과거 AI 결과를 저장하지 않는다.
- 자동 모드는 검증된 독립 결과를 보존하고 실패한 판단과 그 결과에 의존한 부분만 복구한다. 수동 ORDERED의 첫 실패 후 중단 정책은 유지한다.
- quota·lease 상실·원고 변경은 기존 작업 중단 정책을 유지한다. 여러 원고나 회차를 하나의 요청에 섞지 않는다.
- 현재 하위 묶음의 20개·30,000자 한도를 바깥 묶음 전체의 한도로 재사용하지 않는다. 필수 이력이나 원문을 잘라 예산에 맞추지 않는다.

## 변경 경계

1. 서버가 요청에 담을 비교 묶음의 시작 문맥을 고정한다. 기존 batch/decision·API 재사용을 우선 확인하고 필요한 계약만 확장한다. 원고 전체의 한 번 claim·완료를 전제하지 않는다.
2. Worker는 공통 지시·대상별 입력·출력 예산을 합산해 함께 처리할 수 있는 만큼 요청을 구성한다. 여러 요청으로 나누는 것은 정상 경로이며 출력 오류 뒤의 복구와 구분한다.
3. 응답은 묶음 식별자 및 묶음 안의 후보 참조로 연결한다. 같은 대상의 앞선 결과는 같은 요청의 검증 가능한 참조 또는 다음 요청의 문맥으로 전달한다.
4. 서버가 시작 상태를 다시 확인하고 각 요청의 결과를 기존 순서대로 검증·반영한다. 기존 단건 API를 통한 오래된 문맥 우회는 허용하지 않는다.
5. 구 Worker와의 배포 호환성을 유지하고 Backend → AI 순서로 적용한다.

## 토큰과 모델

- 운영 모델: `LLM_MODEL=gpt-5.6-terra`, 추출·내용 비교 `gpt-6.1-sol`, 대상 연결 `gpt-6-luna`, 추론 `medium`.
- 기존 내용 비교는 출력 16,000, ordered 입력 예산 64,000이다. 최초 실험은 이 값으로 실제 합친 입력·출력 사용량부터 확인한다.
- 최종 상한은 실제 합친 prompt와 응답·추론 사용량으로 정한다. 부족하면 기존 내용 비교 설정과 별도의 원고 비교 예산을 명시해 조정하고, 설정 검증·예제 env·Compose·예약 계산을 함께 맞춘다.
- 요청 수에는 생성, 입력 계산, 복구 호출을 각각 기록한다. 토큰 상한을 실제 사용량이나 비용으로 오인하지 않는다.

## 기준값과 측정

선행 v0016의 바바리안 1·2·3화 세계관 내용 비교만의 관측값이다. 각 회차 1회이며 새 구현의 결과가 아니다.

| 회차 | 생성 요청 | AI 응답 시간 | 기존 요청의 입력 토큰 합 | 출력 토큰 합 |
|---|---:|---:|---:|---:|
| 1 | 2 | 16.69초 | 9,006 | 874 |
| 2 | 4 | 32.23초 | 18,385 | 1,447 |
| 3 | 6 | 51.93초 | 28,089 | 2,581 |

이 합산 토큰은 새 prompt의 크기가 아니다. 2/4/6회는 개선 전 관측값이며, 개선 후 요청 수는 실제 묶음 크기와 분할 결과로 측정한다. 한도 안에서 묶을 수 있는 만큼 묶는 것이 목표이고 시간·품질 개선은 측정 전 보장하지 않는다.

- 같은 추출 결과·대상 연결 결과·시작 설정을 양쪽에 재사용해 비교 단계만 먼저 측정한다. 기존 추출 변동을 개선 효과에 섞지 않는다.
- 바바리안 1·2·3화와 기존 후속 회차인 바바리안 6화·AI 생성 2화의 고정 입력을 사용한다. 없는 입력은 없는 것으로 기록하고 회차 내용을 새로 꾸며 만들지 않는다.
- 기존 66회 사례는 세계관 **대상 연결** 호출 수다. 새 속성 비교 절감치로 바꾸어 인용하지 않는다.
- 실제 Java ORDERED 경로의 순서·저장 검증과 FIXED 품질 점수를 구분한다. 업로드부터 결과 표시까지 측정하지 않았다면 전체 서비스 시간으로 부르지 않는다.
- 각 입력은 기존/신규 교차 순서로 3회 실행하고 중앙값·범위·모든 실패를 보존한다. 확정 속성, 검토 여부, 연산, 대상, 값, 경로, 근거 차이를 보고한다.

## 완료 기준

토큰 한도와 실제 의존성에 맞춰 묶음을 구성하고, 한 요청 안과 요청 사이의 순서·참조·저장·복구를 검증한다. 한도 안에서 합칠 수 있는 비교가 묶이고 필요한 분할 사유가 설명돼야 한다. 같은 입력의 운영 모델 측정 및 남은 판정 차이 기록이 필요하며 회차당 1회 달성은 요구하지 않는다. 원문·정답·개별 예측·비밀값은 공개 문서에 넣지 않는다.
