# 검수 근거 부족 검색·사실 전제 설계

사용자가 승인한 범위: DB 근거 부족 시 최소 1회 RAG, 속성별 질문 분리, 추측·희망·회상의 사실 전제 검증, 정상 문장 및 비공개 101화 재평가, 긴급 이슈·PR·main 머지.

## Approaches

프롬프트만 변경하면 모델이 검색을 생략할 수 있다. 모든 질문을 무조건 검색하면 DB에서 직접 확인되는 질문까지 비용이 늘어난다. 승인한 방식은 정확한 속성·시점·조건에 대한 DB 근거 충분성을 모델이 명시하고 Worker가 미충족 시 검색을 보장하는 것이다.

## 동작

- 모델 전용 `db_evidence_sufficient` boolean을 OPEN/FINAL 응답에 추가한다. 기본 false이며 strict schema에서는 필수다. 충분 판정은 같은 질문의 정확한 속성·시점·조건을 설명하는 DB 문장과 검증된 B 인용을 요구한다. 일반적인 문장과 양립한다거나 반대 기록이 없다는 것은 충분하지 않다.
- 아직 성공한 VECTOR 조회가 없고 DB 근거가 불충분하면 Worker가 질문 의도·원문으로 검색 후 FINAL 재판정한다. 문맥 읽기만 한 FOLLOW_UP과 근거 없는 충돌의 정상화도 이 경계를 건너뛰지 않는다.
- 검색 불가·실패·예산 종료를 NO_CONFLICT로 바꾸지 않는다. 빈 검색 범위는 기존 NOT_APPLICABLE 영수증을 사용하며 중복 검색·새 자동 재시도·상한 증액을 추가하지 않는다. 3회 판정 상한과 SUSPECTED_CONFLICT 변화 검색 조건을 유지한다.
- 모델 전용 값은 Java 저장 wire에 추가하지 않는다. PLANNER/JUDGE schema cache 이름은 v4로 갱신한다.
- PLANNER는 신분 등 사실 전제와 희망/회상 내용을 독립 질문으로 만든다. JUDGE는 추측이 적용되는 범위를 확인하고 근거 없는 착각·거짓말·겸직 해석을 만들지 않는다. 순수 희망이나 불확실한 인물의 추측을 세계의 확정 사실로 판정하지 않는다.

## 검증

스크립트 응답으로 검색 보장·실패 경계를 확인하고 실제 모델로 의미를 검증한다. 정상 대조군은 합성 문장이고 작품 원문/정답/개별 결과는 저장소 밖에 둔다. 한스를 뺀 v2 원고는 14개 오류·18구절이며 기존 15개 파일럿은 보존한다. 실제 모델·강도·코드 SHA·입력 해시를 기록한다. 운영 모델 변경과 예산 자동 증액은 이 수정의 범위가 아니다.
