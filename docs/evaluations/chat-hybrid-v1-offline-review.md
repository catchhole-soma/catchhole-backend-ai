# 챗봇 hybrid v1 합성 자료 내부 의미 검토

검토일: 2026-10-13. 대상: [Java #240](https://github.com/catchhole-soma/catchhole-backend-java/issues/240)의 고정 대역 기반 질문 10개. 검토자는 Codex이며, 아래 판정은 저장소의 합성 자료를 읽고 제공된 근거와 작성된 주장을 대조한 내부 검토다. 배포 모델·embedding provider·judge API·운영 원고·운영 DB를 호출하지 않았다. 실제 모델의 정확도, 검색 재현율, 지연 및 비용은 **미측정**이다.

초기 전체 검증의 AI 제품/테스트 코드는 `73ad2a0060315a6a8f202b4b1f5836a3ce054451`이며, provider 호출 계측 보완 후 코드는 `655ac61efba34974124985921cb7f347da466b9e`다. 두 단계에서 이 표의 합성 입력은 동일하다. 전체 검증 기록과 복원 정보는 AI 로직 버전 상세에도 기록한다. 위 입력 hash가 바뀌면 이 검토를 그대로 최신 결과로 재사용하지 않는다.

`tests/test_chat_hybrid.py`의 `ScriptedTextClient`는 fixture의 계획·행 선택·답변 JSON을 순서대로 반환한다. `FakeSearch`도 작성된 청크 목록을 반환하며, 실제 SQL이나 유사도 순위를 계산하지 않는다. `FakeEmbedding`은 합성 벡터와 고정 사용량을 반환한다. `HybridSpring`은 `httpx.MockTransport`를 통해 retrieval receipt를 되돌려 준다. 소켓 연결을 거절하는 autouse fixture가 있어 이 재생은 외부 서비스를 호출하지 않는다. 실제 Python 실행기·HTTP 직렬화·SQLite outbox의 연결을 검사하지만 실제 네트워크의 Spring/S3 통합 실행은 별도 테스트다.

이 검토는 fixture의 기대 답과 근거가 서로 맞는지, 부족한 근거에 대한 분기가 타당한지 확인한다. 모델이 스스로 같은 계획·주장·coverage를 생성하는지는 확인하지 않는다. 테스트 PASS와 의미 검토 판정은 별개다.

## 근거 자료 대조

아래 문장은 운영 원고가 아닌 저장소의 합성 원문이다.

| 자료 | 검토에 필요한 사실 | 지지할 수 없는 주장 |

## 구조 검증과 의미 실패의 경계

마지막 대조군은 허구의 ID나 변조된 원문을 보내는 검사가 아니다. 존재하는 E1을 선택하고 해당 근거에 실제로 있는 날씨 quote를 붙여도, 별도 자연어 주장은 관련 없는 반지 장면을 말할 수 있다는 점을 드러낸다. 현재 runtime은 실제 참조·원문·권한·버전·offset을 검증하지만 주장과 인용 사이의 의미적 함의를 자동 판정하지 않는다. `COMPLETE`도 입력된 모델 판단이며, 서버가 의미적 완전성을 인증한 표시가 아니다.

따라서 이 대조군의 구조 테스트가 PASS하는 것과 내부 의미 검토에서 실패로 표시하는 것은 모순되지 않는다. 실제 모델이 그런 답을 만들 확률, 프롬프트가 이를 얼마나 줄이는지, 별도 검증기가 필요한지는 이 자료로 알 수 없다. 상시 judge API를 호출한 결과나 운영 모델의 오류율로 설명해서는 안 된다.

## 이 재생이 검증하지 않는 것

- 키워드 대역은 질의에 따라 실제 포함 여부를 검사하지 않는다. 특히 6번의 빈 키워드 결과와 7·10번의 무관한 weather 반환은 분기 주입이다. 실제 SQL의 scope/version/purge 필터·순위·LIMIT과 벡터 계산은 별도 격리 PostgreSQL 테스트의 범위다. 두 종류의 결과를 섞어 검색 품질로 집계하지 않는다.
- 이 재생의 `sourceHash` 일부는 합성 placeholder이고 Spring 대역은 receipt를 되돌려 준다. 실제 S3 원문 hash·code point offset·현재 메타데이터 검증을 이 10개 사례가 증명하지 않는다. 양쪽 공통 wire fixture, Java 원문 검증 및 실제 localhost HTTP 테스트는 별도로 기록한다.
- 대역의 고정 토큰 수와 embedding 횟수는 호출 정책 검사용이다. 실제 실패·재시도·UNKNOWN·복구·백필 비용을 포함한 금액이나 비용 절감률이 아니다. `embedding=0`인 사례에도 계획/선택/답변 모델 호출이 있을 수 있다.
- 인접 결과는 이 10개 기본 재생에서 비어 있다. 인접 근거 병합·중복 제거·상한·출처 무효화·허용 회차 검증은 별도 단위/통합 테스트를 확인한다. 이 표만으로 그 계약 전체의 완료를 주장하지 않는다.
- 장문의 과정 설명, 여러 회차를 합쳐야 하는 원인, 동명이인·모호한 주체, 등록값과 원문 충돌, 사용자 직접 입력, 넓은 설정집, 긴 이력, 실제 prompt injection 대응 품질은 이 10개 의미 검토의 평가 범위를 넘는다. 일부의 코드 분기 테스트가 있어도 실제 모델 품질 측정과는 다르다.

## 다음 평가에 보존할 기준

[#242](https://github.com/catchhole-soma/catchhole-backend-java/issues/242)의 실제 모델 비교에서는 동일한 데이터 버전·회차 범위·질문·생성 모델 조건에서 RDB/직접 근거, 원문 검색, 결합 방식을 비교한다. 정답이 데이터에 있다는 것과 각 방식이 실제 사용할 수 있는 자료에 있다는 것을 구분한다. 현재값과 장면/이유가 함께 필요한 질문은 각각의 충족 여부와 최종 결합 출력 모두를 평가한다.

질문별로 필요한 사실, 허용 근거, 지원되지 않는 추가 주장, 적절한 보류 이유를 실행 전에 정한다. 사실 정확도와 인용의 의미적 지지, 필수 근거 누락, 범위 준수, 준비 부족과 사실 부재의 구분, 전체 호출/실패 비용을 독립적으로 기록한다. 유효한 ID를 가진 무관한 주장은 구조 통과와 의미 실패를 계속 분리해 남긴다. baseline 확인 후 최종 평가 전에 통과 기준을 고정하며 결과에 따라 낮추지 않는다.

본 검토는 기본 OFF 상태, 운영 약 400회차 백필 미실시, [#247 OPT-09](https://github.com/catchhole-soma/catchhole-backend-java/issues/247)의 보류 상태를 바꾸지 않는다. 구조·연결 검증과 실제 모델 평가가 별도라는 제한도 유지한다.

## 재생 명령

```sh
.venv/bin/python -m pytest -q tests/test_chat_hybrid.py -k 'authored_offline_replays or semantic_negative_control'
```

이 명령의 통과는 고정 출력의 연결 계약과 음성 대조군 표시를 확인한다. 본 문서의 사례별 의미 검토는 위 원문/기대 주장을 직접 읽어 별도로 수행했다. 전체 테스트 수·실제 HTTP·격리 DB 실행 결과는 공통 [`chat-hybrid-retrieval-v1.md`](../chat-hybrid-retrieval-v1.md)의 검증 기록과 AI 로직 버전 상세를 따른다.
