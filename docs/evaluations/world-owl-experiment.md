# OWL 세계관 실험 결과 — 2026-11-19

**36개 합성 snapshot, 92개 질의에서 실제 OWL 2 DL 엔진의 판정과 모든 부분집합 최소 근거 집합이 독립 수작업 정답과 일치했다.** 개념 분류·복합 정의·명시적 부정·불가능 클래스·전체 모순을 구분했고, 사실뿐 아니라 세계관 정의·출처의 철회도 새 snapshot의 전체 재계산으로 반영했다.

기존 Python 비교 실험은 유지했다. 이번에는 같은 기능을 Python 추론기로 재구현하지 않았다. 확인한 가치는 범용 엔진의 논리 기능을 재사용할 수 있다는 점이며, 운영 도입 효과나 Python 대비 성능 우위를 입증한 것은 아니다.

## 실제로 확인한 행동

| 마지막 지지 철회 | 마지막 사실·정의·출처 제거 | 결론이 사라지며 반대 명제로 자동 전환하지 않음 |
| 시간·출처 | 독자 회차/작중 시점/저장 revision/작품·시간선 | 정의와 사실 모두 적격 범위로 제한 |
| 문장 유형 | 보통/금지 규범/소문/미확정 | 엄격한 참인 공리로 채택하지 않음 |

전체 질의 판정은 ENTAILED **34**, REFUTED **9**, UNKNOWN **29**, SATISFIABLE **4**, UNSATISFIABLE **2**, BLOCKED_INCONSISTENT **14**다. UNKNOWN과 모순 차단은 이 자료에서 기대된 정답이며 실행 실패가 아니다. 실제 ERROR는 0개다. 모순 snapshot은 4개, 일관 snapshot은 32개다.

## 근거와 철회가 의미하는 것

OWL 엔진은 실제 논리 판정을 수행한다. 근거 설명은 앱 코드가 명제 부분집합을 엔진에 다시 질의해서 만든다. `axiomIds`는 사용한 세계관 정의, `factIds`는 개체 사실, `sourceAlternatives`는 각 명제를 지지하는 유효 출처의 OR 대안을 표시한다. 단순히 엔진 결론에 그럴듯한 원문을 붙이지 않는다.

모든 완료된 설명은 **부분집합 최소 명제 집합을 빠짐없이 열거한 결과**다. 최단 하나만 고르거나 모든 내부 증명 경로를 열거한다는 뜻은 아니다. 각 집합의 충분성과 각 원소의 필요성은 새 엔진 검사로 확인했다. 순수 논리의 빈 근거 집합도 구분했다.

사실·정의·출처가 달라질 때에는 적격 직접 명제로 ontology를 새로 만든다. 이전 파생 결과를 재입력하지 않으므로 제거된 전제가 결론을 다시 살리지 않는다. 이 작업은 **전체 재계산**이며 증분 철회 알고리즘이나 운영 DB transaction을 구현한 것이 아니다.

원문 파기 사례는 새 snapshot의 `text:null`을 보존하고 인용문을 재생성하지 않는다는 검사다. 과거 actual/inputs/HTML 파일의 사본 삭제 기능은 없다. 이번 `.owl` 파일에는 직접 공리만 들어 있고 출처 연결은 JSON에 남긴다.

## 비용 측정

환경: macOS 26.6.2 arm64, Python 3.12.13, Java 21.0.11(Microsoft), Owlready2 0.51, JPype1 1.6.0. 실제 bundled 엔진은 **HermiT 1.3.8.1099 / OWLAPI 3.4.3**이다. 최신 릴리스라고 주장하지 않으며, 운영 엔진 선정·배포·유지보수 검토는 별도다.

구현 commit `42b3331910c2668b61357e036e3927dcb38ee0f5`의 깨끗한 작업 트리에서 세 번의 독립 프로세스를 순차 실행했다. JVM은 프로세스마다 한 번 시작하고, 캐시되지 않은 논리 검사마다 ontology와 reasoner를 새로 만든다. 실행당 **336회** 실제 검사가 있었다. 36개 snapshot을 모두 처리한 시간이며 질의 하나나 작품 하나의 운영 지연이 아니다. fixture의 최대 적격 명제는 5개다.

| 전체 프로세스 벽시계 | 558.283 ms |
| 계산 함수 전체(파싱·엔진 초기화 포함) | 457.585 ms |

전체 프로세스 범위는 502.165–616.864 ms, 계산 함수 범위는 446.984–525.346 ms였다. 각 단계의 중앙값을 따로 구했기 때문에 합이 전체 중앙값과 정확히 같지는 않다. RSS는 Python+JVM 전체 최고점으로 객체별 메모리나 증분 사용량이 아니다. 기록 JSON 쓰기·정답 평가 전체 비용은 이 benchmark의 계산 함수 범위에 포함하지 않는다. 프로세스 벽시계에는 sample JSON 쓰기·프로세스 시작/종료가 포함된다.

이전 OWL RL 관계 실험과 이번 DL 실험은 입력·엔진·기동 방식·출력량이 다르다. 숫자를 직접 비교해 속도 개선이라고 해석하지 않는다. 명제 16개·엔진 8,192회/사례·근거 탐색당 노드 8,192개 한도를 두며 초과는 ERROR다. 실제 데이터의 큰 정의망·고분기 다중 근거는 미측정이다.

- 관련 pytest: **66 passed**, 1.44초.
- 전체 pytest: **5916 passed, 186 skipped, 1 warning**, 43.95초. skip은 미실행이며 통과에 합산하지 않는다. warning은 기존 Starlette TestClient의 httpx deprecation이다.
- 최소 근거 탐색: 4개 원소에 가능한 모든 **168개 단조 최소근거 집합족**을 독립 powerset 기준과 대조했다. OWL 의미론 자체를 168개 검사했다는 뜻은 아니다.
- 독립 리뷰에서 출처 검증 누락과 macOS 대소문자 파일 충돌을 재현해 수정했다. 저장 결과의 출처·원문·해시·회차·scope 훼손 10종 및 `.owl` 저장 손상 회귀를 추가했다.
- 입력 순서 변경, 정답 파일 변조/누락, 중복/미지원 구문, 명시 부정과 UNKNOWN, 실제 Java timeout 예외 매핑, check budget, DL profile, RDF/XML 재로딩을 검사했다. timeout 테스트는 예외 처리 계약을 검증하며 실제 대규모 timeout 부하 시험이 아니다.
- 기본 editable install `.[dev]`, 실험 extra `.[dev,world-owl]`, `pip check`, 변경 Python 11파일 Ruff check/format, `git diff --check` 통과.
- 원격 CI: head `00305a6`의 [Test AI](https://github.com/catchhole-soma/catchhole-backend-ai/actions/runs/44485633488) 성공, **5915 passed, 187 skipped, 1 warning**(123.95s). 로컬보다 skip이 하나 더 많은 이유는 depth=1 checkout에 과거 `b4bbce` commit이 없어 `test_baseline_loader_isolates_both_book_modules`가 생략됐기 때문이다. 이후 설명 문서만 보완하며 최신 PR head의 CI 상태는 PR/이슈에 기록한다.

재현 명령과 계약은 [실행 안내](../world-owl-experiment.md), 전체 실제 결과·근거·원자료·해시는 [기계 기록](world-owl-records-20261119.json)을 참고한다. 기본·확장 각각 `run --input ... --oracle ...`로 실행하면 같은 의미 결과를 비교할 수 있다. benchmark는 두 입력의 cases를 기본→확장 순서로 합친 schemaVersion 1 JSON을 사용했다. 그 입력 해시와 실행별 전체 결과 해시도 보존했다.

## 판단

**OWL은 우리 프로젝트의 복합 세계관 논리를 담당할 수 있는 유효한 후보로 확인됐다.** 직접 Python에 개념 분류·부정·논리적 모순 검사를 새로 구현하지 않고 표준 연산과 엔진을 재사용했다는 점이 이전 단순 관계 연결 실험에서 확인하지 못한 가치다.

다만 실제 원문을 정확한 명제로 만드는 일, 데이터 규모에서의 성능과 근거 탐색 한도, 운영 revision/파기 정책, 사용자에게 보여 줄 설명과 챗봇·검수 연결은 아직 남아 있다. 다음 제품 실험은 범위를 정한 실제 세계관 자료를 수작업 형식화하고 현재 검수/조회 결과에 읽기 전용으로 연결해 효과를 확인하는 것이 적절하다. 이번 결과만으로 전체 서비스 도입이나 기존 자연어 검수 대체를 확정하지 않는다.
