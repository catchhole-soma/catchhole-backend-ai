# 일회성 작품 대화와 후속 질문 (#241)

## 제품 정책

대화는 작품 소유자가 명시적으로 종료하거나 마지막 질문 접수/답변 완료 후 2시간이 지나면 이용할 수 없다. 읽기, 새로고침, 화면 이동, 탭 닫힘은 만료 시간을 바꾸지 않는다. 실패 질문의 명시적 재시도는 새 질문 실행이므로 시간을 갱신한다. 빈 대화는 생성 후 2시간이다.

종료 트랜잭션에서 질문·최종 답변·인용 receipt를 지운다. 만료는 모든 API에서 즉시 차단하고, 본문 정리는 60초 간격 작업이 최대 100개씩 처리한다. 정리 실패는 다음 주기에 재시도한다. `chat.session-cleanup.scheduling-enabled`는 기본 true이고 test 프로파일에서만 false로 두어 만료 fixture와 백그라운드 정리가 경쟁하지 않게 한다. 앱 중단 중 지난 만료도 기동 후 정리된다. 스케줄이 지연되면 물리적 본문 삭제도 지연되지만 조회/후속 문맥에는 쓰이지 않는다.

대화 ID·멱등 키·시각·실행 상태·사용량 같은 메타데이터는 남긴다. 대화 종료가 이미 발생한 provider 비용 정산을 취소하지 않는다. 대화 종료 후 새 예약/도구 호출/결과 게시는 거절하지만 이미 예약한 호출의 늦은 정산은 받는다. 일반 종료와 작품/회원 영구 파기는 구분한다. 후자는 기존 파기 그래프에서 세션 행까지 삭제한다. 이 정책은 서버 원장·로그 보존 정책을 대체하지 않는다.

## 소유 경계와 데이터

- Java V80: `chat_sessions` 추가. 최신 `main`의 기존 V77~V79 마이그레이션을 보존하며, 미배포 챗봇 마이그레이션 번호를 V80으로 옮겼다. 기존 `chat_questions`에 nullable `session_id`, `sequence_no`, `submitted_at` 추가. 답변은 기존 `chat_runs.result_json`, 사용량은 기존 원장을 재사용한다. 별도 메시지/답변 복사 테이블을 만들지 않는다.
- 세션 없는 기존 질문 요청은 그대로 동작한다. null `sessionId`는 request hash JSON에서 생략해 기존 멱등 요청과 호환된다.
- 작품 행 잠금 아래 권한·열림·진행 질문 여부·순번 할당을 함께 처리한다. 같은 대화에 다른 탭이 동시에 보내도 한 실행만 접수한다. 생성 요청의 UUID `requestId`, 질문의 `Idempotency-Key`는 응답 유실 시 같은 값을 재사용한다.
- 초기 운영 상한: 회원당 활성 대화 20개, 대화당 질문 200개. 화면 목록은 20개씩 페이지 이동한다. 이 페이지 크기는 모델의 Fact 조회 상한과 별개다.
- 원문 변경/삭제가 기존 `invalidateWork`에 도달하면 해당 작품의 활성 대화를 모두 종료하고 본문을 지운다. 직접 입력한 설정 자체를 삭제하지 않는다. 영향받은 대화만 남기는 정밀한 의존 추적은 후속 최적화다.

## API

모든 사용자 API는 인증·작품 소유권·활성 회원/작품 검사와 `CommonResponse`를 사용한다.

| API | 동작 |
| --- | --- |
| `POST /api/v1/works/{workId}/chat-sessions` | `{requestId: UUID}`로 멱등 생성 |
| `GET .../chat-sessions?page=0&size=20` | 열린 대화만 생성 시각/ID 오름차순 |
| `GET .../chat-sessions/{sessionId}` | 만료 시각·질문 수·전체 실행 여부(`busy`) 조회, TTL 갱신 없음 |
| `GET .../chat-sessions/{sessionId}/messages?page=0&size=20` | 접수 순번 오름차순, 현재 실행 결과/사용량 연결 |
| `DELETE .../chat-sessions/{sessionId}` | 반복해도 안전한 종료·본문 삭제 |
| 기존 `POST .../chat-questions` | optional `sessionId` 추가 |

목록은 `PageResponse`, size 1~50. 닫힌 세션은 410 `CHAT_SESSION_CLOSED`, 진행 중 질문은 409 `CHAT_SESSION_BUSY`, 세션/질문 수 상한은 409 `CHAT_SESSION_LIMIT`. `CHAT_ENABLED=false`는 신규 생성·질문 접수를 막으며 기존 정리/정산은 계속한다.

생성·목록·상세의 `ChatSessionV1.busy`는 메시지 페이지와 무관한 세션 전체 상태다. 실행 기한이 남은 `QUEUED`/`RUNNING` 또는 기한과 무관한 `SETTLEMENT_PENDING`이 있으면 true다. 새 질문·재시도 접수 검사와 같은 저장소 조건을 재사용하며, 방 목록은 현재 페이지의 세션 ID를 묶어 한 번에 검사한다. 최신 질문뿐 아니라 이전 페이지 질문의 재시도도 포함한다. 읽은 이후 다른 탭에서 상태가 바뀔 수 있으므로 최종 접수 권한은 기존 서버 잠금·검증에 남긴다.

## 문맥과 사실의 구분

Spring만 같은 세션의 앞선 완료 질문/답변에서 문맥을 만든다. 클라이언트가 과거 답변·회원 ID·작품 ID를 모델 문맥에 주입하지 않는다. 최근 질문 7개를 스캔해 최대 6개 성공 턴, 답변당 최대 1,000 UTF-16 단위, 질문+답변 합계 8,000 UTF-16 단위까지 보낸다. 이모지 surrogate 쌍을 쪼개지 않는다. 실패/무효 결과는 제외한다. 오래된 성공 턴을 찾으려고 실패 질문을 끝까지 훑지 않는다.

Python `ExecutionContext.conversation`/`conversationTruncated`는 additive 필드다. 과거 출력은 지시나 사실 근거가 아니라 지칭 대상 해석에만 쓰는 비신뢰 데이터다. 현재 질문과 이 문맥에 실제 등장한 이름/검색어만 허용하고, 실제 RDB 대상 탐색으로 재확인한다. 같은 이름의 복수 대상이나 불명확한 대명사는 추가 질문으로 남긴다. 예전 회차 제한은 새 질문에 자동 계승하지 않는다. 모델의 회차 경계는 이번 서버 요청의 동일 경계 또는 현재 질문에 명시된 숫자 회차 표현(예: `3~5화`, `3화부터 5화까지`, `episodes 3–5`)인지 공통 조회 단계에서 확인한다. 확인되지 않으면 RDB/원문 조회 전 추가 확인으로 끝낸다. 숫자 없는 상대 표현을 과거 대화의 범위로 자동 변환하지 않는다.

분류 입력이 토큰 상한을 넘으면 오래된 문맥부터 제외한다. 문맥 생략은 답변 `limitations`에 안내하며 유료 요약 호출을 추가하지 않는다. 현재 프롬프트 버전은 QA plan v4, FIELD select v1, 구형 QA select v3, hybrid plan/answer v4다. 조회·집계·요청 정보별 답변의 현재 계약은 Java/Python 공통 `docs/chat-query-quality-v1.md`를 따른다. 생략 여부는 분류뿐 아니라 RDB 행 선택에도 `conversationTruncated`로 전달한다. 답변에 선택하는 R*/E*는 이번 실행이 다시 읽은 데이터만 가리킨다. 기존 RDB·직접 근거·키워드/인접·벡터 정책과 모델 호출 예산을 재사용한다.

예: “화염술의 소모 마력은?” → 현재 등록값 35. 사용자가 값을 42로 수정 → “그 마법의 소모 마력은?” → 문맥에서 화염술을 해석 → `FIND_WORLD_SETTINGS` → `WORLD_CURRENT` 재조회 → 42. 이전 35는 최신값 증거로 사용하지 않는다.

## 화면

`/chat?workId=...&sessionId=...&messagePage=...`에서 활성 대화를 복원한다. URL에는 식별자/페이지만 넣고 본문·임시 입력을 브라우저 저장소에 보관하지 않는다. React Query 캐시는 인증 세대·작품·세션별로 분리하고 이탈 시 취소/제거한다. 늦은 mutation 응답은 이전 화면을 복원하지 않는다.

서버의 저장 상태를 조회해 질문/답변을 하나의 턴으로 표시한다. FastAPI는 기존 별도 HTTP 역할이며 분석 Job 큐에 질문을 넣지 않는다. 이번 화면은 완료 상태를 2초 간격으로 확인한다. 토큰 단위 스트리밍은 제공하지 않는다. 실패한 질문은 명시적으로 재시도하고, 접수 응답이 유실된 질문은 입력을 보존한 채 같은 키로 접수를 확인한다. 한글 IME Enter는 전송하지 않는다. 질문 접수 성공 후 회차 입력을 비우고, 접수 확인 재전송 중에는 원래 회차 범위와 멱등 키를 보존한다. `SETTLEMENT_PENDING`도 진행 중으로 취급해 정산 완료 전 새 전송/재시도를 막는다.

전송·재시도 잠금은 세션 `busy`와 현재 페이지에서 확인한 진행 상태를 함께 사용한다. 다른 페이지를 읽어도 숨은 실행을 놓치지 않으며 재시도 후 세션 상세와 메시지를 함께 갱신한다. 사용량 부족 공통 알림은 화면에서 진행을 관측한 실행이 새로 실패하거나 본인이 접수/재시도한 실행의 실패를 확인할 때 한 번만 연다. 과거 실패의 최초 조회·대화 재진입·새로고침은 알림을 다시 열지 않고 기존 실패 본문을 유지한다. 추적하는 실행 ID는 해당 대화 컴포넌트 메모리에만 두며 본문이나 알림 이력을 브라우저 저장소에 기록하지 않는다.

근거 창은 현재 질문을 다시 확인하고 직접 근거 도구를 호출한 뒤 실행이 같은지 재확인한다. 검증된 원문 인용, 직접 입력, 과거 이력, 원문 확인 불가 상태를 구분한다. 설정 상세와 현재 원문 화면으로 연결한다. 변경/삭제로 세션을 읽을 수 없으면 본문과 열린 근거 창을 숨긴다.

직접 근거의 `조회한 설정값`은 별도 영역에 표시하며 일부만 받은 값은 부분 표시임을 알린다. 이 등록값을 원문 인용처럼 표시하지 않고 실제 검증된 `quote`가 있을 때만 인용 영역을 만든다. 등록값과 인용문이 모두 있으면 두 정보를 함께 보존한다.

답변의 제한 안내는 정확히 같은 문장만 한 번으로 합친다. 하나면 원문 한 문장을 바로 표시하고, 여러 개면 `답변에서 확인할 점 N가지`와 펼치기 버튼을 표시한다. 펼친 목록에는 서로 다른 서버 안내를 순서대로 보존한다. 다만 조건에 맞는 결과가 1개 이상 확인된 기존 고정 형식의 답변에서는 `관련 설정이 없는 N명/개/건` 제외 집계만 표시하지 않는다. 같은 안내에 미검토·판단 보류 사유가 함께 있으면 그 의미는 유지하며, 질문·답변의 일반 문장이나 인용에는 이 처리를 적용하지 않는다. 접어도 나머지 안내를 삭제하지 않으며 키보드 Enter/Space, 펼침 상태와 상세 영역 연결을 제공한다. Front가 안내의 의미를 추측해 숨기거나 본문·설정명·인용에서 기술어처럼 보이는 표현을 삭제하지 않는다. 직접 근거 일부를 읽지 못하면 확인하지 못한 건수를 알리고 성공한 직접 근거와 검색 인용을 함께 유지한다. 모든 근거 조회가 끝난 뒤 질문 재검증에 실패하거나 실행이 바뀌면 앞서 읽은 인용도 표시하지 않는다.

본문과 근거 창의 `근거 N`은 응답 `sources` 순서 뒤에 `retrievalSources` 순서를 이어 붙인 1-based 번호다. 직접 근거 일부를 읽지 못해도 이후 번호를 당기지 않으며 근거 창은 직접 근거, 검색 인용 순서로 표시한다.

### 대화방 탐색과 읽기 위치 (2026-10-15)

- 대화 선택은 본문 옆 방 목록으로 제공한다. 제목은 서버의 생성 시각이며 질문 수와 현재 선택을 표시한다. API에 없는 제목·첫 질문 미리보기를 만들기 위한 추가 조회나 브라우저 저장은 하지 않는다. 폭 1,100px 이하에서는 목록을 접고 펼치는 버튼을 제공하며 상단 `새 대화`는 유지한다.
- 다른 대화를 선택하면 서버 `questionCount`로 마지막 메시지 페이지를 계산해 연다. 같은 대화 선택이나 명시적인 URL의 `messagePage`는 읽던 페이지를 유지한다.
- 워크스페이스 메뉴는 원고 목록 → 작품 설정 → 분석 목록 → 챗봇 → 분석 리포트 → 그래프 뷰 순서다. 챗봇에서도 좌측 메뉴 영역이 남은 화면 높이를 채운다.
- 모바일 워크스페이스 메뉴는 Radix Dialog로 열어 배경 조작을 차단하고 초점을 메뉴 안에 유지한다. Escape와 닫기 버튼으로 닫으며 열었던 버튼으로 초점을 돌린다.
- 대화 진입·메시지 페이지 전환·본인 새 질문 접수 시에만 해당 턴으로 한 번 이동한다. 같은 내용의 주기 조회, 답변 상태 갱신·완료, 실패 질문 재시도는 사용자가 읽던 위치를 강제로 바꾸지 않는다. 스크롤이 맨 아래에 가깝다는 이유로 마지막 질문 시작으로 반복 이동하지 않는다.
- 상시 `Enter로 보내기 · Shift+Enter로 줄바꿈` 문구는 제거한다. Enter 전송·Shift+Enter 줄바꿈·한글 조합 중 전송 방지 동작은 유지한다.
- 방 목록을 여닫거나 대화를 조회해도 2시간 만료를 연장하지 않는다. 종료·만료, 인증 세대·작품·세션별 캐시 분리, 접수 확인의 멱등성은 기존 계약을 따른다.

- AI: 소켓 차단 합성 테스트에서 잘못된 이전 답변보다 새 RDB 결과 우선, 모호성, 관측되지 않은 이름 거절, 회차 범위, 문맥 상한, 과거 E* 재사용 거절, 기존 wire 호환 검증.
- Front: mock E2E와 별도 opt-in `e2e/chat-live.spec.ts`를 구분한다. 후자는 실제 브라우저·Spring·PostgreSQL·Python QA/hybrid를 연결하고 모델 출력만 고정한다. 실제 LLM/임베딩/judge API는 호출하지 않는다.
- 실제 모델의 대명사/생략 해석 정확도, 의미상 근거 지지, 비용/지연, 세 검색 방식 비교는 #242에서 평가한다. 전체 Fact 이력 누락, 의미 경로 좁히기 및 문맥 상한 최적화는 #247. 미지원 설정집/과거 전체 상태 복원은 지원한다고 표시하지 않는다.
- 적용 순서: Java V80/API → AI 문맥 처리 → Front 생성 SDK/화면. 기존 세 플래그 기본 OFF를 유지하며 운영 배포·백필·활성화는 이번 작업에 포함하지 않는다.
