# 세계관 속성 비교 요청 묶음

포션의 회복 효과, 검의 공격력처럼 서로 독립적인 세계관 비교를 토큰 한도 안에서 함께 요청한다. Spring이 만든 내부 batch의 후보·검수·저장 단위는 유지한다. 작업 이슈는 [#267](https://github.com/catchhole-soma/catchhole-backend-java/issues/267)이다.

## 요청 한도

| 설정 | 기본값 | 검사 대상 |
|---|---:|---|
| `LLM_WORLD_SETTING_BATCH_COMPARISON_MAX_INPUT_TOKENS` | 64,000 | 공통 지시 + 비교 데이터 + 응답 schema + 여유 |
| `LLM_WORLD_SETTING_BATCH_COMPARISON_MAX_OUTPUT_TOKENS` | 16,000 | 응답과 추론을 합친 실제 출력 상한 |

입력은 `o200k_base` 추정에 10%와 256토큰을 더해 확인한다. 출력은 기존 contract-complete 예상량의 2배에 공통 여유 1,024를 더해 묶을 크기를 결정한다. 예상량은 실제 추론량을 보장하지 않으므로 provider의 출력 상한과 응답 복구를 함께 유지한다. 입력 계산 API 호출은 추가하지 않는다.

보류 참고는 `domain=worldSettings`인 항목만 내용 비교 입력에 포함한다. 단독·묶음·복구 요청이 같은 입력 생성 함수를 사용하므로 예산 계산에도 동일하게 적용한다. 세계관 참고의 대상별 관련성을 선별하거나 내용을 자르지 않으며, 인물 참고를 제외해도 서버의 고정 입력·저장된 참고는 변경하지 않는다.

한도를 넘기기 전에 원래 순서의 다음 요청으로 나눈다. 고정된 대상 개수 상한을 추가하거나 필수 원문·이력을 자르지 않는다. 내부 batch의 기존 제한은 그대로다. 단독 batch도 필수 입력이 초과하면 기존 오류 경로로 종료하며, 출력 최소량 초과 시 기존 검토 경로를 유지한다.

## 순서와 저장

1. 같은 작품·고정 출처의 batch를 기존 API로 미리 claim하고 문맥을 읽는다.
2. 대상 또는 canonical subject가 다시 나오거나 출처·시점 지시가 다르면 요청을 나눈다. 같은 대상은 앞선 결과를 저장한 뒤 문맥을 다시 읽는다.
3. 공통 지시는 한 번 보내고 `groups.G1`, `groups.G2`별로 결과를 받는다. C*/T*/P* 참조는 각 그룹 안에서만 유효하다.
4. 기존 그룹별 validator/projection을 적용한다. 누락·중복·허용되지 않은 참조를 거절한다.
5. 각 batch 저장 직전에 원래 모델 입력의 전체 context와 현재 context를 대조한다. 달라졌으면 모델을 다시 호출하며 새 토큰만 붙여 과거 결과를 저장하지 않는다.
6. Spring이 후보 membership·beforeValue·version·contextToken·보호 경로·출처·lease를 기존 방식으로 검증한다. 별도 API나 DB migration은 없다.

## 복구

정상 그룹은 보존하고 오류가 난 그룹만 기존 제한된 복구를 실행한다. 응답 절단/파싱 오류, 그룹 누락, 개별 검증 실패를 정상 분할과 구분한다. 주체 해소가 stale이면 기존 결과 캐시를 비우고 새 batch를 후속 batch보다 먼저 다시 claim한다. 수동 ORDERED는 첫 실패에서 중단한다. quota·lease·고정 원문 변경은 정상 결과로 바꾸지 않는다.

기존 batch별 사용량에는 공유 요청을 시작한 첫 batch에 해당 요청 사용량을 기록한다. 후속 캐시 결과의 추가 provider 사용량은 0이며 전체 합계는 중복되지 않는다. 이 값을 각 대상의 독립 생성 비용으로 해석하지 않는다.

## 검증 범위

FIXED 재생은 같은 추출 후보·대상 연결·시작 설정으로 비교 단계만 측정한다. Java의 실제 순차 저장 테스트와 평가 점수는 구분한다. 업로드·대기열·Spring 문맥 조회/저장까지 포함한 전체 서비스 지연은 이번 재생으로 측정하지 않는다. 실제 모델 조건과 결과는 [v0017 상세](ai-logic-versions/details/v0017.md)에 기록한다.
